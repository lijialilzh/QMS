# AI 客服知识库（零）系统菜单导航

> 本文件是给“AI 客服”使用的菜单导航全景知识库，内容全部来自系统真实菜单（前端 `pages/Home.tsx` 菜单配置 + i18n `zh-CN.json` 文案）。
> 每个一级菜单按统一结构描述：界面位置 / 用户常见问法 / 是做什么的 / 解决什么问题 / 怎么用 / 相关功能。
> 目的：当用户问“X 在哪”“基础数据有什么”“一级菜单都有哪几个”时，AI 能精确回答菜单层级。

---

## 模块总览：系统菜单导航

医疗器械软件质量管理追溯系统（QMS）的左侧菜单共 **11 个一级菜单**，按使用顺序大致是“配置 → 基础数据 → 产品 → 需求 → 设计 → 文件 → 风险 → 报告 → 总览”：

1. **仪表盘**
2. **系统配置**：角色管理 / 用户管理 / 产品线管理
3. **基础数据**：HAZ 管理 / RCM 管理 / THREAT 管理
4. **产品版本管理**：产品管理
5. **产品文件管理**：产品DHF管理 / 测试数据集管理
6. **需求管理**：需求规格说明
7. **设计管理**：软件详细设计
8. **图表文件管理**：物理拓扑图 / 体系结构图 / 网络安全流程图
9. **风险追溯管理**：产品HAZ管理 / 产品RCM管理 / 产品THREAT管理 / 追溯分析
10. **风险管理**：风险管理报告 / 风险分析参与人员
11. **全局视图**：产品关联列表 / 内容对比

> 所有菜单按当前用户的角色权限过滤，无权限的菜单不显示。详情：见各模块说明。

## 1. 仪表盘

- **界面位置**：左侧菜单第 1 项「仪表盘」（`/dashboard`），是一级菜单（无子菜单）。
- **用户常见问法**：仪表盘是什么、首页有什么、登录后第一个看到的页面。
- **是做什么的**：登录后系统的概览/首页。
- **解决什么问题**：作为系统的入口和总体状态展示。
- **怎么用**：登录后默认会跳到仪表盘；从其它页面回到仪表盘可点左侧菜单第一项「仪表盘」。
- **相关功能**：登录、其它各业务菜单。

---

## 2. 系统配置

- **界面位置**：左侧菜单「系统配置」，下含 3 个二级菜单。
- **用户常见问法**：系统配置是什么、系统配置下面有什么、用户角色项目在哪、怎么找到角色管理、产品线在哪个菜单。
- **是做什么的**：管理“谁能用系统”和“项目归属”这两件基础事。包含 3 个二级菜单：
  - **角色管理**（`/roles`）：查看预置 7 个角色（root / dqa / qa / ra / 产品经理 / 开发 / 测试）及配置每个角色的权限范围。
  - **用户管理**（`/users`）：新建 / 编辑用户、给用户分配角色、重置密码、删除用户。
  - **产品线管理**（`/projects`）：维护“项目（产品线）”，是产品的上级归属。
- **解决什么问题**：让每个使用系统的人都有自己的账号、按角色获得权限，并把产品按项目（产品线）归类。
- **怎么用**：点左侧「系统配置」展开 → 选对应二级菜单进入。
- **相关功能**：基础数据（业务数据维护）、产品版本管理（产品挂在项目下）。

---

## 3. 基础数据

- **界面位置**：左侧菜单「基础数据」，下含 3 个二级菜单。
- **用户常见问法**：基础数据是什么、基础数据有什么、基础数据下面包含什么、基础数据都有哪些、HAZ 在哪、RCM 在哪、CST 在哪、THREAT 管理是什么。
- **是做什么的**：维护**风险相关的全局基础库**，是产品风险评估的源头数据。包含 3 个二级菜单：
  - **HAZ 管理**（`/hazs`）：维护「危害分析」基础库——每条 HAZ 记录一种危害的来源、事件、处境、损害和初始/剩余风险评估。
  - **RCM 管理**（`/rcms`）：维护「风险控制措施」基础库——每条 RCM 是一项可复用的控制手段，被 HAZ、SRS 需求、产品 RCM 引用。
  - **THREAT 管理**（`/csts`）：维护「网络安全威胁（CST）」基础库（按 IEC 62443 风格分类），与 HAZ/RCM 在主数据层无关联，专用于网络安全维度。
- **解决什么问题**：把可复用的危害、控制措施、网络安全威胁沉淀为标准库，给每个产品做风险评估时直接引用，不必重复定义。
- **怎么用**：点左侧「基础数据」展开 → 选 HAZ / RCM / THREAT 进入对应库做新建、编辑、导入、导出、删除。
- **相关功能**：风险追溯管理（把基础库关联到具体产品）、风险管理（报告里的矩阵和控制措施引用基础库）、需求管理（SRS 需求可绑定 RCM）。

## 4. 产品版本管理

- **界面位置**：左侧菜单「产品版本管理」，下含 1 个二级菜单。
- **用户常见问法**：产品在哪、产品管理在哪个菜单、产品版本管理是什么、怎么找到产品列表。
- **是做什么的**：管理医疗器械产品档案（按版本组织）。包含 1 个二级菜单：
  - **产品管理**（`/products`）：新建 / 编辑 / 删除 / 导出产品；产品是 SRS、SDS、测试集、图表、DHF、风险等所有业务数据的挂载点。
- **解决什么问题**：建立每个产品的标准档案与版本，作为后续需求、设计、风险、测试的统一挂载点。
- **怎么用**：点左侧「产品版本管理」展开 → 点「产品管理」进入产品列表。
- **相关功能**：系统配置 → 产品线管理（产品的上级归属）、需求管理 / 设计管理 / 风险追溯管理（都挂在产品下）。

---

## 5. 产品文件管理

- **界面位置**：左侧菜单「产品文件管理」，下含 2 个二级菜单。
- **用户常见问法**：产品文件管理是什么、产品 DHF 在哪、测试集在哪、测试数据集管理在哪个菜单。
- **是做什么的**：管理挂在产品下的两类“产品级文件”。包含 2 个二级菜单：
  - **产品DHF管理**（`/prod_dhfs`）：按产品维护「设计历史文件」清单（编号 + 名称），用于产品资料归档。
  - **测试数据集管理**（`/test_sets`）：按「产品 + 测试阶段（单元/集成/系统/用户）」组织测试集，并通过 Excel 导入测试用例。
- **解决什么问题**：把产品的资料文件清单和测试用例集中管理，作为追溯证据。
- **怎么用**：点左侧「产品文件管理」展开 → 选 DHF 或 测试数据集 进入对应页面。
- **相关功能**：产品管理（DHF/测试集挂在产品下）、风险管理报告（DHF 是产品资料）、追溯分析（测试集是测试证据来源）。

---

## 6. 需求管理

- **界面位置**：左侧菜单「需求管理」，下含 1 个二级菜单。
- **用户常见问法**：需求管理是什么、需求文档在哪、SRS 在哪个菜单、怎么找需求规格说明。
- **是做什么的**：编写和维护产品的需求文档（SRS）。包含 1 个二级菜单：
  - **需求规格说明**（`/srs_docs`）：SRS 文档列表与详情页，支持 Word 导入、新建、编辑、复制、导出、删除；详情页可编辑章节树、维护需求条目、变更需求表、功能描述。
- **解决什么问题**：把每个产品的需求结构化记录下来，作为设计、风险、测试与追溯的源头。
- **怎么用**：点左侧「需求管理」展开 → 点「需求规格说明」进入 SRS 文档列表。
- **相关功能**：产品管理（SRS 挂在产品下）、设计管理（SDS 须绑定 SRS 版本）、追溯分析（基于 SRS 的全链路追溯）。

---

## 7. 设计管理

- **界面位置**：左侧菜单「设计管理」，下含 1 个二级菜单。
- **用户常见问法**：设计管理是什么、SDS 在哪、详细设计在哪个菜单、设计文档在哪。
- **是做什么的**：编写和维护产品的软件详细设计文档（SDS）。包含 1 个二级菜单：
  - **软件详细设计**（`/sds_docs`）：SDS 文档列表与详情页，**必须绑定一份 SRS 需求文档版本**；支持 Word 导入、新建、编辑、复制、导出、删除；详情页可编辑章节树、维护设计条目、同步需求追溯。
- **解决什么问题**：把 SRS 的需求落实成可实现的设计，并保持需求与设计的追溯关系。
- **怎么用**：点左侧「设计管理」展开 → 点「软件详细设计」进入 SDS 文档列表。
- **相关功能**：需求管理（SDS 须绑定 SRS）、追溯分析、产品管理。

---

## 8. 图表文件管理

- **界面位置**：左侧菜单「图表文件管理」，下含 3 个二级菜单。
- **用户常见问法**：图表文件管理是什么、拓扑图在哪、结构图在哪、网络安全流程图在哪、怎么上传图表。
- **是做什么的**：按产品管理三类工程图表，并与 SRS/SDS 文档节点联动。包含 3 个二级菜单：
  - **物理拓扑图**（`/doc_files_topo`）：维护产品的物理拓扑图（绑定 SRS 文档版本）。
  - **体系结构图**（`/doc_files_struct`）：维护产品的体系结构图（绑定 SRS 文档版本）。
  - **网络安全流程图**（`/doc_files_flow`）：维护产品的网络安全流程图（绑定 SDS 文档版本）。
- **解决什么问题**：把产品的拓扑、结构、网络安全流程等图集中管理，并与需求/设计文档节点的图片自动联动，保证图文一致。
- **怎么用**：点左侧「图表文件管理」展开 → 选对应图类型 → 选产品 + 文档版本 → 上传图片。
- **相关功能**：需求管理 / 设计管理（图表与文档章节联动）、产品管理（图表挂在产品下）。

---

## 9. 风险追溯管理

- **界面位置**：左侧菜单「风险追溯管理」，下含 4 个二级菜单。
- **用户常见问法**：风险追溯管理是什么、产品 HAZ 在哪、产品 RCM 在哪、产品 CST 在哪、追溯分析在哪。
- **是做什么的**：把基础数据库（HAZ/RCM/CST）关联到具体产品，并查看 SRS 全链路追溯。包含 4 个二级菜单：
  - **产品HAZ管理**（`/prod_hazs`）：把 HAZ 关联到产品，并行内编辑处境、损害、初始与剩余风险、控制措施、证据。
  - **产品RCM管理**（`/prod_rcms`）：把 RCM 关联到产品，自动计算 SRS 编号 / 测试编号追溯（无行内编辑，只能删后重加）。
  - **产品THREAT管理**（`/prod_csts`）：把 CST 关联到产品，行内编辑控制前 / 后评分（独立 Float 体系，与 HAZ 不同套字段）。
  - **追溯分析**（`/srs_doc_trace`）：展示 SRS 需求到设计（SDS）、风险（RCM）、测试（测试用例）的全链路追溯关系，支持导出 Excel/Word。
- **解决什么问题**：让每个产品有自己的一套风险清单，并满足“每条需求是否被设计、风险、测试覆盖”的合规追溯要求。
- **怎么用**：点左侧「风险追溯管理」展开 → 选对应二级菜单进入。
- **相关功能**：基础数据（HAZ/RCM/CST 主库）、风险管理（报告以产品 HAZ 为准）、需求管理（追溯起点是 SRS）。

---

## 10. 风险管理

- **界面位置**：左侧菜单「风险管理」，下含 2 个二级菜单。
- **用户常见问法**：风险管理菜单是什么、风险管理报告在哪、参与人员在哪个菜单。
- **是做什么的**：产出符合监管要求的风险管理报告文档。包含 2 个二级菜单：
  - **风险管理报告**（`/risk_mgmt_docs`）：按产品 + 版本管理风险管理报告文档；支持 Word 导入、空白新建、复制版本、按章节编辑、导出 Word；报告内容由章节树 + 参与人员 + 风险分析矩阵 + 风险控制措施 + 接受标准等构成。
  - **风险分析参与人员**（`/risk_participants`）：维护全局参与人员（项目角色 + 姓名），供风险报告 4.2 章节勾选。
- **解决什么问题**：把产品的风险管理输出整理成报告文档，并与产品 HAZ/RCM 实时联动。
- **怎么用**：点左侧「风险管理」展开 → 选「风险管理报告」做报告主体维护 / 选「风险分析参与人员」维护人员库。
- **相关功能**：风险追溯管理（产品 HAZ/RCM 是报告矩阵的数据源）、产品管理（报告挂在产品下）。

---

## 11. 全局视图

- **界面位置**：左侧菜单「全局视图」，下含 2 个二级菜单。
- **用户常见问法**：全局视图是什么、产品总览在哪、产品对比在哪、文档对比在哪、产品关联列表是什么、内容对比是什么。
- **是做什么的**：跨产品 / 跨版本的总览与对比工具。包含 2 个二级菜单：
  - **产品关联列表**（`/prod_traces`）：产品级追溯总览，按产品列出该产品下的 SRS / SDS / 测试 / 风险等关联实体的概览。
  - **内容对比**（`/prod_comparison`）：对比两份文档（如同一产品不同版本的 SRS、或两个产品的 SDS）的差异。
- **解决什么问题**：在版本升级或交付审计时快速发现功能增删、覆盖差异。
- **怎么用**：点左侧「全局视图」展开 → 选「产品关联列表」看产品全链路 / 选「内容对比」做文档差异对比。
- **相关功能**：需求管理 / 设计管理 / 风险追溯管理（数据来源）。
