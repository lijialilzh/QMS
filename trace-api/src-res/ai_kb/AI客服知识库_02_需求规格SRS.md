# AI 客服知识库（二）需求规格说明 SRS

> 本文件是给“AI 客服”使用的功能知识库，内容全部来自系统真实功能（功能逻辑文档 20–27、用户手册 92）。
> 每个功能按统一结构描述：界面位置 / 用户常见问法 / 是做什么的 / 解决什么问题 / 怎么用 / 相关功能。
> 目的：让 AI 既能“认识”每个功能（是什么、界面里叫什么），又能讲清楚“怎么用”。

---

## 模块总览：需求规格说明（SRS）

需求规格说明（SRS）模块用于为每个产品编写和维护一份“需求文档”，记录这个产品要实现哪些需求。文档挂在产品下、按版本管理，主操作路径是「SRS 文档列表 → 文档详情页」：列表负责新建/导入/复制/导出/删除文档，详情页负责编辑章节树、维护需求条目、变更需求表和功能描述。
它解决的是“把产品需求结构化、规范化地写下来”的问题，并向下连接 SDS 设计、RCM 风险、测试用例，是后续设计、风险、测试与追溯的源头。

---

## 1. SRS 文档管理（新建 / 编辑 / 查看 / 复制 / 删除）

- **界面位置**：菜单「需求管理 → 需求规格说明」，列表页路径 `/srs_docs`；详情页 `/srs_docs/add`（新建）、`/srs_docs/edit/{id}`（编辑）、`/srs_docs/view/{id}`（只读查看）。
- **用户常见问法**：怎么新建需求文档、SRS 怎么建、怎么写需求规格说明、怎么编辑 SRS 文档、怎么复制一份 SRS、怎么把需求文档复制到别的产品、怎么删除 SRS 文档、文件编号怎么改。
- **是做什么的**：对产品的需求规格说明文档做整体管理——新建、编辑、查看、复制、删除，以及在列表里直接修改“文件编号”。
- **解决什么问题**：让每个产品都有一份按版本管理的需求文档，作为需求条目、变更需求、功能描述和后续追溯的统一载体。
- **怎么用**：
  1. 进入列表页，可按产品（产品名称 + 完整版本联动）、文档版本筛选后搜索；须先选产品才能加载该产品下的版本。
  2. 新建：点「新建」进入新建页 → 选择产品、填写需求文档版本号 → 点「初始化模版」加载标准目录结构 → 在目录树中编辑章节、维护需求条目/变更需求表/功能描述 → 点顶栏「保存」；保存成功后进入该文档编辑页。
  3. 编辑：列表行点「编辑」进入编辑页修改内容后保存。
  4. 查看：列表行点「查看」进入只读详情页。
  5. 复制：列表行点「复制」，在弹窗里用产品选择器选“目标产品”（默认当前产品，可选其它产品实现跨产品复制），版本号由系统自动生成，确认后复制。
  6. 删除：列表行点「删除」，按确认弹窗提示完成（提示会说明删除后需求列表清空、绑定的 SDS 会解除绑定）。
  7. 文件编号：在列表里单击“文件编号”单元格直接编辑，失焦或回车保存，提示「文件编号已保存」。
- **相关功能**：导入 Word 需求、导出 Word、文档章节树编辑、需求条目管理、变更需求表、功能描述、需求追溯；上游依赖系统配置里的“产品”（须先建好产品）。

## 2. 导入 Word 需求

- **界面位置**：SRS 文档列表页（`/srs_docs`）顶部「导入」按钮，打开「导入 Word 需求」弹窗。
- **用户常见问法**：需求文档怎么导入、怎么把 Word 导进来、SRS 怎么从 Word 导入、能不能直接上传需求 Word、导入 docx。
- **是做什么的**：上传一个 `.docx` 文件，系统自动解析生成 SRS 文档树，并抽取出需求条目、变更需求表、功能描述、图片等内容入库。
- **解决什么问题**：免去手工逐条录入，把已有的 Word 需求文档一键转成系统里的结构化 SRS 文档。
- **怎么用**：
  1. 列表页点「导入」。
  2. 在弹窗里填写：产品（必填，产品 + 版本联动选择）、需求文档版本（必填）、变更说明（可选）、上传 Word 文件（必填，仅 `.docx`，单文件）。
  3. 点「确定」上传解析。
  4. 成功后系统自动创建文档，并解析出章节树、需求条目、变更需求表、功能描述、关联 RCM 和图表文件。
- **相关功能**：SRS 文档管理（导入后即生成一份可编辑文档）、文档章节树编辑、需求条目管理、变更需求表、功能描述。

## 3. 导出 Word

- **界面位置**：两个入口——列表页（`/srs_docs`）行内「导出」；文档详情页顶栏「导出」。
- **用户常见问法**：SRS 怎么导出、怎么导出 Word、需求文档怎么下载成 Word、详情页怎么导出。
- **是做什么的**：把 SRS 文档导出为 `.docx` 文件。
- **解决什么问题**：方便把系统里的需求文档以 Word 形式交付、评审或归档。
- **怎么用**：
  1. 列表导出：在列表行点「导出」，直接下载该文档的 Word（基于数据库里的已保存数据）。
  2. 详情页导出：在文档详情页顶栏点「导出」，导出当前编辑态的快照 Word；该入口需先保存过文档，否则提示「请先保存文档」。
- **相关功能**：SRS 文档管理、需求追溯（追溯表也支持导出 Word/Excel）。

## 4. 文档章节树编辑（目录结构）

- **界面位置**：文档详情页（`/srs_docs/add` | `/edit/:id` | `/view/:id`）的「目录结构区」。
- **用户常见问法**：SRS 章节怎么编辑、怎么加目录、怎么加章节、怎么加一级菜单、章节正文怎么改、怎么插表格、怎么插图片、怎么删章节、怎么绑定 RCM。
- **是做什么的**：编辑文档的树形目录结构——编辑各节点的标题和正文、增删子节点、在章节里插入表格或图片、为节点绑定 RCM 编码，并内嵌编辑需求表与功能描述。
- **解决什么问题**：让需求文档按章节层级组织内容，是承载需求条目、变更表、功能描述、图表的主体编辑区。
- **怎么用**：
  1. 新增节点：目录结构区顶栏「添加一级菜单」加根级节点；节点行「添加{N+1}级菜单」加下级（最多到四级）；节点左/右侧 `+` 在前面/后面添加同级节点。
  2. 编辑内容：在节点上填写章节标题、正文；部分节点可填需求编号；通过「选择RCM」多选下拉绑定 RCM，选中后 RCM 描述会写入正文。
  3. 插入表格：点节点「表格」→ 填表名、行数(1–50)、列数(1–20)、表头 → 点「生成表格预览」→ 编辑单元格 → 点「保存表格」；表格下方有「编辑」「删除」。
  4. 导入表格：点「导入表格」上传 Excel（首行表头、至少一行数据）。
  5. 上传图片：普通图片节点点「选择文件 / 重新上传」；产品拓扑/结构/流程图会上传到图表文件库。
  6. 删除节点：点节点「删除」并在 Popconfirm 确认。
  7. 编辑完成后点顶栏「保存」，整棵树随文档一起保存。
- **相关功能**：SRS 文档管理（保存即整树提交）、需求条目管理、变更需求表、功能描述（第 7 章随需求行自动生成）、图表文件库。

## 5. 需求条目管理（标准需求 / 其他需求）

- **界面位置**：文档详情页内的需求表（树内嵌表格 / 预览表格）。
- **用户常见问法**：怎么加需求、产品需求列表怎么填、标准需求怎么录、其他需求怎么填、需求编号怎么改、怎么删一条需求。
- **是做什么的**：维护 SRS 的两类需求条目——标准需求（编号、模块、功能、子功能）和其他需求（编号、需求模块、对应章节号），通过表格弹窗编辑、批量保存。
- **解决什么问题**：把产品需求逐条结构化记录下来，作为功能描述、设计、风险、测试追溯的基础数据。
- **怎么用**：
  1. 标准需求：找到标准需求表（产品需求列表）→ 点「编辑」→ 在弹窗里改单元格（列：需求编号、模块、功能、子功能）→ 行尾 `+` 插行、垃圾桶删行 → 点「保存表格」。
  2. 改需求编号：直接修改“需求编号”列即可；与旧编号冲突时系统会自动先写临时编号再更新，用户无感。
  3. 删除行后保存：库中对应旧行被删除。
  4. 其他需求：编辑流程同上，列为需求编号、需求模块、对应章节号；其章节标题/编号需在此表维护（树上对应章节只读）。
- **相关功能**：文档章节树编辑、功能描述（保存标准需求行后自动在第 7 章生成功能描述）、变更需求表、需求追溯。

## 6. 变更需求表

- **界面位置**：文档详情页内，右上角「新增变更表格」；树内变更表标题旁的「编辑」「删除」。
- **用户常见问法**：变更需求表怎么建、怎么加变更表格、变更需求怎么录、变更表怎么删、删了又出来怎么办。
- **是做什么的**：记录某次变更涉及的需求（编号、模块、功能、子功能）。每张变更表是一组需求行，独立于标准/其他需求单独成表。
- **解决什么问题**：把“某次变更涉及哪些需求”单独成表管理，便于变更追踪，并联动第 7 章功能描述。
- **怎么用**：
  1. 新增：点「新增变更表格」→ 在弹窗填表名（必填，默认「变更需求N」）→ 确定后自动打开变更需求编辑弹窗（四列：需求编号、模块、功能、子功能）。
  2. 编辑行：在弹窗里编辑单元格、行尾 `+` 增行、删行（至少保留一行）→ 点「保存表格」，提示「变更需求已保存」。
  3. 删除整张表：点树内变更表标题旁「删除」并确认「确认删除表格？」；系统会联动删除该表的 srs_type、需求行及第 7 章对应功能描述。
- **相关功能**：需求条目管理、文档章节树编辑、功能描述（第 7 章随变更需求行联动生成/删除）、需求追溯（变更需求在追溯导出中单独成 sheet）。

## 7. 功能描述（第 7 章）

- **界面位置**：文档详情页第 7 章「功能描述」下的 KV 明细表（两列：字段名 | 值）；树上 `需求详细列表` 入口可打开只读宽表。
- **用户常见问法**：功能描述怎么填、第 7 章怎么写、用例描述怎么填、前置条件触发器工作流在哪填、怎么新增功能描述。
- **是做什么的**：为每条需求维护一份详情（需求编号、名称、概述、主参加者、前置条件、触发器、工作流/事件流、后置条件、异常情况、约束），章节结构按 模块→功能→子功能 自动生成。
- **解决什么问题**：把每条需求的具体行为和约束讲清楚，作为设计与测试的详细依据。
- **怎么用**：
  1. 自动生成：保存标准需求 / 变更需求行后，系统自动在第 7 章生成对应功能描述子章节及 KV 明细表（没有独立的「新增功能描述」按钮，新增需求行并保存即可触发）。
  2. 填写：定位第 7 章下对应 SRS 编号的功能描述节点 → 点 KV 表「编辑」→ 在弹窗右列填写需求概述、主参加者、前置条件、触发器、工作流/事件流、后置条件、异常情况、约束（需求编号、名称行锁定，名称来自需求表）→ 点「保存表格」，提示「功能描述已保存」。
  3. 部分行（异常/约束/工作流等）可多选 RCM，选中后自动拼接到内容。
  4. 批量查看：树上 `需求详细列表` 节点点「需求详细列表」打开只读宽表（含 RCM 编号列）。
- **相关功能**：需求条目管理、变更需求表（这两类需求行驱动第 7 章生成）、文档章节树编辑、RCM。

## 8. 需求追溯（SRS 文档追溯）

- **界面位置**：菜单「风险追溯管理 → 追溯分析」，路径 `/srs_doc_trace`。
- **用户常见问法**：需求追溯怎么看、SRS 追溯表在哪、需求到设计到测试的追溯、追溯表怎么导出、变更追溯在哪看。
- **是做什么的**：展示 SRS 需求到设计（SDS）、风险（RCM）、测试（测试用例）的追溯关系，并支持导出 Excel / Word。
- **解决什么问题**：一张表看清每条需求是否被设计、风险、测试覆盖，满足合规与追溯需要。
- **怎么用**：
  1. 进入 `/srs_doc_trace`，选择产品后点搜索。
  2. 表格列为产品名、版本、文档版本、文件编号、操作。
  3. 每行点「查看」弹出追溯表（需求编号、RCM 标志、软件详细设计、接口编号、各类测试记录、RCM、备注）；有变更追溯时下方显示「{产品版本}变更追溯」子表。
  4. 点「导出 Excel」或「导出 Word」下载追溯表。
- **相关功能**：SRS 文档管理（追溯基于已保存的 SRS 文档）、变更需求表、SDS 设计、RCM 风险、测试用例；另在「产品追溯总览 → 文档对比」（`/prod_comparison`）可对比两份 SRS 文档。
