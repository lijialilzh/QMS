# 需求追溯（SRS 追溯表）

## 1. 功能概述

展示 SRS 需求到设计（SDS）、风险（RCM）、测试（测试用例）的追溯关系，支持 Excel/Word 导出。

---

## 2. 用户操作流程

菜单「SRS 追溯」→ `/srs_doc_trace` → 选产品/文档 → 查看追溯表 → 导出 Excel/Word。

---

## 3. 前端实现

- 页面：`pages/prod_risk/SrsDocTrace.tsx`
- API：`ApiSrsDoc.list_doc_trace / export_doc_trace / export_doc_trace_word`

---

## 4. 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/srs_doc/list_doc_trace` | id = srs_doc_id |
| GET | `/srs_doc/export_doc_trace` | Excel（模板 `temp_srs_doc_trace.xlsx`） |
| GET | `/srs_doc/export_doc_trace_word` | Word 追溯表 |

权限：`srs_doc_view`。

---

## 5. 追溯数据来源（list_doc_trace）

1. **前置**：取该 SRS 最新绑定 `sds_doc`（`order_by desc SdsDoc.id limit 1`）；**无绑定返回 `[]`**。
2. 主数据：`sds_trace` ⋈ `srs_req`（code 去重）。标准需求在上，其他需求整组在下；两段各自按编号数字排，不看代号字母，也不按入库先后。新增的标准需求如 `SRS-RCN301-015` 排在 `301-014` 后面、`302` 前面，不插进其他需求 `300-010` 和 `300-011` 之间。`SRS-ACN300-001` 这类其他需求仍在标准需求下面。主表只放标准需求和其他需求。有新增变更表时，「版本变更追溯」列出这一版仍在的全部需求（标准、其他、新增变更），顺序与主数据相同，每行带上该需求自己的 RCM。
3. RCM：`req_rcm` + 节点/reqd 文本提取。
4. 测试：`test_case` ⋈ `test_set`（按阶段：单元/集成/系统/用户，取该 SRS 所属产品下的整份用例）；SRS code 与 SDS-IF/单元用例编号互转。同一编号主段内再按功能点对一次：用例功能点与该主段里需求的子功能或功能一致时，挂到该需求。中间插入新需求、后面的编号顺延后，用例仍跟着功能点走（例如功能点「报告导出」的 `TU05-003` 挂到现在的「报告导出」，不挂到占用了旧编号的「报告编辑」）。整份用例表里插入的变更需求按用例上的需求编号挂到变更追溯，例如 `SRS-RCN308-001` 挂 `TI08-001`，不因为功能点文字和别的主段相同就挪走。用例代号字母和需求不一致、主段和序号相同（如用例 `SRS-RCN301-003`、需求 `SRS-ACN301-003`）时，仍挂到现需求上，集成用例因此能覆盖仍在的其他需求。功能点为空、或对不上本主段任何需求时，仍按编号。
5. 固定备注：`SRS-RCN300-009` 行附加 IEC62304 等文档引用（`TRACE_FIXED_NOTE_CODE`）。

返回字段含：`srs_code, rcm_flag, sds_code, chapter, sis_codes[], test_codes[], tests_integ/sys/user[], rcm_codes[], note, type_code`。

## 6. 边界与特殊处理（Excel 导出）

- 普通需求与变更需求（type_code 非 1/2）分 sheet。
- 多接口/多用例行合并单元格。
- 特定 SDS code 隐藏 chapter 展示。

### 6.1 近期修复 / 优化

- **RCM 聚合去重（后端 `__query_node_rcm_codes`）**：仅按节点**自身 SRS 编号**归属 RCM，不再把无编号节点（如导入表格行）的 RCM 上挂到祖先章节，避免章节型需求（如 `SRS-RCN300-007`「图像显示」）被子表 RCM 过度聚合；聚合结果按编号去重（`dict.fromkeys`），不再出现重复 RCM。
- **SDS 编号成对附组件名（导出）**：导出时**每个 SDS 编号后单独追加其所属组件名（中文括号）逐行展示**，多个编号各自带括号、不再整体拼成一串，且不丢失括号；隐藏章节集合（`SDS-RCN300-001/002/003/008/009/010`）内的编号不加括号。
- **安装包打开 / 安装包安装 / 安装包卸载**：设计节点挂在 NeoViewer 下，导出源代码名称仍写 `（NeoViewer）`。
- **文档需求**（模块或功能含「文档需求」，如 `SRS-RCN300-008`）：不追溯设计编号，SDS 列为空（页面和导出都显示 `/`）。法规符合、外部连接仍保留各自设计编号。
- **外部连接 `SRS-RCN300-010` 的接口与单元测试**：接口编号按数值拼接还原（主号×10+次号）。`SRS-RCN300-010` 对应 `SDS-IF00-RCN3010-` 与 `TU00-010-`，不再拼成对不上的 `RCN30010`。设计编号 `SDS-` 同号也能反查到 `SRS-`。
- **RCM 编号升序**：追溯结果里的 RCM 按编号末尾数字从小到大排列，页面和 Excel/Word 导出一致。
- **追溯表 UI**：相同内容的行/单元格按需合并；补齐表格各列竖线边框，避免缺列分隔线。

> 上述追溯结果同样作为网络安全报告「7. 威胁缓解措施追溯」的数据来源（见 [47_网络安全管理.md](./47_网络安全管理.md)）。该章节前端展示时：RCM/威胁编号**按末尾数字大小排序并去重**、多值列**逐编号换行**、空单元格用 `/` 占位；仅保留「威胁编号↔RCM」有对应关系的行；导出时 RCMID 列仅保留编号。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. **无 SDS 绑定时返回空数组**是既定行为，不可改为报错。
2. **SRS↔SDS↔测试编号互转规则**（SRS-→SDS-、单元/集成/系统/用户用例前缀）是追溯匹配核心，改动会断链。
3. `SRS-RCN300-009` 等固定备注为合规需要，属产品特例，不可随意删除。
4. 变更需求分 sheet 导出逻辑不可与普通需求混表。
