# 需求规格说明导出（Word）

## 1. 功能概述

将 SRS 文档导出为 `.docx`。支持两种入口：列表导出（数据库快照）与编辑页导出（当前编辑态 snapshot）。

---

## 2. 两种导出入口

| 场景 | 接口 | 前端 |
|------|------|------|
| 列表直接导出（DB 快照） | GET `/srs_doc/export_srs_doc?id=` | `SrsDocs.handleExport` |
| 编辑页导出（当前编辑态） | POST `/srs_doc/export_srs_doc_snapshot`（body=SrsDocForm） | `SrsDocDetail.handleExport` |

权限：`srs_doc_view`。

---

## 3. 实现要点（export_srs_doc）

- 使用 `serv_utils/docx_util.py`：`save_title2docx / save_txt2docx / save_tab2docx / save_img2docx / insert_toc_field`。
- 过滤导入残留：目录行、「导入表格N」「导入图片N」占位标题。
- 需求表导出前清理合并占位、填充 module/function 继承值。
- 插入 TOC 域；可选 LibreOffice 刷新页码。
- 封面「需求规格说明」「文件修订记录」特殊排版；各大段分页前去掉文末空段落，避免封面表后空段落到下一页再强制分页，从而在封面与修订记录之间多出空白页。
- 「文件修订记录」表导出行数与编辑页一致：不足 5 行补空行，超过 5 行全部保留；导出前清空导入 Word 的 `cells` 网格，避免只写出 1 行。
- 正文之后另起一页追加「附件一 评审结论」（表格渲染与软件开发计划/详细设计评审记录一致）。树上已保存该节时，导出用保存后的评审内容表和参评人员表，不再用模板覆盖用户改过的单元格；正文里不再重复输出该节。树上没有该节时，才按《需求规格说明 附：评审记录》模板生成，参评人员按职称匹配该产品参与人员。评审表行高至少 40 磅，单元格文字上下居中。评审结论里的「通过 / 存在问题」勾选导出时画成「☑ 通过    □ 存在问题」：方框用 Wingdings 单色符号（不用会变成灰色表情的 ☑ 字符），框与文字之间一格，两项之间四格。已改过的评审项、结论文字仍按保存内容导出。
- 2.2 物理拓扑图 / 2.3 系统结构图：编辑页导出以当前树 `img_url` 为准，不再从产品图示覆盖。列表导出仅按当前 SRS 版本匹配图表文件，版本对不上则不插图。

---

## 4. 编辑页导出前置处理（前端）

- `fetchSrsTableState`：合并最新 SRS 表数据。
- `syncChangeReqTablesToTree`、`syncExportReqTablesInTree`、`appendMissingChangeTablesForExport`：把变更表/需求表行同步进树。
- `cleanTreeNode`：清洗后 POST snapshot；2.2/2.3 保留编辑页 `img_url`，导出不再用图表库覆盖。

---

## 5. 边界与特殊处理

- 列表导出用 DB 数据；编辑页导出包含**未保存**的编辑态。
- 导出会过滤 Word 导入残留的占位节点。
- `show_header=0` 的表不导出表头行。导出会把表重建成 `cells`，首行写的是表头名，因此 `save_tab2docx` 对不显示表头的表要把首行为表头名的那行一并去掉（否则新增需求的功能描述 KV 表会多出一行「字段 / 内容」）；只在还有数据行时去掉，避免把整表删空。
- 需求区节点（`ref_type=srs_reqs`）只在文档没有需求表时从库里补出「产品需求列表 / 其他需求列表」。产品需求列表已经导出过（`main_req_exported`）后，整节点跳过；编辑页即使把变更表挂到该节点上（节点因此带表子节点）也不再输出它的 label 和正文。跳过前若变更表还没写出，先从库补一次。否则导入文档会在变更需求表和「2.2 物理拓扑图」之间多出「产品功能列表如下：」「变更需求」两行。新建文档还没有导出过产品需求列表时，这个节点仍要输出，标题「产品功能列表如下：」留在需求表前面。
- **「变更」判断必须看表结构，不能只看名字**：变更需求表的跳过/延后导出逻辑（`__writenodes` 里按 `table.name` 含「变更」跳过、`has_change_req_marker`、`__is_snapshot_change_req_child`）都要再要求 `__is_req_list_table`（表头含「需求编号」+「功能」）。功能描述 KV 表的 `table.name` 可能就是带「变更需求」的章节名，若只按名字判断，该章节的表会整张不导出。同理 `__sync_change_req_tables_from_db` 清空节点标题也只对需求列表表格生效。

---

## 6. 修改注意事项 / 不可破坏的核心逻辑

1. **两种导出数据源不同**（DB vs snapshot），不可混用；编辑页必须用 snapshot 才能反映未保存内容。
2. 导出前的需求表清洗（合并占位、module/function 继承）不可去除，否则导出表格会缺值。
3. 占位节点（导入表格/图片 N）过滤逻辑不可移除。
