# 登录与权限

## 1. 功能概述

提供账号密码登录、会话保持、当前用户加载、修改密码、退出登录，并基于角色-权限模型控制菜单与接口访问。

---

## 2. 用户操作流程

1. 访问 `#/login`，输入账号 `name`、密码 `pwd` 提交。
2. 成功跳转 `#/`；`Home` 调用 `current_user` 拉取用户与 `role_perms`，写入 Redux，按权限渲染菜单。
3. 未登录访问受保护接口：返回 `code=-2`，前端跳转登录页。
4. 顶栏可改密、退出；「忘记密码」仅提示联系管理员重置。

---

## 3. 前端实现

| 路径 | 说明 |
|------|------|
| `pages/Login.tsx` | `login()` → `ApiUser.login` |
| `pages/Home.tsx` | `ApiUser.current_user`，`transformMenus(MENUS, role_perms)` 按权限过滤菜单 |
| `views/UserInfo.tsx` | `update_pwd`、`logout` |
| `api/http.ts` | `code === -2` 时 `location.replace(.../#/login)` |
| `store/` | Redux `user` slice 保存当前用户 |

---

## 4. 后端接口

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| POST | `/user/login` | LoginForm: name, pwd | 成功仅 `code=1`，session 写 `user=uid`（**不返回 data**） |
| GET | `/user/logout` | — | 清空 session |
| GET | `/user/current_user` | — | UserObj（含 role_perms） |
| POST | `/user/update_pwd` | pwd, pwd_new1, pwd_new2 | 任意 |

---

## 5. 数据库表

- `usr`：id, name(唯一), pwd, pwd_sk, nick_name, role_code
- `session`：key(PK), value(JSON), exp, uid

---

## 6. 关键业务逻辑与规则

1. **鉴权**：`AuthMiddleware` 从 session 取 `user` → `get_user` → `CtxUser/CtxPerm`；非白名单且无用户 → HTTP 200 + `code=-2`。
2. **会话**：`SessionMiddleware` + `DbBackend`（PostgreSQL `session` 表）；cookie `tx-session`，`max_age=24h`。
3. **密码哈希**：`md5(raw_pwd + pwd_sk)`；`pwd_sk` 为时间戳盐。
4. **默认密码**：新用户/重置默认 `DEF_PWD`（环境变量，默认 `test`）。
5. **管理员保护**：`ADMIN_NAME`（默认 master）受保护，不可被重置密码/删除。
6. **菜单渲染**：基于 `*_view` 权限；`/` 访问时 `findFirstLeaf(menus)` 跳第一个有权限的叶子菜单。

---

## 7. 边界与特殊处理

- 登录接口成功**不返回用户体**，前端需再调 `current_user`。
- 前端 `fetch` 未显式设 `credentials`；开发依赖 Vite 同源代理带 cookie。
- `Home` 无 `user.id` 时显示 Loading；非 `-2` 的失败仅 message，不自动跳登录。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **`code=-2` 跳登录**是全局约定，任何接口未登录都应返回 -2，前端据此跳转。不可改成别的码或抛 401。
2. **密码哈希算法**（md5+盐）固定，改动会导致存量用户无法登录。
3. **白名单**（login/logout/swagger/static）不可误删，否则登录页本身也会被拦。
4. **master/ADMIN_NAME 保护**不可移除。
5. 会话 cookie 名 `tx-session`、有效期 24h 为既定，改动需同步前后端。
