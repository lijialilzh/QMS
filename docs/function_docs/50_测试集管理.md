# 测试集管理

## 1. 功能概述

按产品 + 测试阶段维护测试集，支持 Excel 导入用例。同一产品同一阶段可有多份合集（如 A1/A2），用上传文件的**文件编号 + 名称**区分是否已上传。阶段：单元测试、集成测试、系统测试、用户测试。

---

## 2. 用户操作流程

按产品、阶段筛选 → 新增/编辑（产品+阶段+可选 xlsx）→ **批量添加**（选产品；每行选阶段，该行可多选多个 xlsx）→ 删除（级联用例）。列表操作列顺序：**查看**（原「查看数据集」，打开用例弹窗）→ 编辑 → 删除 → **导出测试记录**（原「导出数据集」）。

---

## 3. 前端实现

- 页面：`pages/test_set/TestSets.tsx`（内嵌 `TestCases`）
- API：`api/ApiTestSet.ts`（multipart）

---

## 4. 后端接口

| 方法 | 路径 | 权限 | 入参 |
|------|------|------|------|
| POST | `/test_set/add_test_set` | test_set_edit | Form: product_id, stage, file?（有 file 时解析文件名写入 file_no/file_name） |
| POST | `/test_set/update_test_set` | test_set_edit | id, product_id?, stage?, file? |
| DELETE | `/test_set/delete_test_set` | test_set_edit | id |
| GET | `/test_set/list_test_set` | test_set_view \| srs_doc_view | product_id?, stage?, 分页 |
| GET | `/test_set/get_test_set` | test_set_view | id |

---

## 5. 数据库表

`test_set`：product_id, stage, file_no（文件编号）, file_name（文件名称）；唯一 `(product_id, file_no, file_name)`。**须删除**旧唯一 `(product_id, stage)`。历史无文件名的行迁移时 `file_no=legacy-{id}` 占位（见 `trace-api/scripts/alter_test_set_file_no.sql`）。

---

## 6. 关键业务逻辑与规则

1. **Excel 导入**（`__read_excel`）：读 **全部 sheet**；扫描前 30 行识别表头（用例编号、需求编号、测试类型等）；`code` 须匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{1,63}$` 且含 `-`；varchar 字段截断 64；sheet 名写入用例 `sheet_name`（用户测试阶段下 sheet 名=型号）。
2. 更新且上传文件：**先删该集全部用例再导入**；并按新文件名刷新 `file_no`/`file_name`。
3. 列表过滤：未指定 product_id 时，超级管理员与非产品经理看全部；产品经理仅自己创建的产品（与软件测试计划等测试文件列表一致）。
4. **QA 默认权限**：可 `test_set_view`（查看列表/详情/导出），**无** `test_set_edit`（不可新增/更新导入/删除测试集）。超级管理员、DQA、测试人员等仍按各自默认角色包。
5. stage=`用户测试` 且导入 Excel 成功后，触发用户测试记录的自动新建或刷新（见 `91_用户测试记录管理.md`）；用例取该产品该阶段 **create_time 最新** 的测试集。
6. stage∈{单元测试,集成测试,系统测试} 且导入成功后，触发开发测试记录自动新建（见 `101_开发测试记录_单元集成系统.md`）；用例同样取该阶段最新测试集。
7. **查看用例**：弹窗按 `sheet_name` 分 Tab 区分型号（不另加「型号」列）；无 sheet 名时不显示 Tab，直接列表（无「全部」Tab）。
8. **导出数据集**：单元/集成/系统 → 导出测试记录 xlsx（模版+用例，按 `sheet_name` 分 sheet）；其它阶段仍导出用例表；用例来源为该阶段最新测试集。**下载文件名**（单元/集成/系统）= 导出记录表头「文件编号」（已按合集同步 Ax）+ 空格 +「单元/集成/系统测试记录」+ `.xlsx`；其它阶段仍为合集「文件编号 + 空格 + 文件名称」。表头文件编号、文件版本与该阶段最新合集版本一致（上传 A1 则导出记录为 A1；DHF 编号无 Ax 后缀时追加 `-A1`）。
9. **文件编号 / 名称**：从上传文件名（去扩展名）按「编号 + 空格 + 名称」解析，例 `TX-…-A1 用户测试用例.xlsx` → file_no=`TX-…-A1`，file_name=`用户测试用例`；无空格时 file_no=整段文件名、file_name 为空串。同产品下 `(file_no, file_name)` 已存在则视为已上传，拒绝新增（提示已存在）。
10. **批量添加**：选一次产品；默认 4 行，每行阶段下拉（可只填 1～2 行）；**每行「选择文件」可多选多个 `.xlsx`**；选产品后拉取已有编号+名称，选文件时即校验（含本批互斥），冲突在文件旁红字提示「已存在：{文件编号} {文件名称}」，并禁用「确定」；提交时每个文件各调一次 `add_test_set`。单条新增/编辑入口保留。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. 同产品下 `(file_no, file_name)` 唯一，用于识别是否已上传；**不再**用 `(product_id, stage)` 限制一阶段仅一份。
2. **更新上传文件 = 先清空再导入**（仅当前这条测试集），不可改为增量合并（会重复）。
3. 用例编号正则校验（含 `-`、长度 ≤64）不可放松，影响追溯编号匹配。
4. 删除测试集级联删用例不可遗漏。
5. 下游自动生成/导出用例必须取该产品该阶段 **最新**（create_time）测试集，避免多版本并存时取错。
