# 软件详细设计（SDS）导入导出

## 1. 功能概述

Word 导入解析生成 SDS 文档树并初始化设计/追溯数据；Word 导出生成 `.docx`。

---

## 2. Word 导入

### 2.1 用户操作流程
列表「导入」→ 选产品、SRS 版本、SDS 版本、变更说明、Word(.docx)，可勾选清空该产品历史 SDS → 提交。

### 2.2 后端接口
| 方法 | 路径 | 入参 |
|------|------|------|
| POST | `/sds_doc/import_sds_doc_word` | Form: product_id, srsdoc_id, version, change_log, file |

### 2.3 处理流程（import_sds_doc_word）
1. 绑定 SRS（指定 srsdoc_id → 同 version → 最新）。
2. 复用 `serv_srs_doc.__parse_docx_content` 解析。
3. SRS 编号 → SDS 编号（`SRS-` → `SDS-`）。
4. 目录提取、图片/表标题绑定、数据结构 DB 表拆分、章节号规范化。
5. `add_sds_doc(preserve_word_structure=True)`。
6. `__sync_imported_sds_reqd_fields`：从树文本写 `sds_reqd`。
7. `__sync_imported_sds_doc_images_to_doc_file`：流程图写入产品 `doc_file`。
8. `__ensure_sds_traces`：初始化追溯（**不**立即同步第 6 章）。

---

## 3. Word 导出

### 3.1 后端接口
| 方法 | 路径 | 入参 |
|------|------|------|
| GET | `/sds_doc/export_sds_doc` | id |

### 3.2 实现
- 读取 SDS 树 + `list_sds_reqd` + `list_sds_trace(from_sync)`。
- 组装封面、目录、追溯表、第 6 章功能设计（按需求层级插入描述六段）。
- 导出前自动获取封面签署人/日期（编制人=TPM，审核/批准=研发负责人），并按职称回填评审记录人员；封面若为 Word 导入 `cells` 表，同步写入对应格子，避免只导出空的姓名和日期。
- 正文之后另起一页追加「附件一 评审结论」（内容取自《软件详细设计-评审记录》模板，表格渲染与软件开发计划评审记录一致）；参评人员按职称匹配该产品参与人员，不导出树内已有评审记录以免重复。
- 输出 StreamingResponse，文件名 `{file_no}软件详细设计.docx`（与导入解析互逆，编号与固定文档名称直接拼接；`file_no` 为空则为 `软件详细设计.docx`）。
- 导出前规范化章节号、处理 stopper 节点（限制条件/尚未解决问题等）。

---

## 4. 边界与特殊处理

- 依赖 `python-docx`，缺失报错。
- 导入可选「清空该产品历史详细设计」。
- 导入后**首次**展示 Word 自带追溯表；点击同步后才重算（见 [34_SDS与SRS追溯同步.md](./34_SDS与SRS追溯同步.md)）。

---

## 5. 修改注意事项 / 不可破坏的核心逻辑

1. **SRS→SDS 编号转换（SRS-→SDS-）** 是追溯关联基础，不可改。
2. **导入用 `preserve_word_structure=True`** 保留 Word 结构，不可走手工树重排路径。
3. **导入只初始化追溯、不同步第 6 章**——同步是用户显式操作，不可在导入时自动执行。
4. 导出数据来自 `from_sync` 的追溯，需与同步状态一致。
