# 现场测试记录管理（FTR Record）

## 1. 功能概述

管理现场测试记录（测试文件 VV-006），一张大表格以 JSON 存储。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 大表格编辑器 → 导出 docx。

---

## 3. 前端实现

- 页面：`pages/ftr/FtrRecordDocs.tsx`（列表）、`FtrRecordDocDetail.tsx`（详情/编辑）
- API：`api/ApiFtrRecordDoc.ts`

---

## 6. 关键业务逻辑与规则

1. 与功能描述（26）不同，FTR Record 是现场测试记录。
2. 大表格以 JSON 数组形式存储。
3. 编辑页「测试项目」使用 Ant Design `Table`，须加 `className="ftr-record-table"`，覆盖全站 `.ant-table-wrapper{height:0}`，否则页面空白而导出仍正常。
4. 「测试结果」编辑页用复选框（通过 / 不通过，互斥）；存盘仍为 `■通过 □不通过` 文案，与导出一致。
5. **功能模块 / 功能**：打开时若同产品有《现场测试规程》，按其中第 2 章「功能测试用例」重建行。功能模块取该章下的二级章节名（如「登录」「系统管理」），其下级章节里的用例也归到这个二级章节。功能取「用例标题」，顺序与规程一致。模块和功能都对得上、或仅功能对得上时，保留测试结果和备注。模板里有、规程里没有的样例行去掉。规程和模板都没有的行视为手增，留在表尾。没有规程或没有该章时不改已有行。功能模块、功能都可改。增删不放在功能列：编辑页在「备注」后增加「操作」列，加号在当前行下插入一行，删除图标删当前行。封面表与测试项目表同宽、左右对齐；备注列收窄，操作列紧挨备注。查看页不显示该列。表内没有行时，表下仍可「添加功能」。操作列不入库、不导出。
6. **测试目的**：编辑页为「成品检验」「现场测试」两个勾选，互不排斥。存盘和导出写成 `□成品检验   □现场测试`，勾中的一项用 `■`。原来只有文字、没有勾选符的，打开后两个都不勾。
