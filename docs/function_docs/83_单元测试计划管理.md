# 单元测试计划管理（UTP）

## 1. 功能概述

管理单元测试计划（测试文件），PDP 风格章节树结构。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 导出 docx。

---

## 3. 前端实现

- 页面：`pages/utp/UtpDocs.tsx`（列表）、`UtpDocDetail.tsx`（详情/编辑）
- API：`api/ApiUtpDoc.ts`

---

`utp_doc`：product_id, version, file_no, change_log, content(JSON)

## 6. 关键业务逻辑与规则

1. PDP 风格章节树结构（菜单名「用户测试计划」）。
2. 与 UTR（用户测试报告）不同，UTP 是测试计划阶段文档。导出 docx 与编辑页一致：按 `{{TBL}}`/`{{IMG}}`/见下表交错输出表与图，静默占位不写入 Word；`table_captions`（如「测试计划如下：」）随表导出。
3. **「描述」章**：打开/换产品时自动写入产品名称←`name`、完整版本←`full_version`；有产品型号（`type_code`）则写入「产品型号：…」，无型号则不显示该行；其后说明正文保留。编辑页产品信息行只读，说明正文仍可改。
4. 「运行环境」章节打开/导出时从产品运行环境 `tables_json` 整表覆盖前 4 张表（含增删行列后的结构与表标题）；第 5 张测试设备表不改。文档内前 4 张表只读，不允许改单元格、增删行列或删表；章节标题可改、章节可删。
5. 章节树通用表格列宽按内容自适应，编号等短列收窄。
6. **文件修订记录**：修改日期、封面编制/审核/批准的日期、生效日期，都取时间线输出含「用户测试计划」的最晚一天（`yyyy.MM.dd`）。本版本没有时间线时，用同一产品名称下其它版本的时间线。不用宽泛「用户测试」，避免串到用户测试用例/记录/报告。修订人 ← 测试人员日期规则（2025.09 前「宋月」、之后「孙家旭」，打开即覆盖）；批准人 ← 研发负责人。本版本参与人员里没有研发负责人时，用同一产品名称下其它版本的研发负责人。
7. **「测试计划」表**：表名固定为「测试计划如下：」（去掉前缀版本号残片）。负责人打开/换产品时覆盖——活动或交付物含「用户测试记录」→ 用户人员（参与人员角色含「用户测试」）；活动含「用户培训」→ 产品经理（参与人员角色含「产品经理」，多人「、」连接，无则空）；其余行 → 测试人员（与修订人同一日期规则：宋月/孙家旭）。计划完成时间按测试活动匹配时间线；用例行关键字仅「用户测试用例」（不用宽泛「用例」，避免误取其它评审月）。
8. **「角色和职责」表**：打开/换产品时按「职责」与「测试计划」负责人同一规则覆盖「角色」「人员」——职责含「用户培训」→ 角色=产品经理、人员=产品经理；职责含「用户测试记录」→ 角色=模拟用户、人员=参与人员中角色含「用户测试」者；其余（计划/用例/报告及评审等）→ 角色=测试人员、人员=测试人员日期规则（宋月/孙家旭）。
9. 评审记录页面与需求规格说明一致：只读合并表，点右侧「编辑」弹出表格编辑，确认后写回；点「删除」去掉该表。编辑弹框里，参评人员签字、评审时间、评审结论、批准人员签字这些只在第一格有内容的行合并成一格。查看页不显示编辑和删除。参评人员从该产品参与人员覆盖。测试负责人多人时有宋月用宋月，没有宋月用孙家旭。
