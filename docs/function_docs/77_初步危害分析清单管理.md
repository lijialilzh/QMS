# 初步危害分析清单管理（PHA）

## 1. 功能概述

管理初步危害分析清单（风险文件），按产品+版本管理。整份文档以 content(JSON) 存储（单表），含封面/修订记录/A.1~A.4 各表。自动替换全文产品名称，A.2~A.4（CFMEA/DFMEA/PFMEA）表按危害编号从产品 HAZ 回填，封面日期从时间逻辑线自动更新。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 自动获取章节只读 → 导出 docx。

## 6. 关键业务逻辑与规则

1. 模板 `pha_template.json` 定义章节树结构。
2. 自动替换全文产品名称。
3. 1.2 / 1.3 / 1.4（CFMEA / DFMEA / PFMEA）的数据行只保留「当前产品名称 + 完整版本」在产品 HAZ 中、且模板把该编号分到本章的危害，按编号排序，不铺危害总表。潜在故障模式 ← 来源，故障的潜在原因 ← 产品 HAZ 情况（无则事件），失效的潜在影响 ← 伤害，分类 ← 分类，危害编号 ← 产品 HAZ 编号。表头整行都是同一个 CFMEA / DFMEA / PFMEA 时合并成一格。打开和导出都按这个重写。
4. 封面编制/审核/批准日期、生效日期、修订记录首行日期，从时间逻辑线自动覆盖。匹配输出含「初步危害分析」或「危害分析」的日期行，优先含「评审」的最新一天，写成「YYYY年M月D日」。不匹配「风险管理」，避免取到风险管理报告/计划的日期。表头「日    期」按去掉空白后的「日期」识别。
5. 修订记录首行：修订人 ← 参与人员「产品经理」的姓名，批准人 ← 参与人员「产品负责人」的姓名。只写姓名，不放签名图。打开即覆盖。
6. 导出复用 `docx_util` 工具。评审记录「评审结论」勾选导出用 Wingdings 单色方框（方框对号 + 空框），写成「☑ 通过    □ 存在问题」。不用 `☑` 字符，避免 Word 画成灰色表情。风险管理计划及其他走评审表导出的文件同一套。
7. 点「顶级章节」时，新章节插在「评审记录」之前。已经排在评审记录后面的正文顶级章节，打开和导出时挪到评审记录前面。评审记录保持目录最后一项。其他带评审记录的章节树文档，点「顶级章节」同样插在标题含「评审记录」的章节之前。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. 封面、修订记录等自动获取项仍按规则覆盖。评审记录表格可编辑（单元格、增删行列、添加表格）。没有评审记录章节时才按模板生成；已有内容打开和导出不再整章覆盖。
2. HAZ 回填逻辑不可破坏。
