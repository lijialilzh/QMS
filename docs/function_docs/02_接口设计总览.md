## 1. 统一规范

| 项 | 规范 |
|----|------|
| 基础路径 | `/trace-api`（`context_path`，见 `trace-api/src/__init__.py`） |
| 模块前缀 | `/trace-api/{module}/...`，例如 `/trace-api/srs_doc/...` |
| 方法语义 | GET=查询/导出；POST=创建/更新/导入/同步；DELETE=删除 |
| 请求体 | JSON Body（多数 POST 业务对象）或 `multipart/form-data`（文件上传 / 部分 Form 接口） |
| 分页入参 | `page_index`（从 0 开始，<0 归零）、`page_size`（默认 10，≤0 归 10） |
| 语言头 | `x-lang: zh-CN` 或 `en-US`，决定 `msg` 文案语言 |
| 鉴权 | Cookie Session（`tx-session`，DB 后端，`max_age=86400`） |
| 响应壳 | `{code, msg, data}`；分页时 `data` 为 `Page<T>` |
| HTTP 状态 | 业务响应**统一 HTTP 200**（错误也是 200，靠 `code` 区分）；文件导出返回二进制流 |
| Swagger | `/trace-api/docs`、`/trace-api/redoc` |

### 1.1 统一响应壳 `Resp<T>`

| 字段 | 类型 | 含义 |
|------|------|------|
| code | int | `1`=成功；`0`=业务错误；`-1`=未知异常；`-2`=未登录 |
| msg | str | 文案（i18n key 经 `ts()` 翻译，受 `x-lang` 影响） |
| data | T \| null | 业务数据 |

### 1.2 分页壳 `Page<T>`

| 字段 | 类型 | 默认 | 含义 |
|------|------|------|------|
| total | int | 0 | 总条数 |
| pages | int | 0 | 总页数（由 total/page_size 计算） |
| page_index | int | 0 | 当前页 |
| page_size | int | 10 | 页大小 |
| rows | List<T> | — | 数据列表 |

> ⚠️ 注意：部分列表接口（`list_prod_rcm`、`list_prod_haz`、`list_prod_cst`、`list_test_case`）后端**未做 offset/limit 真分页**，一次返回全部匹配，前端分页仅 UI 层。`list_prod_dhf`、`list_test_set`、SRS/SDS 列表等为真分页。

## 2. 错误码与消息

| code | 场景 | 处理方 | 典型 msg key |
|------|------|--------|--------------|
| 1 | 成功 | 业务 | `msg_ok` |
| 0 | 业务错误（已存在、不存在、无权限、参数错误） | 业务/装饰器 | `msg_obj_exist`/`msg_obj_null`/`msg_no_perm`/`msg_err_param:{字段}` |
| -1 | 未捕获异常 | `@try_log` | `msg_fatal` |
| -2 | 未登录 | `AuthMiddleware` | `msg_unlogin` |

### 2.1 常见 msg key 对照

| key | 含义 |
|-----|------|
| `msg_no_perm` | 您没有权限执行此操作 |
| `msg_obj_null` | 记录不存在 / 项目不存在 |
| `msg_obj_exist` | 数据已存在（唯一性冲突） |
| `msg_err_db` | 数据库处理异常 |
| `msg_err_param:{字段}` | 请求参数错误（FastAPI 校验失败） |
| `msg_unlogin` | 未登录 |
| `msg_user_null` / `msg_err_pwd` | 用户不存在 / 密码错误 |
| `msg_user_exist` / `msg_err_del_self` / `msg_err_reset_admin` | 用户名重复 / 不能删自己 / 不能重置管理员 |
| `msg_role_exist` / `msg_role_null` / `msg_role_in_use` | 角色名重复 / 角色不存在 / 角色被引用 |
| `msg_proj_x_product` | 项目下存在产品，禁止删除 |
| `msg_prod_x_srsdoc` / `msg_prod_x_testset` / `msg_prod_x_proddhf` / `msg_prod_x_docfile` | 产品被引用，禁止删除 |
| `msg_newpwd_unset` / `msg_newpwd_diff` | 新密码未设置 / 两次新密码不一致 |
| `msg_dup_row` | 导入存在重复行 |

## 3. 鉴权与权限

### 3.1 登录流程
1. `POST /trace-api/user/login`（白名单，无需 session），成功写 session `{"user": 用户id}`。
2. 后续请求 `AuthMiddleware` 读 session → 加载用户、角色、权限码到上下文（`CtxUser`/`CtxPerm`）。
3. 未登录访问非白名单 → `code=-2`。

### 3.2 白名单（无需登录）
`/trace-api/user/login`、`/trace-api/user/logout`，以及 `docs`/`redoc`/`openapi`。

### 3.3 权限装饰器 `@try_log(perm=...)`
- `perm` 为单值：需该 code 在用户权限集中。
- `perm` 为列表：满足**任一**即可（OR）。
- 无 `perm`：不校验功能权限，但仍需登录。
- 权限不足 → `code=0`，`msg_no_perm`。

## 5. 通用约定与坑位

1. **导出接口返回二进制流**（`StreamingResponse`，`.xlsx`/`.docx`），`response_model` 声明的 `Resp[Any]` 与实际不符，前端用 `responseType: blob` 接收。
2. **删除接口的 id 参数**：部分为单值 int（query），部分为逗号分隔字符串多值（`prod_rcm`/`prod_haz`/`prod_cst` 的 `delete_*s`）。
3. **Pydantic 字段几乎全为 Optional**，模型层无 `min_length`/`pattern` 等约束；必填校验主要来自 `Form(...)`/`File(...)` 与 service 层业务逻辑。
4. **文档树写入策略**：`update_srs_doc`/`update_sds_doc` 为「删除该文档全部节点 → 全量重建」，前端必须提交完整树；content 为 null/空数组会被拒绝。
5. **非管理员数据范围**：用户 id≠1 时，产品/文档/DHF 等列表按 `prod_user` 关联或 `create_user_id` 过滤。
