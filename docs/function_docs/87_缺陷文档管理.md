# 缺陷文档管理（Bug）

## 1. 功能概述

管理缺陷/Bug 文档（测试文件），上传原始 xlsx 文件（只读存档），解析"bug描述"工作表得到缺陷统计（按级别/状态分类），供软件测试报告缺陷统计分析引用。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增（上传 xlsx 文件）→ 系统自动解析统计 → 在线预览缺陷统计 → 下载原始文件 / 下载模板。

---

## 3. 前端实现

- 页面：`pages/bug/BugDocs.tsx`（列表）
- API：`api/ApiBugDoc.ts`

---

## 4. 后端接口

| 方法 | 路径 | 权限 |
|------|------|------|
| POST | `/add_bug_doc` | `bug_doc_edit` |
| POST | `/update_bug_doc` | `bug_doc_edit` |
| DELETE | `/delete_bug_doc` | `bug_doc_edit` |
| GET | `/list_bug_doc` | `bug_doc_view` |
| GET | `/get_bug_doc` | `bug_doc_view` |
| GET | `/preview_bug_doc` | `bug_doc_view` |
| GET | `/download_bug_template` | `bug_doc_view` |
| GET | `/download_bug_doc` | `bug_doc_view` |

---

## 5. 数据库表

`bug_doc`：product_id, version, file_no, change_log, file_name, file_path, file_data(LargeBinary), stats(JSON)

---

## 6. 关键业务逻辑与规则

1. 使用 openpyxl 解析 xlsx，统计缺陷级别分布和解决状态。
2. 文件存磁盘 + 二进制兼容旧数据。
3. 文件为只读存档，不支持在线编辑。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. 文件解析逻辑不可破坏，stats(JSON) 结构需与前端预览兼容。
2. 不支持在线编辑，仅上传/下载/预览。
