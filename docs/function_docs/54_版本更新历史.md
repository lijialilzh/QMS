## 1. 功能概述

按**产品（版本）**维护《版本更新历史》文档（DHF 之一），提供「新增 / 编辑 / 导出 Word / 复制 / 删除」操作，开发范式与「产品开发计划」完全一致。

- 一个产品下可有多个版本文档，`(product_id, version)` 唯一。
- 采用**目录树模型**：`content.sections` 为可递归的章节树，用户可自助任意增删/重命名章节、加子章节、编辑正文与表格，不需改代码即可扩展章节。
- **章节编号自动生成**：标题只存名称（不含编号），编号按目录树层级与位置自动计算（正文顶级 1/2/3、子级 1.1）；封面、文件修订记录为前置项不编号。导出 Word 时套 `Heading N` 样式并强制加粗。
- 新增时预填标准模板默认树（封面、文件修订记录、版本信息、软件版本命名规则、软件开发阶段更新历史表）。
- **自动获取**：进入编辑/查看或刷新时实时拉取产品/时间线/参与人员数据填充（版本信息始终取最新覆盖；命名规则/更新历史表/修订记录仅填空不覆盖）。

## 2. 前置依赖 & 关联模块

- 依赖：产品主数据（`/product/list_product`、`/product/get_product`）提供「产品名称 + 完整版本」级联下拉与自动获取字段（name/full_version/release_version）。
- 自动获取数据源：`/project_timeline/list_timeline`（发布/修订日期）、`/project_member/list_project_member`（修订人/批准人）。
- 列表页：`pages/vuh/VuhDocs.tsx`；详情录入页：`pages/vuh/VuhDocDetail.tsx`（复用 `pages/pdp/PdpDocDetail.less`）；API `api/ApiVuhDoc.ts`。
- 导出：后端 `python-docx` 生成 Word，复用 `serv_utils/docx_util.fonted_txt` 与 `insert_toc_field`；前端 `http.ts` 识别 `octet-stream` 自动触发下载。
- 菜单：「产品管理 → 版本更新历史」`/vuh_docs`，权限 `vuh_doc_view`。
- 【只读 / 禁止修改】：`/product/*` 产品模块、时间线/参与人员模块（仅读取）。

## 3. 完整执行流程（分步细化）

1. 列表页按产品 / 文档版本筛选，分页展示；「文件编号」支持列内单击编辑、失焦保存。
2. 新增：弹窗选择产品 + 文档版本（默认 A0）+ 文件编号 + 变更说明 → `add_vuh_doc` 以模板默认值建档 → 跳转 `/vuh_docs/edit/:id`。
3. 编辑（`/vuh_docs/edit/:id`）：左侧目录树切换/增删章节，右侧编辑「标题 / 正文 / 通用表格」；进入或刷新时自动填充（见第 4 节）；点「保存」整体 `update_vuh_doc`（仅提交 `content`，剥离临时 `_key`）。
4. 查看（`/vuh_docs/view/:id`）：与编辑同页，输入禁用为只读，仅可导出。
5. 导出：`export_vuh_doc` 先执行后端 `__autofill_for_export` 再遍历 sections 树渲染——封面（4 列、合并生效日期行）与修订记录为前置不编号，随后插入目录域 + 分页，再按树层级渲染正文（标题加粗、正文多行、各表格）。
6. 复制：`duplicate_vuh_doc` 同产品/跨产品自动递增版本号，深拷贝 `content`。
7. 删除：`delete_vuh_doc` 物理删除该文档记录。

## 4. 自动获取规则

前端在编辑/查看页 `load()` 时填充，后端 `__autofill_for_export` 在导出时同口径再填一次。

- **版本信息**（`ref_type=version_info`）：**始终取最新覆盖**（数据源全空时保留原值）。正文按模板生成：
  `本次软件为首次注册，软件完整版本为{完整版本}，发布版本为{发布版本}。` + 产品名称 / 发布版本 / 完整版本三行。其中产品名称 ← 产品名称、发布版本 ← `release_version`、完整版本 ← `full_version`。
- **软件版本命名规则**：写死规范文本（`NAMING_RULE_BODY`），**仅填空、不覆盖**。
- **文件修订记录首行**（仅填空）：`修改日期` ← 时间线含「版本更新历史」行最早日期（`YYYY年M月D日`）；`版本号` ← 文档版本；`修订说明` ← 写死「首次发布」；`修订人` ← 参与人员中角色含「产品经理」者；`批准人` ← 角色含「产品…负责人」者。
- **软件开发阶段更新历史表首行**（仅填空）：`完整版本` ← `full_version`；`发布版本` ← `release_version`；`类型` ← 写死「首次发布」；`发布日期` ← 时间线含「版本更新历史」行最早日期（`YYYY.MM.DD`）；`具体更新内容` ← 写死「首次发布」。

## 5. 核心规则 & 判定条件

- `add_vuh_doc`：`(product_id, version)` 已存在则报 `msg_obj_exist`；`content` 经 `__normalize_content` 补齐模板默认结构。
- `update_vuh_doc`：仅按 `exclude_none` 更新传入字段；`content` 落库前规范化。
- `duplicate_vuh_doc`：同产品在原版本号递增；跨产品按目标产品现有最大版本递增；冲突则继续递增。
- 列表权限收敛：`product_manager` 角色（非超管）仅能看到自己创建产品下的文档。
- 权限：写操作 `vuh_doc_edit`，读操作 `vuh_doc_view`；默认授予 root/dqa/qa 及 `product_manager`。

## 6. 数据结构说明

表 `vuh_doc`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| product_id | Integer NOT NULL | 产品 ID |
| version | String(64) NOT NULL | 文档版本，`(product_id, version)` 唯一 |
| file_no | String(128) | 文件编号 |
| change_log | String(512) | 版本变更说明 |
| content | JSON | 整份文档内容（目录树，结构同产品开发计划） |

`content` JSON 结构（目录树）：

```
content = { "sections": [ node, ... ] }
node = {
  "title":    str,            # 章节名称（不含编号，编号自动生成）
  "body":     str,            # 正文（多行，\n 分段）
  "tables":   [ table, ... ], # 通用表格列表，table 为二维字符串数组，首行视为表头
  "children": [ node, ... ],  # 子章节（可递归）
  "ref_type": str|omit        # cover=封面(4列，不编号)、revision=修订记录(不编号)、version_info=版本信息(始终取最新)、update_history=开发阶段更新历史表(首行自动填空)
}
```

- 后端 `__normalize_content` 递归规范化：非法 `content` 回落 `DEFAULT_VUH_CONTENT`；封面表旧版 2 列结构由 `__migrate_cover_table` 迁移为 4 列。
- 前端加载时给每个节点附加临时 `_key`，保存前 `stripKeys` 剥离。
- 模板默认树见后端常量 `DEFAULT_VUH_CONTENT`。

## 7. 异常场景 & 兜底逻辑

- 新增版本重复：返回 `msg_obj_exist`。
- 详情不存在：`get_vuh_doc` 返回 `msg_obj_null`；导出空 id 返回空白 docx。
- `content` 非字典：`__normalize_content` 回落为模板默认结构。
- 自动获取数据缺失（无时间线/参与人员/产品字段）：版本信息保留原值，其余单元保持空白，不报错。
- 保存 / 导出失败：前端 `message.error` 提示；数据库异常后端 `rollback` 返回 `msg_err_db`。

---

## 8. 功能约束 & 修改红线

1. 章节为数据驱动的目录树，用户可自助增删；导出仅依赖 `ref_type`（cover/revision/version_info/update_history）做特殊处理，其余按树层级渲染。
2. `update` 不接受修改 `id`；不允许跨产品迁移 `product_id`（复制走 `duplicate`）。
3. 仅「版本信息」为始终取最新覆盖，其余自动获取均为仅填空、不覆盖已保存数据。
4. 仅读取产品/时间线/参与人员数据，不修改这些模块。
