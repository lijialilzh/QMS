# 产品发布说明管理（Release Note）

## 1. 功能概述

管理产品发布说明（产品文件），章节树结构，记录每个版本的产品发布信息，包括新功能、修复的问题等。支持导出 docx。

| 项 | 内容 |
|----|------|
| 功能编号 | 57 |
| 所属模块 | 产品文件管理 |
| 主要代码位置 | 后端 `serv/serv_release_note.py`；前端 `pages/release_note/ReleaseNotes.tsx`、`ReleaseNoteDetail.tsx` |
| 文档版本 | v1.4 |
| 最后更新 | 2026-10-30 |

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 导出 docx。

## 6. 关键业务逻辑与规则

1. 章节树结构存储于 content(JSON)。
2. 与版本更新历史（54）不同，发布说明侧重发布内容而非版本历史记录。
3. **打开/刷新自动获取**（切换产品同样覆盖）：
   - 3.1「发布时间」始终按时间线输出含「发布说明」的**最晚**日期覆盖（`YYYY年M月D日`）；无匹配则空。
   - 3.4.1「产品移交记录」交付时间始终按时间线「产品验收记录」最晚日期覆盖；无匹配则空。
   - 3.4.1 / 3.4.2 文件编号始终按产品 DHF 名称匹配覆盖（名称含匹配；《》忽略）。
   - 第 2 章「产品概述」始终覆盖为：产品名称、产品型号（← `type_code`）、发布版本、完整版本、交付形式「物理交付」、存储媒介「U盘」、产品功能概述（← 总体描述）。没有产品型号时不写「产品型号」这一行，归档句也不再带空括号。
   - 3.3「文档归档」始终覆盖为：`通过评审，{产品名称}({型号}) {完整版本}版本的全套设计开发历史文档（DHF）和全套器械主记录（DMR）已完成归档。`
   - 「文件修订记录」首行日期/修订说明/修订人/批准人仅填空。版本号不把 A0 改成当前版本：文档版本为 A1、A2 时保留 A0 行，并按顺序补上尚未出现的 A1、A2 行。A0 的修订说明仍是「首次发布」。文档版本改低时去掉高于当前版本的行，同一个版本只留一行。
4. 封面表「文件版本」始终与文档 `version` 同步（升 A1 则封面为 A1）。
5. `duplicate_release_note`：同产品在原版本号递增。跨产品：目标已有该文档则按最大版本递增；**目标没有则版本为 A0**，文件编号取目标产品 DHF「产品发布说明」（再按版本同步尾缀），不用源产品编号。
6. 导出与打开同一套规则：发布时间/交付时间/DHF 编号/修订版本号/产品概述/文档归档覆盖。
7. **文件移交记录（3.4.2）交付人/接收人列纵向合并**：表头为「文件编号 / 文件名称 / 交付人·日期 / 接收人·日期」时，第 3、4 列（索引 2、3）在**数据区全部为空白**的情况下，纵向合并成一整格（导出 Word 为 `vMerge` 合并，编辑页为 `rowSpan`），供手工签字；只要其中任一行填了内容即不合并，恢复逐行独立单元格。数据结构不变，仍为二维数组，行数不变。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. content(JSON) 结构需与章节树编辑器兼容。
2. 更新只提交 content / 产品 / 版本，不改 id。
3. 改文档版本或新增更高版本时，文件修订记录保留不超过当前版本的版本行，每个版本只留一行，并补上从 A0 到当前版本中还没有的行。改回 A0 时去掉 A1 及更高的行。
