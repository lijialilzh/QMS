# 人员签名管理

## 1. 功能概述

管理人员签名（基础数据），记录人员姓名、职务、预留印鉴（图片）、人员签字（图片）、状态、排序。供各文档导出时自动注入签名/印章图片。

---

## 2. 用户操作流程

列表页展示所有人员签名 → 新增/编辑弹窗填写字段并上传印鉴/签字图片（base64）→ 保存 → 支持删除和排序。

---

## 5. 数据库表

`person_sign`：name, position, seal_img(TEXT base64), sign_img(TEXT base64), status, sort_order

---

## 6. 关键业务逻辑与规则

1. 图片以 base64 dataURL 格式存储和传输。
2. 表格内直接预览印鉴/签字图片缩略图。
3. 按 sort_order 排序展示。
4. **导出签名规则（共性）**：
   - 各模块列表页 / 编辑页的「导出」按钮（单文档导出接口 `export_xxx_doc`）：**不带签名**。封面「编制人/审核人/批准人」签署格留空白供手签，评审记录「参评人员签字」「批准人员签字」的签名图一并清空，姓名文字保留。
   - 整合导出（一键导出）、一键打印：走各自接口的 `with_sign` 开关，行为不变。
   - 实现：`trace-api/src/api/__init__.py` 在 `try_log` 里只识别单文档导出接口（`export_*_doc`、`export_*_doc_snapshot`、`export_release_note`，且排除 `export_single_doc` / `export_srs_doc_trace` / `export_doc_trace` 等带开关的整合导出），默认置 `with_sign=False`。打开、保存、列表（`get_*_doc` 等）不走这个开关，封面编制人、审核人、批准人按签名图填充。`serv_review_util.set_export_sign_mode(False)` 只在上述导出里让 `fill_cover_signers()` 清空封面签署格，并清除内容中命中「人员签名管理」的签名图。
   - 出口兜底：`docx_util.strip_signature_images()` 对最终 docx 做统一剥离，直接删除引用签名图的 `w:drawing` 元素并 `drop_rel` 解除关系（不保留占位图/底色，Word 打开不报错）。识别依据是与本表 `sign_img` / `seal_img` 完全一致的图片 MD5，正文截图与图表不受影响；非 Word（xlsx 等）导出直接跳过。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. 图片字段为 TEXT 类型存储 base64，注意长度限制。
2. 签名数据被多个文档导出功能引用。
