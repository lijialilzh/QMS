# AI 客服知识库（四）风险管理

> 本文件是给“AI 客服”使用的功能知识库，内容全部来自系统真实功能（功能逻辑文档 40–45、用户手册 94）。
> 每个功能按统一结构描述：界面位置 / 用户常见问法 / 是做什么的 / 解决什么问题 / 怎么用 / 相关功能。
> 目的：让 AI 既能“认识”每个功能（是什么、界面里叫什么），又能讲清楚“怎么用”。

---

## 模块总览：风险管理

风险管理模块覆盖医疗器械产品的风险识别、控制、追溯与报告产出，分布在多个一级菜单下：
- **基础库**（菜单「基础数据」）维护三类全局风险基础数据：**HAZ 管理**、**RCM 管理**、**THREAT 管理**（即 CST 网络安全威胁）。
- **产品风险**（菜单「产品管理 → 风险管理」）把基础库关联到具体产品，包含**风险参与人员 / 产品HAZ管理 / 产品RCM管理 / 产品THREAT管理**四个子项。
- **产品 DHF**（菜单「产品文件管理 → 其他 → 产品DHF管理」）按产品维护设计历史文件清单。
- **风险管理报告**（菜单「产品文件管理 → 风险文件 → 风险管理报告」）按产品/版本维护报告文档。
- **网络安全管理**（菜单「开发测试文件管理 → 网络安全管理 → 网络安全风险管理报告」）按产品/版本维护网络安全报告文档，独立于通用风险管理报告。

它解决的核心问题是：把产品要面对的危害与对应控制措施结构化地记录下来，并产出符合监管要求的风险管理报告，同时与需求（SRS）、设计（SDS）、测试形成追溯。

## 1. RCM 风险控制措施库

- **界面位置**：菜单「基础数据 → RCM 管理」，列表页路径 `/rcms`。
- **用户常见问法**：怎么新建 RCM、风险控制措施怎么加、RCM 怎么导入、RCM 怎么导出、怎么删 RCM、RCM 是什么。
- **是做什么的**：维护全局的「风险控制措施」基础库，每条 RCM 是一项控制手段，被 HAZ 危害分析、SRS 需求和产品层引用。
- **解决什么问题**：把可复用的控制措施沉淀为一个标准库，HAZ、需求、产品 RCM 都直接引用编号，避免重复定义、保证表述一致。
- **怎么用**：
  1. 列表页可模糊搜索；分页展示编号、描述、证明、备注、创建时间。
  2. 新建：点「新增」→ 填写编号（必填，全局唯一）、描述（必填）、证明、备注 → 保存。
  3. 编辑：行内点「编辑」修改描述/证明/备注（编号也可改，但需保证唯一）。
  4. 删除：单条删除或勾选后批量删除；删除会同时移除所有引用该 RCM 的产品 RCM 关联。
  5. 导入：选 `.xlsx` 文件即上传；存在按编号更新，否则新增。
  6. 导出：按当前筛选条件导出 Excel（最多 2000 条）。
- **相关功能**：HAZ 危害分析（HAZ 通过 RCM 编号串引用控制措施）、产品 RCM（把 RCM 关联到产品）、SRS 需求（需求可绑定 RCM）。

## 2. HAZ 危害分析库

- **界面位置**：菜单「基础数据 → HAZ 管理」，列表页路径 `/hazs`。
- **用户常见问法**：怎么新建 HAZ、危害分析怎么加、HAZ 怎么导入、HAZ 风险水平怎么填、怎么删 HAZ、HAZ 是什么。
- **是做什么的**：维护全局的「危害分析」基础库，每条 HAZ 记录一种危害的来源、事件、处境、损害，以及初始风险与剩余风险的评估（概率、程度、危险水平），并通过 RCM 多选关联控制措施。
- **解决什么问题**：把每种潜在危害和它对应的控制措施统一记录下来，作为后续产品风险评估和风险管理报告矩阵的源头数据。
- **怎么用**：
  1. 列表页支持模糊搜索，列含编号、来源、事件、处境、损害、初始/剩余风险、控制措施、RCM、证据、受益标志、类别。
  2. 新建：点「新增」→ 必填编号、来源、事件、处境、损害；可填初始/剩余风险三项（概率 1–5、程度 A–E、危险水平：不可接受 / 进一步降低的研究 / 可忽略）、控制措施、RCM（多选 RCM 编号，选中后自动拼接到「控制措施」）、证据、受益开关、类别。
  3. 编辑：行内编辑或弹窗编辑，未填的字段更新时不会清空原值。
  4. 删除：删除 HAZ 时会同时移除所有产品 HAZ 关联。
  5. 导入：导入模板从**第 3 行**起读取数据。
- **相关功能**：RCM 风险控制措施（被 HAZ 引用作为控制措施）、产品 HAZ（把 HAZ 关联到产品并补充评估）、风险管理报告（附录 B 风险矩阵以产品 HAZ 为准）。

## 3. CST 网络安全威胁库

- **界面位置**：菜单「基础数据 → THREAT 管理」（即 CST 网络安全威胁），列表页路径 `/csts`。
- **用户常见问法**：怎么新建 CST、网络安全威胁怎么加、CST 怎么导入、CST 类别有哪些、CST 是什么、CST 和 HAZ 有什么区别。
- **是做什么的**：维护「网络安全威胁」基础库（按 IEC 62443 风格分类），每条 CST 记录一项网络安全相关的威胁原因/条件；与 HAZ/RCM 在主数据层**无关联**，专用于产品层网络安全风险评估。
- **解决什么问题**：把网络安全维度的威胁单独成库，区别于医疗器械「危害分析」的安全风险，避免混在一张表里管理。
- **怎么用**：
  1. 列表页支持模糊搜索；列含编号、类别、模块、连接、描述、损害、创建时间。
  2. 新建：点「新增」→ 必填编号、描述；可填类别（下拉 9 类：认证、授权、保密性、密码学、代码/数据和执行完整性、事件检测与日记记录、恢复力与恢复、其他）、模块、连接、损害。
  3. 编辑：行内或弹窗编辑各字段。
  4. 删除：删除 CST 时会同时移除所有产品 CST 关联。
  5. 导入：导入模板从**第 2 行**起读取数据。
- **相关功能**：产品 CST（把 CST 关联到产品并做控制前/后评分）；CST 与 HAZ 是两个不同的风险维度，不可混为一张表。

## 4. 产品 RCM / HAZ / CST 关联（产品风险）

- **界面位置**：菜单「产品管理 → 风险管理 → 产品RCM管理」(`/prod_rcms`)、「产品管理 → 风险管理 → 产品HAZ管理」(`/prod_hazs`)、「产品管理 → 风险管理 → 产品THREAT管理」(`/prod_csts`)。
- **用户常见问法**：怎么把 RCM 关联到产品、产品 HAZ 怎么编辑、产品 HAZ 风险评估怎么填、产品 CST 评分怎么填、产品风险怎么删、能不能改产品 RCM。
- **是做什么的**：把基础库（RCM/HAZ/CST）批量关联到具体产品，并在产品层维护风险评估和追溯数据。三个子模块分别为：
  - **产品 RCM**：选产品后从主库批量勾选 RCM 加入，无行内编辑（只能删后重加）；系统按追溯规则自动计算「是否关联 SRS、SRS 编号、测试编号」。
  - **产品 HAZ**：批量加入 HAZ 后，可对每行做行内编辑（处境/损害、初始与剩余风险、控制措施、证据、RCM 多选）。
  - **产品 CST**：批量加入 CST 后，可行内编辑控制前/后的评分（得分、严重度、等级、可接受性）和关联 RCM 编号；CST 评分是独立 Float 体系，与 HAZ 评分**不是同一套字段**。
- **解决什么问题**：让每个产品有自己的一套风险清单与评估证据，作为风险管理报告的实时数据源，并把控制措施与 SRS 需求、测试用例打通形成追溯。
- **怎么用**：
  1. 进入对应子页（产品 RCM / HAZ / CST），先选产品（必选，否则提示「请选择产品!」）。
  2. 点「添加」打开主库勾选弹窗 → 模糊搜索 → 多选 → 确定，未勾选会提示。
  3. 行编辑（仅产品 HAZ / 产品 CST 支持）：
     - 产品 HAZ：可编辑处境、损害、初始/剩余风险（概率/程度/危险水平下拉）、控制措施、证据、RCM 多选；**选 RCM 多选后会自动重写控制措施文本**，证据可由同产品的 RCM 描述与测试编号自动聚合。
     - 产品 CST：可编辑控制前/后评分、严重度、等级、可接受性（下拉：可接受/不可接受/可忽略）、RCM 编号多选；只读列为编号、类别、描述。
  4. 删除：单条删除或勾选后批量删除。
  5. 导出：列表页可导出 Excel。
- **相关功能**：RCM / HAZ / CST 基础库（数据来源）、SRS 需求追溯（产品 RCM 自动计算 SRS/测试关联）、风险管理报告（附录 B 矩阵以产品 HAZ 为准、6.5 风险控制以产品 RCM 为准）。

## 5. 产品 DHF 设计历史文件

- **界面位置**：菜单「产品文件管理 → 其他 → 产品DHF管理」，列表页路径 `/prod_dhfs`。
- **用户常见问法**：怎么新建 DHF、产品 DHF 怎么加、DHF 怎么导入、设计历史文件在哪、DHF 怎么删、DHF 是什么。
- **是做什么的**：按产品维护「设计历史文件」清单——每条 DHF 记录一份文件的编号和名称，用于产品资料归档管理。
- **解决什么问题**：把每个产品对应的设计历史文件清单结构化记录下来，便于审计、监管追溯和资料管理。
- **怎么用**：
  1. 列表页按产品筛选，列含编号、名称、产品名称、产品版本、操作（编辑/删除）。
  2. 新建：点「新建」→ 必填产品、编号、名称（**同产品下编号唯一**） → 保存。
  3. 编辑：点行内「编辑」修改名称或编号。
  4. 删除：单条或勾选后批量删除。
  5. 导入：点「导入」→ 必填产品、选择 `.xlsx` 文件 → 上传；按编号更新，否则按名称回写编号。
  6. 导出：列表页可导出 Excel。
- **相关功能**：产品管理（DHF 挂在产品下）；DHF 与 RCM/HAZ/CST 无直接关联，是独立的资料清单。

## 6. 风险管理报告（列表 / 新建 / 编辑 / 复制 / 导入 / 导出 / 删除）

- **界面位置**：菜单「风险管理 → 风险管理报告」，列表页路径 `/risk_mgmt_docs`；详情页 `/risk_mgmt_docs/add`（新建）、`/risk_mgmt_docs/edit/{id}`（编辑）、`/risk_mgmt_docs/view/{id}`（只读查看）。
- **用户常见问法**：怎么写风险管理报告、风险管理报告怎么导入 Word、怎么新建风险报告、报告怎么复制、怎么导出风险报告 Word、报告版本怎么改、文件编号在哪改。
- **是做什么的**：按「产品 + 版本」管理风险管理报告文档，支持 Word 导入、空白新建、复制版本、按章节编辑、导出 Word。报告内容由章节树（content JSON）+ 参与人员 + 风险分析矩阵 + 风险控制措施 + 接受标准等构成。
- **解决什么问题**：把产品的风险管理输出整理成符合监管要求的标准报告文档，并与产品 HAZ/RCM 实时联动，保证报告里的矩阵和控制措施和当前产品风险数据一致。
- **怎么用**：
  1. 列表页按产品 + 文档版本筛选，列含产品名称、产品版本、报告版本、文件编号（单击编辑）、变更说明、创建时间、操作（查看/编辑/复制/导出/删除）。
  2. **新建（空白）**：点「新建」→ 选产品（必填，**选完会自动联动该产品的 HAZ/RCM 数据**，并把范围/产品描述/产品预期用途等文本章节按产品信息预填，仅当章节为空时填，不覆盖手填）→ 填写报告版本（必填）、变更说明 → 点「初始化模版」加载目录结构 → 选中章节后编辑内容 → 点顶栏「保存」。
  3. **导入 Word**：点列表「导入 Word」→ 弹窗中填写产品（必填）、版本（必填）、变更说明、上传 `.docx`（必填）→ 确定上传，系统按标题归一化匹配模板章节、图片转 base64 写入。
  4. **复制版本**：点行内「复制」→ 弹窗选目标产品（默认当前产品，可选其它产品实现跨产品复制）→ 确定，系统自动生成新版本号（同时复制风险分析/控制行）。
  5. **编辑**：列表行点「编辑」进入详情页 → 在目录结构区编辑章节（增删一级目录、节点改标题/加同级或下级）→ 各章节按类型编辑：
     - 「4.2 参与人员」从参与人员库勾选或在表格内编辑/删除行；
     - 「5.2.3 接受标准」展示固定矩阵色块表（红/橙/绿图例，5×5 概率×严重度），编辑态可维护矩阵格；
     - 「附录 B 风险分析矩阵」单元格可编辑，数据主要来自**产品 HAZ 实时数据**；
     - 「6.5 风险控制」可增 RCM 行，展示产品 RCM 描述列表；
     - 普通章节：段落文本 + 表格单元格可编辑；
     - 含图章节：上传/更换/清除图片（非图片提示「请选择图片文件」）；
     编辑完成点顶栏「保存」。
  6. **导出 Word**：详情页顶栏点「导出 Word」（**非新建态可见**，新建状态需先保存才能导出）。
  7. **文件编号**：在列表里单击「文件编号」单元格直接编辑。
  8. **删除**：行内点「删除」并按确认提示完成（删除会级联删除其风险分析/控制行）。
- **相关功能**：产品 HAZ（附录 B 矩阵的数据源）、产品 RCM（6.5 风险控制的数据源）、参与人员库（4.2 章节的勾选来源）、产品管理（报告挂在产品下）。

## 7. 参与人员库

- **界面位置**：菜单「风险管理 → 风险分析参与人员」，路径 `/risk_participants`。
- **用户常见问法**：怎么新建参与人员、参与人员怎么删、风险报告参与人员在哪维护、参与人员重复了怎么办。
- **是做什么的**：维护全局的「项目角色 + 姓名」参与人员清单，供风险管理报告 4.2 章节勾选填入。
- **解决什么问题**：把跨多份报告复用的参与人员沉淀为一个全局列表，避免每份报告手工重复录入。
- **怎么用**：
  1. 列表页支持按关键词搜索（匹配项目角色 / 姓名）。
  2. 新建：点「新建」→ 必填项目角色、姓名 → 保存（**唯一约束：(角色, 姓名) 不可重复**）。
  3. 编辑：点行内「编辑」修改角色或姓名。
  4. 删除：点「删除」按提示「确认删除该参与人员吗？」确认。
- **相关功能**：风险管理报告（4.2 参与人员章节从该库勾选；参与人员同时存在于报告 content 与人员库，二者相对独立）。
