# AI 客服知识库（零）系统菜单导航

> 本文件是给“AI 客服”使用的菜单导航全景知识库，内容全部来自系统真实菜单（前端 `pages/Home.tsx` 菜单配置 + i18n `zh-CN.json` 文案）。
> 每个一级菜单按统一结构描述：界面位置 / 用户常见问法 / 是做什么的 / 解决什么问题 / 怎么用 / 相关功能。
> 目的：当用户问“X 在哪”“基础数据有什么”“一级菜单都有哪几个”时，AI 能精确回答菜单层级。

---

## 模块总览：系统菜单导航

医疗器械软件质量管理追溯系统（QMS）的左侧菜单共 **10 个一级菜单**，按使用顺序大致是"配置 → 基础数据 → 产品 → 文件 → 开发测试 → 总览"：

1. **仪表盘**
2. **系统配置**：角色管理 / 用户管理 / 产品线管理
3. **通用配置**：打印服务配置 / 版本命名规则 / 公司基本信息 / 人员签名管理
4. **基础数据**：HAZ 管理 / RCM 管理 / THREAT 管理
5. **产品管理**：基本信息（版本管理 / 参与人员 / 时间逻辑线 / 运行环境 / 设备资源）、风险管理（风险参与人员 / 产品HAZ管理 / 产品RCM管理 / 产品THREAT管理）、产品图示（物理拓扑图 / 体系结构图 / 用户界面关系图 / 网络安全流程图）
6. **产品文件管理**：产品文件（产品立项报告 / 产品开发计划 / 需求规格说明 / 产品验收记录 / 产品发布说明 / 版本更新历史 / 产品技术要求 / 自研软件研究报告）、风险文件（风险管理计划 / 初步危害分析清单 / 自研软件网络安全研究报告 / 网络安全能力分析 / 产品标签样稿 / 网络安全维护计划 / 风险管理报告）、其他（培训记录表 / 产品DHF管理）
7. **开发测试文件管理**：开发文件（软件配置管理计划 / 软件配置状态报告 / 软件开发计划 / 软件详细设计 / 开发环境维护说明 / 代码审查记录 / 数据申请单 / 开发设备清单）、测试文件（软件测试计划 / Bug管理及回归测试 / 软件测试报告 / 测试环境维护说明 / 安装维护手册 / 现场测试规程 / 现场测试记录 / 用户测试计划 / 用户测试报告 / 测试设备清单 / 测试用例合集 / 追溯分析）、网络安全管理（网络安全风险管理报告）
8. **全局视图**：文档内容比对 / 整合导出（整合导出 / 导出记录）/ 一键打印（一键打印 / 打印记录）

> 所有菜单按当前用户的角色权限过滤，无权限的菜单不显示。详情：见各模块说明。

## 1. 仪表盘

- **界面位置**：左侧菜单第 1 项「仪表盘」（`/dashboard`），是一级菜单（无子菜单）。
- **用户常见问法**：仪表盘是什么、首页有什么、登录后第一个看到的页面。
- **是做什么的**：登录后系统的概览/首页。
- **解决什么问题**：作为系统的入口和总体状态展示。
- **怎么用**：登录后默认会跳到仪表盘；从其它页面回到仪表盘可点左侧菜单第一项「仪表盘」。
- **相关功能**：登录、其它各业务菜单。

## 2. 系统配置

- **界面位置**：左侧菜单「系统配置」，下含 3 个二级菜单。
- **用户常见问法**：系统配置是什么、系统配置下面有什么、用户角色项目在哪、怎么找到角色管理、产品线在哪个菜单。
- **是做什么的**：管理“谁能用系统”和“项目归属”这两件基础事。包含 3 个二级菜单：
  - **角色管理**（`/roles`）：查看预置 7 个角色（root / dqa / qa / ra / 产品经理 / 开发 / 测试）及配置每个角色的权限范围。
  - **用户管理**（`/users`）：新建 / 编辑用户、给用户分配角色、重置密码、删除用户。
  - **产品线管理**（`/projects`）：维护“项目（产品线）”，是产品的上级归属。
- **解决什么问题**：让每个使用系统的人都有自己的账号、按角色获得权限，并把产品按项目（产品线）归类。
- **怎么用**：点左侧「系统配置」展开 → 选对应二级菜单进入。
- **相关功能**：基础数据（业务数据维护）、产品版本管理（产品挂在项目下）。

## 3. 基础数据

- **界面位置**：左侧菜单「基础数据」，下含 3 个二级菜单。
- **用户常见问法**：基础数据是什么、基础数据有什么、基础数据下面包含什么、基础数据都有哪些、HAZ 在哪、RCM 在哪、CST 在哪、THREAT 管理是什么。
- **是做什么的**：维护**风险相关的全局基础库**，是产品风险评估的源头数据。包含 3 个二级菜单：
  - **HAZ 管理**（`/hazs`）：维护「危害分析」基础库——每条 HAZ 记录一种危害的来源、事件、处境、损害和初始/剩余风险评估。
  - **RCM 管理**（`/rcms`）：维护「风险控制措施」基础库——每条 RCM 是一项可复用的控制手段，被 HAZ、SRS 需求、产品 RCM 引用。
  - **THREAT 管理**（`/csts`）：维护「网络安全威胁（CST）」基础库（按 IEC 62443 风格分类），与 HAZ/RCM 在主数据层无关联，专用于网络安全维度。
- **解决什么问题**：把可复用的危害、控制措施、网络安全威胁沉淀为标准库，给每个产品做风险评估时直接引用，不必重复定义。
- **怎么用**：点左侧「基础数据」展开 → 选 HAZ / RCM / THREAT 进入对应库做新建、编辑、导入、导出、删除。
- **相关功能**：风险追溯管理（把基础库关联到具体产品）、风险管理（报告里的矩阵和控制措施引用基础库）、需求管理（SRS 需求可绑定 RCM）。

## 4. 产品管理

- **界面位置**：左侧菜单「产品管理」，下含 3 个二级分组。
- **用户常见问法**：产品在哪、产品管理在哪个菜单、产品管理下面有什么、版本管理在哪、参与人员在哪、时间逻辑线在哪、运行环境在哪、设备资源在哪、风险参与人员在哪、产品HAZ在哪、产品RCM在哪、产品THREAT在哪、产品图示在哪、拓扑图在哪、结构图在哪、界面关系图在哪、流程图在哪。
- **是做什么的**：管理产品维度的所有配置与文件。包含 3 个二级分组：
  - **基本信息**（`prod_basic`）：版本管理（`/products`）/ 参与人员（`/project_members`）/ 时间逻辑线（`/project_timeline`）/ 运行环境（`/prod_runtime_env`）/ 设备资源（`/prod_device_res`）
  - **风险管理**（`prod_risk_mgmt`）：风险参与人员（`/risk_participants`）/ 产品HAZ管理（`/prod_hazs`）/ 产品RCM管理（`/prod_rcms`）/ 产品THREAT管理（`/prod_csts`）
  - **产品图示**（`prod_diagrams`）：物理拓扑图（`/doc_files_topo`）/ 体系结构图（`/doc_files_struct`）/ 用户界面关系图（`/doc_files_ui`）/ 网络安全流程图（`/doc_files_flow`）
- **解决什么问题**：把产品的档案、配置、风险管理和图示集中在一个菜单下，方便产品经理和项目成员一站式管理。
- **怎么用**：点左侧「产品管理」展开 → 选对应分组展开 → 点具体功能进入。
- **相关功能**：系统配置 → 产品线管理（产品的上级归属）、产品文件管理（产品下的文档）、开发测试文件管理。

## 5. 产品文件管理

- **界面位置**：左侧菜单「产品文件管理」，下含 3 个二级分组。
- **用户常见问法**：产品文件管理是什么、产品文件有哪些、风险文件在哪、产品立项报告在哪、产品开发计划在哪、需求规格说明在哪、产品验收记录在哪、产品发布说明在哪、版本更新历史在哪、产品技术要求在哪、自研软件研究报告在哪、风险管理计划在哪、初步危害分析清单在哪、自研软件网络安全研究报告在哪、网络安全能力分析在哪、产品标签样稿在哪、网络安全维护计划在哪、风险管理报告在哪、培训记录表在哪、产品 DHF 在哪。
- **是做什么的**：按「产品文件」「风险文件」「其他」三个分组管理产品全生命周期的各类文档。包含 3 个二级分组：
  - **产品文件**（`prod_files`）：产品立项报告（`/pir_docs`）/ 产品开发计划（`/pdp_docs`）/ 需求规格说明（`/srs_docs`）/ 产品验收记录（`/acc_docs`）/ 产品发布说明（`/release_notes`）/ 版本更新历史（`/vuh_docs`）/ 产品技术要求（`/ptr_docs`）/ 自研软件研究报告（`/research_docs`）
  - **风险文件**（`risk_files`）：风险管理计划（`/rmp_docs`）/ 初步危害分析清单（`/pha_docs`）/ 自研软件网络安全研究报告（`/nsr_docs`）/ 网络安全能力分析（`/cyber_cap_docs`）/ 产品标签样稿（`/label_docs`）/ 网络安全维护计划（`/nsmp_docs`）/ 风险管理报告（`/risk_mgmt_docs`）
  - **其他**（`prod_other_files`）：培训记录表（`/train_record_docs`）/ 产品DHF管理（`/prod_dhfs`）
- **解决什么问题**：把产品从立项、开发、验收、发布到风险管理的所有文档集中在一个菜单下，按类型分组，方便查找和维护。
- **怎么用**：点左侧「产品文件管理」展开 → 选对应分组展开 → 点具体文档类型进入列表页。
- **相关功能**：产品管理（文档挂在产品下）、开发测试文件管理（SDS 等开发测试文档）、全局视图（跨产品文档比对与导出）。

- **用户常见问法**：开发测试文件管理是什么、开发文件有哪些、测试文件在哪、软件配置管理计划在哪、软件配置状态报告在哪、软件开发计划在哪、软件详细设计在哪、开发环境维护说明在哪、代码审查记录在哪、数据申请单在哪、开发设备清单在哪、软件测试计划在哪、Bug管理在哪、软件测试报告在哪、测试环境维护说明在哪、安装维护手册在哪、现场测试规程在哪、现场测试记录在哪、用户测试计划在哪、用户测试报告在哪、测试设备清单在哪、测试用例合集在哪、追溯分析在哪、网络安全风险管理报告在哪。

  - **开发文件**（`dev_files`）：软件配置管理计划（`/scm_docs`）/ 软件配置状态报告（`/scs_docs`）/ 软件开发计划（`/sd_docs`）/ 软件详细设计（`/sds_docs`）/ 开发环境维护说明（`/dem_docs`）/ 代码审查记录（`/crr_docs`）/ 数据申请单（`/dat_docs`）/ 开发设备清单（`/deq_docs`）

- **怎么用**：点左侧「开发测试文件管理」展开 → 选对应分组展开 → 点具体文档类型进入列表页。
- **相关功能**：产品文件管理（SRS 等产品文档是 SDS 的输入）、产品管理（文档挂在产品下）、全局视图（跨产品文档比对与导出）。

## 7. 全局视图

- **界面位置**：左侧菜单「全局视图」，下含 3 个二级菜单。
- **用户常见问法**：全局视图是什么、文档内容比对在哪、整合导出在哪、一键打印在哪、导出记录在哪、打印记录在哪。
- **是做什么的**：跨产品 / 跨版本的文档比对、整合导出与一键打印工具。包含 3 个二级菜单：
  - **文档内容比对**（`/doc_comparison`）：选择两个文档（同一产品不同版本的 SRS/SDS，或不同产品的同类文档）进行内容差异对比，高亮显示增删改差异。
  - **整合导出**（`doc_integrate_export`）：按产品聚合所有文档清单，支持批量选择后整合导出为 Word 文档；下含「导出记录」（`/doc_export_records`）查看历史导出任务。
  - **一键打印**（`doc_one_click_print`）：选择文档后一键生成打印 URL 清单，批量打印；下含「打印记录」（`/doc_print_records`）查看历史打印任务。
- **解决什么问题**：在版本升级、交付审计或归档时，快速完成文档比对、批量导出和批量打印，提升效率。
- **怎么用**：点左侧「全局视图」展开 → 选「文档内容比对」做差异对比 / 选「整合导出」批量导出文档 / 选「一键打印」批量打印文档。
- **相关功能**：产品文件管理 / 开发测试文件管理（数据来源）、产品管理（文档按产品版本组织）。
