# 风险管理报告（风险管理文档）

## 1. 功能概述

按产品维护风险管理文档（章节树 JSON），含参与人员、风险分析矩阵、风险控制措施、接受标准等；支持 Word 导入导出、复制版本。

---

## 2. 用户操作流程

### 2.1 列表（`/risk_mgmt_docs`）
按产品/版本筛选 → 新建空白 / Word 导入 / 复制版本（弹窗选目标产品，支持跨产品复制） / 编辑文件编号 / 导出 docx / 删除。
> 列表列宽：「文件编号」整列完整展示（不换行），「变更说明」列收窄。

### 2.2 详情（`/risk_mgmt_docs/add|edit/:id|view/:id`）
章节树编辑、`content` JSON、参与人员、附录矩阵（拉取产品 HAZ/RCM）、导出 Word。

**新增模式选产品后自动联动**（`RiskMgmtDocDetail.tsx`，仅 `isAdd`）：
- 选定产品+版本后，按 `selectedProductId` 自动拉取该产品的 RCM（`list_prod_rcm`）、HAZ（`list_prod_haz`）、全局 HAZ（`list_haz`），填充 6.5 风险控制措施、附录 B HAZ 矩阵等动态区。
- 自动填充文本章节（**仅当章节正文为空时填**，不覆盖手填）：
  - 「范围」← 产品 `scope`；「产品描述」← 产品名称/型号/完整版本；「产品预期用途」← 产品 `component`（产品组成）。
  - 其它固定文本章节（如「目的」「审评历史」「风险分析方式」「危害识别」「参考标准」等）填入内置默认文案。
- 「初始化模版」按钮同样会用当前所选产品（若有）执行上述文本章节填充。

### 2.3 参与人员库（`/risk_participants`）
全局角色+姓名维护（与文档内 4.2 节可并存）。

## 5. 数据库表

`risk_mgmt_doc`（content JSON）、`risk_participant`、`risk_analysis`、`risk_control`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）。

content 结构：`sections[]`（title, ref_type, text, tables, children, images）、participants[]、riskMatrix[]、riskControls[]、productName、sourceWordPath。

ref_type：cover、revision、participants、acceptance_standard、risk_analysis、risk_controls。

---

## 6. 关键业务逻辑与规则

1. **接受标准**：内置 `RISK_ACCEPTANCE_TABLE`（5×5 概率×严重度→水平；红/橙/绿说明）。
2. **6.4 / 附录B**：`ref_type === risk_analysis` 时 `renderProdHazMatrix()` 用 `list_prod_haz`（**非必须** risk_analysis 表）。
3. **6.5 产品 RCM**：`ref_type === risk_controls` 子节展示 `prodRcms`。
4. **6.5.4 引入新风险**：表格 + 全局 hazs 按 RCM 编号匹配。
5. 复制（支持跨产品）：列表「复制」弹窗选目标产品（默认当前产品），版本号自动生成、不允许手动填。
   - 同产品：`new_version(原版本)` 递增；跨产品：按目标产品现有最大版本 `new_version()` 递增，目标产品无文档则沿用原版本；撞号循环兜底递增，保证目标产品下 `(product_id, version)` 唯一。
   - 新文档 `product_id` = 目标产品；复制 `risk_analysis` / `risk_control` 行时其 `product_id` 同步改为目标产品（`doc_id` 指向新文档）。
6. 删除文档：删关联 analysis/control 行。
7. 选产品自动填充：见 2.2，文本章节「仅空时填」，动态矩阵区按 `selectedProductId` 实时拉取。

---

## 7. 边界与特殊处理（重要：三套并行数据源）

风险管理报告存在**三套并行**数据：
- `risk_mgmt_doc.content`（JSON 章节）
- `risk_analysis` / `risk_control`（结构化表）
- 产品 HAZ 实时矩阵（`list_prod_haz`）

详情页矩阵主要来自 **`list_prod_haz`**，非仅 DB 矩阵表。

- 保存文档时 participants 写入 **content**，与 `risk_participant` 表分离；`list_risk_participant` 首次可从历史 doc seed。
- Word 导入按标题归一化匹配模板章节；图片转 base64 写入 section。
- 导出：产品名替换、附录表搬迁、接受标准图从 `sourceWordPath` 回填。
- `RiskMgmtListPage` 无菜单路由。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **三套数据源的权威关系**：详情页矩阵以 `list_prod_haz` 为准，不可误改为只读 risk_analysis 表。
2. **接受标准表 RISK_ACCEPTANCE_TABLE**（5×5）为合规内容，不可随意改动。
3. **participants 同时存在于 content 与 risk_participant 表**，两者分离，不可强制同步。
4. 删除文档级联删 analysis/control 不可遗漏。
5. content 经 `__normalize_content` 规范化，保存前结构不可破坏。
6. **复制 `product_id` 为可选参数**，不传=同产品复制；跨产品复制时子表 `product_id` 必须同步为目标产品，否则残留旧产品 ID。
7. 选产品自动填充文本章节遵循「仅空时填」，不可改为覆盖手填内容。
