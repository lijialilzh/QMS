## 1. 功能概述

按**产品（版本）**维护合规医院清单：医院名称、区域划分、医院编号、省份、城市信息。用于产品数据采集/合规医院登记。列与 `hospital_info.xls` 一致。

- 数据维度：产品版本级（`prod_id`），与参与人员一致。
- 菜单：「产品管理 → 基本信息 → 合规医院列表」`/prod_hospitals`。
- 支持 Excel 导入（`.xls` / `.xlsx`，表头对齐 `hospital_info.xls`）；导入覆盖当前产品已有清单。不回写产品主数据。`dd_002` 打开/换产品时只读本列表：按病例明细 TXID 查医院编号，命中的医院信息及数据量写入回传表（见 [100_数据文件管理.md](./100_数据文件管理.md) R20）。

## 2. 前置依赖 & 关联模块

- 依赖：产品主数据（`/product/list_product`）提供「产品名称 + 完整版本」级联下拉（`ProductVersionSelect`）。
- 权限：读 `prod_hospital_view`，写 `prod_hospital_edit`。产品经理读写；开发/测试/RA 只看；root/DQA/QA 全权限。
- 【只读 / 禁止修改】：`/product/*` 产品模块、参与人员、时间逻辑线、运行环境、设备资源。数据文件仅 `dd_002` 只读本列表，不回写。

## 3. 完整执行流程（分步细化）

1. 进入页面 → 拉取产品下拉（`list_product`，page_size=1000）。
2. 选择产品（版本）→ `list_prod_hospital(prod_id)`，按 `sort_order, id` 升序展示。
3. 产品下尚无记录时，自动写入默认 8 家医院（截图名单），之后可手动增删改或导入覆盖；已有记录不重复写入。
4. 关键字（可选）筛医院名称 / 医院编号 / 区域划分 / 省份 / 城市信息，调用 `list_prod_hospital(prod_id, fuzzy)`。有关键字时不触发默认写入。
5. 点击「新增」→ `add_prod_hospital(prod_id, 空字段, sort_order=当前最大+1)`，再加载。
6. 点击「导入」→ 选择 `.xls` / `.xlsx` → 确认覆盖 → `import_prod_hospitals(prod_id, replace=true, file)`。
   - 表头行定位含「医院名称」「医院编号」的行（`hospital_info.xls` 第 2 行；第 1 行标题「客户信息」跳过）。
   - 列映射：医院名称→`org_name`，区域划分→`region`，医院编号→`hospital_no`，省份→`province`，城市信息→`city`；若有合同编号则写入 `contract_no`。
   - 医院名称与医院编号都空的行跳过；同一文件内医院编号重复只保留首次。
7. **点击单元格即可编辑、失焦实时保存**：
   - 医院名称 / 医院编号 / 省份 / 城市信息：`Input`，失焦或回车保存；
   - 区域划分：`AutoComplete`（东区 / 南区 / 西区 / 北区，可自定义），失焦保存；
   - 保存调用 `update_prod_hospital`，不改 `id` / `prod_id`。
8. 删除：行尾「删除」→ 确认 → `delete_prod_hospitals(id)` → 重新加载。

## 4. 核心规则 & 判定条件

| 编号 | 规则 / 判定条件 | 含义 | 不满足 / 命中时的后果 |
|------|----------------|------|----------------------|
| R1 | `add_prod_hospital`：`prod_id` 必填 | 医院挂在产品下 | 参数错误 |
| R2 | `update_prod_hospital` 不更新 `id` / `prod_id` | 不可跨产品迁移 | 只改名称/编号/区域/省份/城市/合同编号/排序 |
| R3 | `delete_prod_hospitals` 逗号分隔 id | 物理删除 | 过滤非数字后批量删 |
| R4 | 列表按 `sort_order, id` 升序；未传 `prod_id` 返回空页 | 按产品查询 | 前端未选产品不请求 |
| R5 | 空表才写默认 8 家 | 保护手改 / 导入结果 | 已有记录不重复写 |
| R6 | 写 `prod_hospital_edit`，读 `prod_hospital_view` | 权限 | 无权限拦截，菜单不可见 |
| R7 | `import_prod_hospitals`：`prod_id` 必填；`replace=true` 先删该产品全部再写入 | 导入覆盖 | 无表头或文件无法解析返回参数错误；其它产品不受影响 |

## 5. 数据结构说明

表 `prod_hospital`：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| prod_id | Integer NOT NULL, index | 产品 ID |
| contract_no | String(64) | 合同编号（导入有则写，列表不展示） |
| org_name | String(256) | 医院名称 |
| hospital_no | String(64) | 医院编号 |
| region | String(32) | 区域划分 |
| province | String(64) | 省份 |
| city | String(128) | 城市信息 |
| sort_order | Integer 默认 0 | 排序 |

接口：

| 方法 | 路径 | 权限 |
|------|------|------|
| POST | `/prod_hospital/add_prod_hospital` | prod_hospital_edit |
| POST | `/prod_hospital/update_prod_hospital` | prod_hospital_edit |
| DELETE | `/prod_hospital/delete_prod_hospitals` | prod_hospital_edit |
| GET | `/prod_hospital/list_prod_hospital` | prod_hospital_view |
| POST | `/prod_hospital/import_prod_hospitals` | prod_hospital_edit |

## 6. 异常场景 & 兜底逻辑

- 未选产品点「新增」/「导入」：提示「请先选择产品」，不发请求。
- 未选产品：内容区居中空态「请先选择产品」。
- 导入文件无「医院名称 + 医院编号」表头：参数错误。
- 保存/删除/导入失败：`message.error` 提示后端 msg。
- 数据库异常：后端 `rollback` 并返回 `msg_err_db`。

---

## 7. 功能约束 & 修改红线

1. `update` 不可修改 `prod_id`。
2. 删除为物理删除，按 id 批量；不做软删除。
3. `dd_002` 打开/换产品只读本列表，按病例明细 TXID 匹配后写入回传表，不回写本列表。`dd_003` / `dd_004` / `dd_010` 跟随最新 `dd_002` 回传结果（见 [100_数据文件管理.md](./100_数据文件管理.md) R21 / R22 / R29），也不回写本列表。
4. 默认 8 家仅在该产品记录为空时写入一次。
5. 导入覆盖仅限当前产品，不改其它产品清单。
