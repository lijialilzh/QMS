# 需求规格说明（SRS）文档管理

## 1. 功能概述

SRS 文档的列表、新增、编辑、查看、复制、删除、文件编号内联编辑。SRS 文档以「文档主表 + 节点树」存储，挂在产品下，按版本管理。

---

## 2. 用户操作流程

### 2.1 列表（`/srs_docs`）
1. 按产品、文档版本筛选，分页浏览。
2. 行内：查看 / 编辑 / 复制（弹窗选目标产品，支持跨产品复制） / 导出 Word / 删除。
3. 单击「文件编号」单元格内联编辑保存。
4. 顶部「导入」Word、「新增（弹窗选产品/版本，创建后进入编辑页）」。产品可见范围不在本页，只从系统配置进入。

### 2.2 新增 / 编辑 / 查看
- 新增：列表页点击「新增」→ 弹窗选择产品、SRS 版本等 → 调用 `add_srs_doc` 创建空文档 → 跳转 `/srs_docs/edit/:id`；编辑页加载时若正文无标准章节（如「1 介绍」），自动按 `standard_nodes.json` 初始化目录并静默保存；路由 `/srs_docs/add` 仍保留为兼容入口。
- 编辑：`/srs_docs/edit/:id`
- 只读：`/srs_docs/view/:id`（`pathname.includes("/view/")`）

## 6. 关键业务逻辑与规则

### 6.1 列表过滤与可见范围
- `version` 不以 `__deleted_srs__` 开头（软删占位）。
- **产品可见范围**按产品、按人配置，数据写在 `prod_user`：
  - 超级管理员（`user.id == 1` 或 `role_code=root`）与 DQA：可见全部产品的 SRS，并能给任意用户分配；无需给自己勾选。
  - 产品创建人：自动可见自己创建的产品（保存时强制写入，界面勾选禁用）。
  - 其他人（含 QA/RA/开发/测试等）：只看被勾选的产品；未勾选则 SRS 列表/详情/下拉均不可见。
- 列表无论是否指定 `product_id` 都按上述范围过滤；详情/增删改/导入/复制/导出同样校验。
- SRS 产品下拉调用 `list_product(for_srs=1)`。产品管理、产品图示和各文件列表对非超级管理员、非 DQA 使用同一勾选范围。
- 配置入口：系统配置 → 产品可见范围（`/srs_viewers`，超级管理员与 DQA 菜单可见）。SRS 列表页不提供该入口。

### 6.2 文件编号与 DHF
- 列表/详情展示时，若 `file_no` 为空，按产品 DHF 清单名称关键字「需求规格说明 / 需求规格」匹配 `code` 并随文档版本同步末尾版本段（仅展示，不强制回写数据库）。
- 新增/复制未手填 `file_no` 时，同样从 DHF 自动带入并落库。

### 6.3 复制（支持跨产品）
- **入口**：列表行「复制」弹窗，用产品选择器选「目标产品」，默认选中当前文档所属产品；版本号**自动生成、不允许手动填**。
- **版本规则**（`duplicate_srs_doc`）：
  - 目标=原产品（同产品复制）：`new_version(原文档版本)`，对版本末位数字 +1。
  - 目标=其它产品（跨产品复制）：查目标产品现有最大版本号后 `new_version()` 递增；若目标产品尚无任何文档，则沿用原文档版本号。
  - 兜底：循环检查目标产品下 `(product_id, version)` 是否已存在，撞号则继续 `new_version()` 递增直到可用（不再像旧逻辑那样撞号即报错）。
- 新文档 `product_id` = 目标产品；`file_no` 经 `__sync_file_no_version` 把末尾版本段同步为新版本。
- 复制节点树（`__update_nodes`）与需求数据（`srs_type` / `srs_req` / `srs_reqd` / `req_rcm`）；变更需求表 `type_code`（非 1/2）复制时重新生成 UUID，避免新旧文档共享标识。

### 6.3.1 封面（审批表）联动
- 封面审批表（`isApprovalTable`）首行：
  - 「文件版本」单元格随文档版本（A0/A1…）自动同步，**始终覆盖**手填值。
  - 「编制部门」单元格默认填「产品部」，**仅当为空时**填入，不覆盖手填值。
- 打开/刷新/导出时覆盖签署人（本文件属**产品文件**）：编制人 ← 参与人员「产品经理」；审核人、批准人 ← 参与人员「产品负责人」。不取开发部 TPM / 研发负责人。当前完整版本没有对应职能时，用同一产品名称下其它版本。
- 文件修订记录首行：修订人 ← 产品经理；批准人 ← 产品负责人。文档版本为 A1、A2 时保留 A0 行，并补上还没有的版本行；已有行的日期、说明、人员不改。文档版本改低时去掉高于当前版本的行，同一个版本只留一行。编审批日期、评审时间：A0 按文档名称取值，但不使用带 A1、A2 的单元格；A1、A2 及以后按文件名称和该版本号取值。文件修订记录每一行的修改日期按该行自己的版本号取值，A0 行不使用带 A1、A2 的时间线。
- 由 `SrsDocDetail.tsx` 监听 `Form.useWatch("version")` 与 `treeStructure` 变化驱动。

### 6.3.1.1 文件修订记录行数
- 「文件修订记录」表（`isChangeLogTable` / `isSrsChangeLogTableNode`）默认至少 5 行；已有数据超过 5 行则全部保留。
- 编辑页加载时若不足 5 行，自动补齐空行（`ensureChangeLogMinRows`）写入树，与画面展示一致。
- 标准模板 `standard_nodes.json` 预置 5 行空记录。

### 6.3.1.2 标准模板默认内容
- **1.3 术语、定义、首字母缩写和缩写**：标准模板预置两列表格（术语/缩写、定义），默认行 DICOM3.0、CT、B/S、GPU。编辑页加载时若该节表格为空，从模板补入并静默保存。该节自己已有术语表时，不再同时显示其下「导入表格」里的同一张表；打开编辑页时去掉这张重复表并静默保存。
- **其他需求列表**（`srs_req` type_code=2）：新增空模板、或打开时库内尚无其他需求且树上也没有其他需求表时，预置 SRS-RCN300-001～010（数据库要求 2.5、2.6 / 性能要求 2.7 / 基本要求 3 / 图像接收 4 / 图像存储 5 / 图像处理 6 / 图像显示 7 / 文档需求 9 / 法规符合需求 1.4 / 外部连接 参考法规和标准」章名、不另插同级章节；这一章写上法规符合需求这一行的需求编号。打开时去掉同级重复章节号。新增的其他需求若「对应的章节号」对不上现有目录、且没有同名章节，按需求编号顺序（代号数字、末位序号，与变更需求排序相同）在附件一之前补一级章节，标题用需求模块，并把这个章号写回「对应的章节号」。新增行先按需求编号在附件一之前补新章，不拿「对应的章节号」去改已有章节。已有章节（含「10 也排回图像接收前面，不留在附件一前），再把排列后的章号写回「对应的章节号」。增加或删除其他需求时，剩下的行如果需求编号和模块名都没变，保存时「对应的章节号」按左侧目录里该章显示的章节号重写。目录、需求规格说明、文件修订记录不参与这个编号。法规符合需求仍只写 1.4，数据库要求仍写 2.5、2.6，性能要求仍写 2.7。这两项只用第 2 章里的 ### 6.3.2 评审记录（附件一 评审结论）
- 封面/修订记录为前置 extraNav，不编号；**附件一 评审结论** 在目录末尾展示、不参与章节编号。
- 编辑页加载时若树中没有该节，自动补标准评审内容表 + 参评人员表并静默保存。保存后的表格就是导出内容，再次打开或导出不再用模板覆盖已改单元格。
- 评审内容取自《需求规格说明 附：评审记录》：风险/法规标准引用 5 项 + 需求撰写 10 项。评审结论勾选写作「☑ 通过    □ 存在问题」。
- 参评人员：研发总监/产品部经理、开发负责人/测试负责人、QA/RA、临床人员/产品经理、其他参会人员、批准人员签字/日期。
- 参评人员签字表与评审内容表一样，编辑页表格右侧有「编辑」「删除」。点「编辑」弹出表格编辑，确认后只写回签字表；点「删除」去掉签字表，评审内容表保留。查看页不显示这两个按钮。
- 按表格「人员角色」从该产品参与人员取姓名和签字，打开和导出都覆盖。匹配不到保留原值。测试负责人：角色含「测试」且不含「用户」的参与人员只有一人就用该人；多人时有宋月用宋月，没有宋月用孙家旭。已误写入姓名列的签名图会挪回签字列。批准人按研发负责人回填（签字图+日期）。「参评人员签字 / 评审时间 / 评审结论 / 批准人员签字」整行合并，「其他参会人员」后格合并为 `/`。

### 6.2.1 需求区节点（srs_reqs）必须存在
- 「2 软件整体架构要求」下 `ref_type=srs_reqs` 的需求区节点承载产品需求列表 / 其他需求列表预览及**「新增变更表格」入口**。
- Word 导入的文档只有「导入表格N」承载节点、没有该 ref 节点，会导致变更需求表入口消失；编辑页加载时（`ensureStandardTemplateChildren`）若缺失则按模板补回并静默保存。
- 其它模板章节（如 2.6，以及 2.3 系统结构图下的子章节）删除后仍不因打开页恢复，只有该需求区节点例外。2.3 子章节正文打开时不盖回模板。

### 6.3.1 第 7 章功能描述目录层级（固定规则）
- 功能描述挂在其他需求里设计类型为 NeoViewer 或功能设计的那一行对应的一级章节。先按这一行当前模块名找章；图像显示改名或删掉后，不再按「图像显示」四个字找，改按这一行的需求编号找仍带着该编号的一级章节。不用标题里写死的「7」。导入后标题号仍是 7、章名已是图像处理时，变更需求（含复用标准需求编号的行）保存、刷新后不挂到图像处理。打开页面用当次加载的其他需求找功能章，不用页面上还没写回的旧列表。同名模块也只在这个功能章里找，不回到标题号 7。
- 模块=二级章节、功能=三级章节、子功能=四级章节；只有模块时该需求就是二级，只有模块+功能时是三级。
- 保存产品需求表后按当前表重排该层级（`TreeStructure.tsx` 的 `normalizeReqChapterHierarchy`）：带需求编号的章节归位到「模块 → 功能 → 子功能」，缺的层级补建，移动后无内容的空章节删除，编号按需求编号顺序重新连续。
- 章节名按层级取字段，不按字段顺序下标：二级用模块、三级用功能、四级用子功能；因此新增、改名、删除行都不会把模块名写到功能或子功能章节上。
- 功能描述正文按需求稳定标识（`req_detail_key`）跟随节点移动，重排目录不丢内容。

### 6.3.3 目录加下一章
- 左侧目录里，一级到四级章节都有「＋」，点了在该章下加下一章。自动需求组、需求列表、评审、图片节点不加。
- 编辑页点开普通章节，正文下方有「添加正文」「上传图片」「添加表格」。添加正文新增一个输入框（正文 2、正文 3），不在正文 1 里换行；删空后这个框仍留着。上传图片写到本章；添加表格打开原有表格编辑。已有表格时正文框仍在，可以继续写。表上方的「添加正文」「上传图片」「添加表格」加在这张表上面；表下方同样有这三项，加在这张表下面。导出时表上正文在表前，表下正文在表后。运行环境、产品绑定的拓扑图/结构图、需求列表区不加这三项。查看页没有。导出时不写出正文框之间的占位标记。
- 进入编辑页或查看页时，左侧目录默认展开到二级：一级展开，能看到二级；二级及更深的章节默认收起，三级及以下要点箭头再展开。

### 6.4 删除（软删 vs 物删，重要）
- 若已绑定 `sds_doc`（存在 `sds_doc.srsdoc_id` 指向它）：**保留 `srs_doc` 主记录**，版本改为 `__deleted_srs__{id}_{stamp}`（软删）。
- 否则物理删除；同时清 `srs_req / srs_reqd / srs_type / srs_node / req_rcm`。

### 6.5 保存（update_srs_doc）后端联动（commit 之后顺序执行）
1. `__sync_srs_reqs_from_doc_tables` — 从树内**标准/其他需求表** upsert `srs_req`（**变更表不反向覆盖 DB**）。
2. `__upsert_imported_change_req_tables_from_tree` — 兜底迁移错分类变更行。
3. `__sync_srs_req_names_from_doc_nodes` — 同步需求名称到节点。
4. `__upsert_imported_srs_reqds` — 从第 7 章 KV 表 upsert `srs_reqd`。
5. `__fix_rcms` — 从节点文本/表格提取 RCM，重建 `req_rcm`。

### 6.6 保存策略
- 整树重建：删全部 `srs_node` 再 insert；`__reset_tree_node_ids` 清空前端旧 `n_id`（新节点 0）。
- 空 `content` 拒绝保存。

### 6.7 读取联动
- `get_srs_doc` 时若需同步变更表到树（`__sync_change_req_tables_from_db`），会重建节点并 commit。
- 2.2/2.3 图片：本章已有图（含导入原图）则保留；没有图时才从 `doc_file` 产品图表库 hydrate（`__hydrate_tree_product_doc_images`），只匹配当前 SRS 版本，不回退其它版本。编辑页导出以树上图片为准。编辑页物理拓扑图、系统结构图只有 A0 显示「重新上传」，上传后更新本章图片；A1 及以后不显示该按钮，也不能修改这两张图。编辑页物理拓扑图最大宽度 560px。产品图示仍只从需求 A0 获取这两张图。
- 2.1 软件总体描述：打开/换产品时用版本管理「总体描述」（`product.overall_desc`）覆盖该节正文；未填写则保留原文。
- 2.4 运行环境：打开/导出时用产品运行环境覆盖（单向，保存/Word 导入不回写运行环境）。编辑页切换产品后立即按新产品的运行环境覆盖，不必先保存再刷新。2.4 下已有子章节时，按标题把对应表写到该子章节的表格上，父章节不再同时保留这些表；没有子章节时，各表仍挂在 2.4 正文。文档内自动获取的正文与表格只读，章节标题可改、章节可删。文档内普通表格列宽按内容自适应（功能需求键值表首列仍固定 120px）。

## 7. 边界与特殊处理

- `(product_id, version)` 唯一。
- 软删后版本不可见但记录保留，用于维持 SDS 绑定。

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **删除的软删/物删分支**不可破坏：绑定 SDS 必须软删（保留主记录），否则 SDS 追溯断裂。
2. **保存后 5 步联动**是数据一致性关键，整树重建前提下不可遗漏任一步骤。
3. **`__sync_srs_reqs_from_doc_tables` 跳过变更表（type_code 非 1/2）**——这是变更表数据不被树覆盖的根本保证，详见 [25_变更需求表管理.md](./25_变更需求表管理.md)。
4. **整树重建**为既定策略，不可改为增量更新。
5. 列表过滤 `__deleted_srs__` 前缀不可移除。
6. **复制 `product_id` 为可选参数**，不传=同产品复制（行为同旧逻辑）；跨产品复制的版本规则（按目标产品最大版本递增、无则沿用、撞号兜底递增）与封面联动规则（文件版本始终覆盖、编制部门仅空填「产品部」）不可破坏。
