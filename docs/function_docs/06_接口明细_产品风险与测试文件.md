## 一、产品 RCM `api_prod_rcm.py`（prefix `/prod_rcm`）

### ProdRcmObj（继承 ProdRcmForm→RcmForm）
| 字段 | 类型 | 含义 |
|------|------|------|
| id | int | 产品-RCM 关联 ID |
| rcm_id | int | RCM 主表 ID |
| code / description / proof / note | str | RCM 主数据 |
| create_time | datetime | 创建时间 |
| srs_codes | List[str] | 需求编号列表 |
| srs_flag | int | 是否有需求追溯 |
| test_codes | List[str] | 测试用例编号/固定证据文案 |
| product_name / product_version | str | 产品信息 |

### 端点
| M | 路径 | 权限 | 入参 | 出参/错误 |
|---|------|------|------|-----------|
| POST | /prod_rcm/add_prod_rcms | prod_rcm_edit | Body `{prod_id, rcm_ids[]}` | 冲突忽略；`msg_err_db` |
| DELETE | /prod_rcm/delete_prod_rcms | prod_rcm_edit | Query `id`(逗号分隔多值) | data=null |
| GET | /prod_rcm/list_prod_rcm | prod_rcm_view | `prod_id`、分页 | `Page[ProdRcmObj]`；非 admin 无 prod_id 时按 UserProd 过滤 |
| GET | /prod_rcm/export_prod_rcms | prod_rcm_view | 同 list | xlsx 流 |

**无 update 接口**（改动需删后重加）。

## 八、图表文件 `api_doc_file*.py`

### 通用工具 `api_doc_file.py`（prefix `/doc_file`）
**POST `/doc_file/read_excel`**
- 权限：**无功能权限**（仅需登录）
- 入参：multipart File `file`
- 出参：`Resp[List[Table]]`（每 sheet 一个 Table：name, show_header, headers[code,name], rows, cells）
- 解析异常返回空列表

### 三类图表（topo / struct / flow）
路由前缀分别为 `/doc_file/img_topo`、`/doc_file/img_struct`、`/doc_file/img_flow`，端点形态相同，category 固定为对应值。

| 操作 | M | 路径 | 权限（topo/struct/flow） |
|------|---|------|--------------------------|
| 上传 | POST | `.../add_doc_file` | doc_file_*_edit |
| 删除 | DELETE | `.../delete_doc_file` | doc_file_*_edit |
| 更新 | POST | `.../update_doc_file` | doc_file_*_edit |
| 列表 | GET | `.../list_doc_file` | doc_file_*_view |
| 详情 | GET | `.../get_doc_file` | doc_file_*_view |

**add_doc_file（multipart）**：`product_id`(topo 可选/struct/flow 必填) + File `file`，内部构造 `DocFileForm(category=对应值, product_id)`。
**update_doc_file**：`id`(必填)、`product_id`（topo 可选；struct/flow `Form(...)` 必填）、File `file`。
**delete_doc_file**：Query `id`(int)。

**list_doc_file 入参**：`product_id`(默认0,>0过滤)、`file_name`(模糊)、`file_no`(API 有但 serv 未用)、`doc_version`(文件名 token 过滤+回填)、`product_name`(精确)、`product_version`(精确)、分页。

**DocFileObj 出参字段**（三类共用）：
| 字段 | 类型 | 含义 |
|------|------|------|
| id | int | ID |
| product_id | int | 产品ID |
| category | str | img_topo / img_struct / img_flow |
| file_name | str | 文件名 |
| file_size | int | 大小 |
| file_url | str | 存储路径 |
| create_time | datetime | 创建时间 |
| product_name / product_version / product_type_code | str | 产品信息 |
| srsdoc_version | str | 需求文档版本（列表未必赋值） |
| doc_version | str | 从文件名解析的文档版本 |

**列表回填来源**：img_topo 取 SRS 章节 2.2 / img_struct 取 SRS 2.3 / img_flow 取 **SDS** 节点（流程图关键词）。上传/更新后反向写文档节点 `img_url`。

## 十、开发环境维护说明 `api_dem_doc.py`（prefix `/dem_doc`）

### DemDocForm / DemDocObj
| 字段 | 类型 | 含义 |
|------|------|------|
| id | int | ID |
| product_id | int | 产品ID |
| version | str | 文档版本 |
| file_no | str | 文件编号（自动从 DHF「开发环境维护说明」获取） |
| change_log | str | 版本变更说明 |
| content | dict | 文档内容：`{desc, assets, checks}` |

DemDocObj 额外：`product_name, product_version, product_full_version, product_type_code, create_time`。

### content 结构
- `desc`：说明正文（固定模板，八节验证说明）
- `assets`：资产表（二维数组），表头「资产编码/设备信息/产品名称/完整版本」，资产编码从**开发设备清单**自动获取
- `checks`：各资产周检查表 `[{asset, kind(server/dev), rows}]`，日期行按产品时间线「开始开发~测试结束」每周一条（周一~周五）自动生成；每格 是/否 复选框

### 端点
| M | 路径 | 权限 | 入参 | 出参/错误 |
|---|------|------|------|-----------|
| POST | /add_dem_doc | dem_doc_edit | Body DemDocForm（id=null） | `msg_obj_exist`(同产品同版本)、`msg_err_db` |
| GET | /duplicate_dem_doc | dem_doc_edit | Query `id`、`product_id?`（跨产品复制逻辑同 deq_doc） | `msg_obj_null`、`msg_err_db` |
| POST | /update_dem_doc | dem_doc_edit | Body DemDocForm（需 id） | `msg_obj_null`、`msg_err_db` |
| DELETE | /delete_dem_doc | dem_doc_edit | Query `id`(单值 int) | |
| GET | /list_dem_doc | dem_doc_view | `product_id`(0不过滤)、`version`(模糊)、分页 | `Page[DemDocObj]`；非 admin 且 product_manager 按 create_user_id 过滤 |
| GET | /get_dem_doc | dem_doc_view | Query `id` | `msg_obj_null` |
| GET | /export_dem_doc | dem_doc_view | Query `id`(默认0) | docx 流（横版），标题「开发环境维护说明」 |

**自动填充逻辑**（get/list 时触发）：
1. 资产编码从「开发设备清单」按清单顺序取（去重），设备信息按编码前缀自动匹配（ISER→macOS，其它→Ubuntu）
2. 产品名称/完整版本填入资产表首个数据行
3. 检查人从产品参与人员取 TPM 签名章（无签名章用姓名）
4. 周检查表按时间线「开发开始~测试结束」生成周区间，默认勾选「是」（更新升级/日志错误默认「否」）
5. 已保存的勾选/问题/检查人数据保留，仅新增周区间时补充默认值

## 十二、测试环境维护记录 `api_tem_doc.py`（prefix `/tem_doc`）

### TemDocForm / TemDocObj
| 字段 | 类型 | 含义 |
|------|------|------|
| id | int | ID |
| product_id | int | 产品ID |
| version | str | 文档版本 |
| file_no | str | 文件编号（自动从 DHF「测试环境维护记录」获取） |
| change_log | str | 版本变更说明 |
| content | dict | 文档内容：`{desc, assets, checks}` |

TemDocObj 额外：`product_name, product_version, product_full_version, product_type_code, create_time`。

### content 结构
- `desc`：说明正文（固定模板，八节验证说明，与 dem_doc 相同）
- `assets`：资产表（二维数组），表头「资产编码/设备信息/产品名称/完整版本」，资产编码从**测试设备清单**自动获取
- `checks`：各资产周检查表 `[{asset, kind(server/dev), rows}]`，日期行按产品时间线「开始测试~测试结束」每周一条（周一~周五）自动生成；每格 是/否 复选框

### 端点
| M | 路径 | 权限 | 入参 | 出参/错误 |
|---|------|------|------|-----------|
| POST | /add_tem_doc | tem_doc_edit | Body TemDocForm（id=null） | `msg_obj_exist`(同产品同版本)、`msg_err_db` |
| GET | /duplicate_tem_doc | tem_doc_edit | Query `id`、`product_id?`（跨产品复制逻辑同 deq_doc） | `msg_obj_null`、`msg_err_db` |
| POST | /update_tem_doc | tem_doc_edit | Body TemDocForm（需 id） | `msg_obj_null`、`msg_err_db` |
| DELETE | /delete_tem_doc | tem_doc_edit | Query `id`(单值 int) | |
| GET | /list_tem_doc | tem_doc_view | `product_id`(0不过滤)、`version`(模糊)、分页 | `Page[TemDocObj]`；非 admin 且 product_manager 按 create_user_id 过滤 |
| GET | /get_tem_doc | tem_doc_view | Query `id` | `msg_obj_null` |
| GET | /export_tem_doc | tem_doc_view | Query `id`(默认0) | docx 流（横版），标题「测试环境维护记录」 |

**自动填充逻辑**（get/list 时触发）：
1. 资产编码从「测试设备清单」按清单顺序取（去重），用途含「共用」归类为 server，否则为 dev
2. 设备信息按编码前缀自动匹配（ISER→macOS，其它→Ubuntu）
3. 产品名称/完整版本填入资产表首个数据行
4. 检查人从产品参与人员取 TPM 签名章（无签名章用姓名）
5. 周检查表按时间线「开始测试~测试结束」生成周区间，默认勾选「是」（更新升级/日志错误默认「否」）
6. 已保存的勾选/问题/检查人数据保留，仅新增周区间时补充默认值
