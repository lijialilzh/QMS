# 软件详细设计（SDS）文档管理

## 1. 功能概述

SDS 文档的列表、新增、编辑、查看、复制、删除。SDS 通过 `srsdoc_id` 绑定一个 SRS 文档版本，采用「文档主表 + 节点树」存储。

---

## 2. 用户操作流程

### 2.1 列表（`/sds_docs`）
按产品、文档版本筛选 → 查看/编辑/复制/导出/删除 → 文件编号内联编辑 → 顶部 Word 导入、新增。

### 2.2 新增/编辑/只读
- 新增：列表里选产品、需求规格说明和版本后进入编辑页。目录还是空的，顶部提示「如需要标准模版，请点击初始化模版后进行编辑操作」。点「初始化模版」后提示消失并自动保存。已有章节的文档打开时不提示，也不再用标准模版覆盖。
- 编辑 `/sds_docs/edit/:id`：改元数据/变更说明/树 → `update_sds_doc`。文档内表格列宽按内容自适应。点表格「编辑」弹出的表格编辑框可改单元格，也可在预览表右侧按行插入空行或删除行（至少保留一行）；改「行数」再点「生成表格预览」仍可用。软件概要设计共用同一套弹框。运行环境等只读表仍不可进弹框增删行。
- 只读 `/sds_docs/view/:id`：`isReadOnly=true`，禁用编辑与同步。
- 打开或导出时，「1.4 术语」表格从所绑定需求规格说明的「1.3 术语、定义、首字母缩写和缩写」整表带出（术语/缩写、定义）。需求规格说明该节有内容才覆盖；没有则保留详细设计原文。章节下原来的「导入表格」术语副本（含英文表头 Terms/Abbreviations）不再显示。

| `components/SdsTraceSection.tsx` | 追溯区按钮 |

## 4. 后端接口

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| GET | `/sds_doc/list_sds_doc` | product_id, version, 分页 | Page[SdsDocObj] |
| GET | `/sds_doc/get_sds_doc` | id | SdsDocObj（含 content） |
| POST | `/sds_doc/add_sds_doc` | SdsDocForm（含 content 树） | {id} |
| POST | `/sds_doc/update_sds_doc` | SdsDocForm | 成功/失败 |
| DELETE | `/sds_doc/delete_sds_doc` | id | 级联删 reqd/trace/node |
| GET | `/sds_doc/duplicate_sds_doc` | id | SdsDocForm{id} |
| POST | `/sds_doc/update_sds_doc_file_no` | Form: id, file_no | 成功/失败 |

**SdsDocForm 字段**：id, srsdoc_id, version, file_no, change_log, content[], n_id
**权限**：查看 `sds_doc_view`；编辑/导入/同步 `sds_doc_edit`。

## 5. 数据库表

`sds_doc`（唯一 `(srsdoc_id, version)`）、`sds_node`、`sds_reqd`、`sds_trace`、`logic`。

## 6. 关键业务逻辑与规则

### 6.1 创建时自动初始化
- `SdsReqd`：`SrsReq.type_code != "2"` 的全部需求。
- `SdsTrace`：`SrsReq.type_code != "reqd"` 的全部需求，默认 `sds_code = SRS→SDS`，`chapter` 来自层级。

### 6.2 保存策略
- 编辑页点「初始化模版」后自动保存，不必再手动点保存。新增文档保存成功后进入该文档的编辑页。产品或需求规格说明没选时不保存，并提示先选。
- 删全部 `sds_node` 后整树重建（`_update_nodes`），`n_id` 递增分配。
- **非 Word 导入树**保存前：`_ensure_trace_nodes_from_saved_locations`、`_refresh_trace_table_nodes`、`__normalize_heading_hierarchy`、`_dedupe_requirement_nodes`。
- **Word 导入树**（`preserve_word_structure` / `_is_word_imported_doc`）：跳过上述重排，保留 Word 结构。

### 6.3 复制 / 删除
- 复制：`new_version()` 递增；复制节点树 + `sds_reqd` + `sds_trace`；`(srsdoc_id, version)` 不可冲突。
- 删除：级联删 `sds_reqd / sds_trace / sds_node / sds_doc`。

### 6.4 评审记录签字表
- 「附件一 评审结论」的参评人员签字表，编辑页表格右侧有「编辑」「删除」。点「编辑」弹出表格编辑，确认后只写回签字表；点「删除」去掉签字表，评审内容表保留。查看页不显示这两个按钮。

### 6.5 目录加下一章
- 左侧目录里，一级到四级章节都有「＋」，点了在该章下加下一章。软件概要设计用同一套目录，规则相同。需求区、追溯区、自动图片节点不加。
- 编辑页点开普通章节，正文下方有「添加正文」「上传图片」「添加表格」。添加正文在本章正文末尾另起一行；上传图片写到本章；添加表格打开原有表格编辑。软件概要设计同一套。物理拓扑图、系统结构图也可以加这三项：自动获取的那张图留在标题旁，右侧有「重新上传」，新图替换这一张，不能删除这张图。用「上传图片」另加的图仍另起一条图题放在正文下，表格也显示在本章。「1.4 术语」的表仍从需求规格说明自动带出，排在本章最前；新加的正文、图片、表格都排在这张术语表下面，不插到表的上方，也不改这张自动表。「1.2 范围」、运行环境，以及设计列表、追溯表这些章不加。查看页没有。
- 进入编辑页或查看页时，左侧目录默认展开到二级：一级展开，能看到二级；二级及更深的章节默认收起，三级及以下要点箭头再展开。软件概要设计相同。
- 详细设计点全局保存后，重新加载目录与打开页面、刷新相同，不再额外跑需求补章剪枝。避免把「5.7.1 数据上传接口」这类接口章节当成过期需求删掉，也不要因此改乱章节号和标题。

### 6.6 封面日期与章节图片
- 编制人、审核人、批准人日期、生效日期，以及文件修订记录的修改日期，取该产品时间线里部门为产品开发部、输出包含「软件详细设计」的最晚日期，格式 `yyyy.MM.dd`。不使用「算法方案详细设计」。已有错误日期会被覆盖；签名、修订人、批准人已有内容不改。软件概要设计同样：时间线输出含「软件概要设计」或「概要设计」的最晚一天写入编审批日期、生效日期与修订首行修改日期，封面和文件修订记录用同一天，模板/导入的错误旧日期打开与导出都会覆盖；签名、修订人、批准人仍只填空不覆盖。评审记录里的「评审时间」和「批准人员签字/日期」也用这一天，已有的旧日期同样覆盖。文件修订记录在文档版本从 A0 改为 A1，或新建 A1、A2 时，保留已有版本行，并补上从 A0 到当前版本还没有的行；A0 的修订说明仍是「首次发布」，已有行的日期和人员不改。需求规格说明同样。
- 父章节不重复显示子章节自己的图。例如「2 系统结构与功能模块」不显示「2.1 物理拓扑图」的图；「6.6 登录」不显示「6.6.1 用户登录」下导入的图。
- 章节正文末尾按回车可以换行继续写，末尾空行保留。
- 「1.2 范围」正文从当前产品基本信息和产品版本自动写入，不能手改。产品名称、产品型号、版本号（完整版本）、适用范围分别取产品上的对应字段。没有产品型号时不写「产品型号」这一行。软件概要设计的范围章同样。打开页面或更换产品后整段覆盖。适用范围里的「1）」「2.」等编号不再拿来截断这一章，避免和整段写入来回覆盖，初始化模版后页面卡住、正文无法修改。
- 法规符合性需求、外部连接、文档需求的设计编号尾号仍是 `300-009`、`300-010`、`300-008`。字母跟着同一套 300 编号里其他章节：其他需求代号是 ACN 时，章节编号是 `SDS-ACN300-009`、`SDS-ACN300-010`，与 2.4 追溯表一致；整套仍是 RCN 时才用 `SDS-RCN300-009`、`SDS-RCN300-010`。编号只出现在章节标题旁的编号框，正文不再重复写同一行编号。打开页面时按这个编号改掉章节上仍写着旧字母的编号。
- 需求规格说明里新增的其他需求，若详细设计还没有同名章节或对应设计编号，打开详细设计时补一级章节，不自动生成同名子章节。非预置编号（如 `300-011`）补在附件一之前。预置 `300-004`～`300-010`（字母是 RCN 还是 ACN 都算）对应固定模块章节：`300-004` DataProcessing（图像接收）、`300-005` RePACS、`300-006` DLServer、`300-007` NeoViewer、`300-008` 文档需求、`300-009` 法规符合性需求、`300-010` 外部连接。这些模块章节如果已经被删掉，再把需求加回来时按固定模块名补回这一级章节，插在后一个模块之前；法规符合不另插同名章。`300-001`～`300-003` 不另建章。多条按需求编号顺序（代号数字、末位序号）排列。设计编号把需求编号的 SRS 换成 SDS。已有章节不重排、不改号、不改标题、不清正文。打开时去掉与本章同名、正文仍是空的「总体描述/功能/程序逻辑」占位子章节。编号框里的临时编号（`TMP-SRS`）不保留，按对应需求补回 SDS 编号。附件一、封面、目录上的编号不算已有章节。
- 「外部连接」下「接口」的各接口详情（如 8.1.1 目标物导入接口）编号框为空时自动生成接口编号，规则与「5.7 接口」列表一致：由当前外部连接设计编号得到前缀，字母跟着该编号。例如 `SDS-ACN300-010` 得到 `SDS-IF00-ACN3010-`，再按接口章节顺序补三位序号（001、002…）。编号框里已经有编号时，打开、保存、导出都保留手改结果，不再覆盖。编辑页可以改这个编号。
- 「图 N ……程序逻辑」显示在正文「程序逻辑」一节下面，并显示图题。按钮放在图的右侧：还没有图时写「上传图」，已有图时写「重新上传」。新图写回该图题节点，不改章节正文。新加入、正文还是「无」的需求同样使用这套结构，上传后补上「图 N 章节名程序逻辑」。内嵌表显示表名。导入后没有表名、或只有「导入表格N」这种占位名的，表名为空。章节标题本身就是表名的（以「表」结尾，或字段表标题），打开时把这个名字写入表格名称，章节标题不动。表名可以和章节名相同，输入相同不会被清空。编辑态表名、图题可直接修改。表名写在表格自己的名称上，不改章节标题；改表名不会在章节后面补字。章节标题框只改章节。图题仍写回图题节点。运行环境等只读表仍不可改。软件概要设计共用同一套编辑组件，规则相同。
- 同一章节直接挂的多张「图 N」都显示，并带图题。例如「5.2 功能」同时显示「图 9」和「图 10」。子章节自己的图仍不出现在父章节。
- 查看页展示与编辑页同一章的内容。章节标题旁已有的设计编号（SDS-RCN、SDS-IF 接口编号）以文本显示，不能改。章节下内嵌的导入表格，含「5.7 接口」和概要设计「3 接口设计」的接口列表，查看页同样展示。查看页没有编辑、删除、上传按钮。
- 「2.4 设计与需求追溯表」标题旁不显示「设计需求追溯」按钮，追溯表直接在这一章。未同步时编辑页仍可点「获取SRS追溯」。
- 详细设计「5.7 接口」和概要设计「3 接口设计」的接口表，编辑页与查看页都按当前页面宽度排开。接口设计编号、接口名称、接口 URL、接口参数、备注都在这一页里显示完整，长链接和参数换行，不再把右侧列裁出页面。单元格内容左对齐、顶对齐，行高随文字，不再居中撑高。接口设计编号仍保持一行。
- 「5.7 接口」的接口列表（接口设计编号 / 接口名称 / 接口URL）只在该章展示。打开 5.7.1 等单个接口章节时不重复这张表。软件概要设计同样：接口总表只在「3 接口设计」展示，打开「3.1 用户接口」「3.2 外部接口」「3.3 内部接口」时不重复这张表。「3.3 内部接口」按详细设计的方式，一个接口一章（3.3.1 数据上传接口、3.3.2 创建处理任务接口，以此类推），正文从该章原来挤在一起的说明里切开。已经按接口拆开的不再重拆。单个接口章（详细设计 5.7.x）编辑与查看顺序为「图 →（1）输入 →（2）输出 → 表」：图在输入上方可上传/重新上传；输入与输出分开展示。导出时接口详情的图写在「（1）输入项」下面、输出前面，不再排到输出后面。删掉「（2）输出」前面的正文后，这一段输入框仍留着，可以再写，输出段不并进这一框。Name/Value 等表在输入输出下方，可新增/编辑/删除。概要设计接口内容从详细设计同步带出，不单独改布局。导出 Word 时「接口设计编号」单行显示。「接口名称」略收窄，八个字以内仍一行，更长的名称换行。「接口 URL」列加宽，链接按正常行宽换行，不再挤成十几个字一行。参数、备注列保持能读。
- 数据结构里「××表：」这类数据表，导出时表题写在表的前面，表紧跟表题。连续多张表时，表题不落到下一张表或下一章前面。详细设计与概要设计导出时，「表 N」这类表题居中，与原 Word 模版一致。库表名（如 `alembic_version: 版本管理`）左对齐，与表格左缘对齐。
- 软件概要设计导出使用同一套版式：封面标题「软件概要设计」上方、标题与表格之间留出与详细设计相同的空行。编制人取参与人员 TPM，审核人、批准人取研发负责人，有签名图导出签名，没有则导出姓名。页眉文件编号右对齐（与详细设计相同）。封面「生效日期」后面的空格合并成一格。文件修订记录之后另起一页写「目录」，列出正文章节标题，末行是「附件一 评审结论」。章节标题用正文里已有的章号（如「1 引言」），去掉 Word Heading 自带列表编号，避免导出成「.1 引言」。章节图按正文区缩小，图题在图下；父章节不再把子图题已经有的图再导一遍，运行环境这类章节也不补体系结构图。数据表表题写在表前：正文里的「××表：」或「字段名: 说明」，以及表格自带的表名，都紧挨着对应的表。不把「导入表格」写成章节；接口表的设计编号、接口名称单行显示，URL 列加宽。下载文件名与详细设计对称：`{文件编号}软件概要设计.docx`（中间不加分隔符），不用 `hld_doc_时间戳`。
- 软件概要设计的「附件一 评审结论」只在目录末尾单独展示，不写进「5.3 系统维护设计」。打开时：5.3 正文末尾若粘有「附件一 评审结论」去掉；5.3 下误挂的评审内容表、参评人员签字表也不显示并从该章拿掉。导出时正文同样跳过这些误挂内容，文末单独分页写出居中标题「附件一 评审结论」及评审表；评审结论勾选用 Wingdings「☑ 通过    □ 存在问题」，与详细设计一致。

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **创建时自动初始化 sds_reqd/sds_trace** 的类型过滤（reqd 排除 trace、type_code=2 排除 reqd）不可改。
2. **Word 导入树与手工树的不同保存路径**（保留结构 vs 重排）不可混淆。
3. **整树重建 + 级联删除**为既定策略，不可改为增量。
4. SRS 软删时 SDS 仍显示、srs_version 置空的兼容逻辑不可移除。
5. 图片 URL 去 `?_v=` 防止参数无限叠加，不可去除。
