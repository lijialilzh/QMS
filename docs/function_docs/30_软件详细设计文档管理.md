# 软件详细设计（SDS）文档管理

## 1. 功能概述

SDS 文档的列表、新增、编辑、查看、复制、删除。SDS 通过 `srsdoc_id` 绑定一个 SRS 文档版本，并冗余记录 `product_id` 直接关联产品（用于解绑/软删 SRS 后仍能定位产品），采用「文档主表 + 节点树」存储。

---

## 2. 用户操作流程

### 2.1 列表（`/sds_docs`）
按产品、文档版本筛选 → 查看/编辑/复制（弹窗选目标产品，支持跨产品复制）/导出/删除 → 文件编号内联编辑 → 顶部 Word 导入、**新增（弹窗选产品/需求规格说明/版本，创建后进入编辑页）**。

### 2.2 新增/编辑/只读
- 新增：列表页点击「新增」→ 弹窗选择产品、绑定 SRS、SDS 版本等 → 调用 `add_sds_doc` 创建空文档 → 跳转 `/sds_docs/edit/:id`；编辑页加载时若正文无标准章节（如「1. 介绍」），自动按 `standard_nodes.json` 初始化目录并静默保存，再按需从 SRS 补全功能设计；路由 `/sds_docs/add` 仍保留为兼容入口。
- 编辑 `/sds_docs/edit/:id`：改元数据/变更说明/树 → `update_sds_doc`。
- 只读 `/sds_docs/view/:id`：`isReadOnly=true`，禁用编辑与同步。

---

## 3. 前端实现

| 路径 | 说明 |
|------|------|
| `pages/sds_doc/SdsDocs.tsx` | 列表、导入、复制、导出、文件编号 |
| `pages/sds_doc/SdsDocDetail.tsx` | 详情/树编辑、同步追溯、设计/追溯弹框、保存 |
| `components/TreeStructure.tsx` | 树渲染与节点 CRUD |
| `components/EditableTableGenerator.tsx` | 表格编辑弹框 |
| `components/SdsTraceSection.tsx` | 追溯区按钮 |
| `standard_nodes.json` | 标准目录模板（含 2.4 追溯表、6.6 功能设计等） |

> `SdsReqds.tsx`、`SdsTraces.tsx` 为独立列表页实现，**未注册路由**；实际入口在 `SdsDocDetail` 弹框与树节点按钮。

---

## 4. 后端接口

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| GET | `/sds_doc/list_sds_doc` | product_id, version, 分页 | Page[SdsDocObj] |
| GET | `/sds_doc/get_sds_doc` | id | SdsDocObj（含 content） |
| POST | `/sds_doc/add_sds_doc` | SdsDocForm（含 content 树） | {id} |
| POST | `/sds_doc/update_sds_doc` | SdsDocForm | 成功/失败 |
| DELETE | `/sds_doc/delete_sds_doc` | id | 级联删 reqd/trace/node |
| GET | `/sds_doc/duplicate_sds_doc` | id, product_id?（目标产品；为空或同原产品=同产品复制，指定其它产品=跨产品复制） | SdsDocForm{id} |
| POST | `/sds_doc/update_sds_doc_file_no` | Form: id, file_no | 成功/失败 |

**SdsDocForm 字段**：id, srsdoc_id, product_id, version, file_no, change_log, content[], n_id
**权限**：查看 `sds_doc_view`；编辑/导入/同步 `sds_doc_edit`。

---

## 5. 数据库表

`sds_doc`（唯一 `(srsdoc_id, version)`；含 `product_id` 字段直接关联产品）、`sds_node`、`sds_reqd`、`sds_trace`、`logic`。

---

## 6. 关键业务逻辑与规则

### 6.1 创建时自动初始化
- `SdsReqd`：`SrsReq.type_code != "2"` 的全部需求。
- `SdsTrace`：`SrsReq.type_code != "reqd"` 的全部需求，默认 `sds_code = SRS→SDS`，`chapter` 来自层级。
- **文件编号**：未手填时从产品 DHF 按名称关键字「软件详细设计 / 详细设计」匹配 `code`，并随版本同步末尾版本段；列表/详情空编号时同样只读回填展示。

### 6.2 保存策略
- 删全部 `sds_node` 后整树重建（`_update_nodes`），`n_id` 递增分配。
- **非 Word 导入树**保存前：`_ensure_trace_nodes_from_saved_locations`、`_refresh_trace_table_nodes`、`__normalize_heading_hierarchy`、`_dedupe_requirement_nodes`。
- **Word 导入树**（`preserve_word_structure` / `_is_word_imported_doc`）：跳过上述重排，保留 Word 结构。

### 6.3 复制 / 删除
- **复制入口**：列表行「复制」弹窗，选「目标产品」（默认当前产品）；版本号自动生成、不允许手动填。
- **同产品复制**：`new_version(原版本)` 递增；`srsdoc_id`、`product_id` 沿用原值。
- **跨产品复制**（目标≠原产品）：
  - `srsdoc_id`：自动绑定**目标产品下最新有效 SRS 文档**（按 `create_time` 倒序，排除 `__deleted_srs__` 前缀）；若目标产品无 SRS 则置 0（不绑定）。
  - `product_id`：= 目标产品。
  - 版本：查目标产品现有最大 SDS 版本后 `new_version()` 递增；目标产品无文档则沿用原版本。
- **唯一性兜底**：循环检查 `(srsdoc_id, version)` 与 `(product_id, version)` 是否已存在，撞号则继续 `new_version()` 递增直到可用（防止解绑/软删 SRS 后产生重复孤儿记录）。
- 复制节点树（`_update_nodes`）+ `sds_reqd` + `sds_trace`。
- **取真实关联值**：`srsdoc_id` / `product_id` 直接从 `sds_doc` 行（`srcrow`）读取，不依赖 `get_sds_doc` 的展示层值（后者在 SRS 软删时会把 `srsdoc_id` 置 0）。
- 删除：级联删 `sds_reqd / sds_trace / sds_node / sds_doc`。

### 6.3.1 封面联动 & 文件修订记录
- 封面表格（`isCoverTable`）首行：「文件版本」随文档版本自动同步（**始终覆盖**）；「编制部门」默认「研发部」（**仅空时填**）。
- 「文件修订记录」表（`isChangeLogTable`）默认 5 行；编辑已有文档时若不足 5 行，自动补齐空行（`ensureChangeLogMinRows`），不影响已有数据。
- 由 `SdsDocDetail.tsx` 监听文档版本与 `treeStructure` 变化驱动。

### 6.4 可见范围 & SRS 绑定
- 非 admin 按 `prod_user` 过滤。
- SRS 已删（版本前缀 `__deleted_srs__`）：列表仍显示 SDS，但 `srs_version` 置空。
- 导入 SRS 绑定优先级：指定 `srsdoc_id` → 同 `version` → 最新 SRS。

---

## 7. 边界与特殊处理

- 未绑定 SRS（`srsdoc_id=0`）：前端警告并限制操作。
- 加载后若静默同步导致树变化，会**静默** `update_sds_doc` 持久化。
- 图片 URL 保存时去掉 `?_v=` 缓存参数。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **创建时自动初始化 sds_reqd/sds_trace** 的类型过滤（reqd 排除 trace、type_code=2 排除 reqd）不可改。
2. **Word 导入树与手工树的不同保存路径**（保留结构 vs 重排）不可混淆。
3. **整树重建 + 级联删除**为既定策略，不可改为增量。
4. SRS 软删时 SDS 仍显示、srs_version 置空的兼容逻辑不可移除。
5. 图片 URL 去 `?_v=` 防止参数无限叠加，不可去除。
6. **复制时必须从 `sds_doc` 行读取真实 `srsdoc_id` / `product_id`**（不可用 `get_sds_doc` 展示值），并做 `(srsdoc_id, version)` + `(product_id, version)` 双重唯一校验 + 撞号兜底递增——这是防止重复孤儿 SDS 的根本保证。
7. 跨产品复制「自动绑定目标产品最新有效 SRS、无则置 0」与封面/修订记录规则（文件版本始终覆盖、编制部门仅空填、修订记录最少 5 行）不可破坏。
