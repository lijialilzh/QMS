# 软件详细设计（SDS）文档管理

## 1. 功能概述

SDS 文档的列表、新增、编辑、查看、复制、删除。SDS 通过 `srsdoc_id` 绑定一个 SRS 文档版本，采用「文档主表 + 节点树」存储。

---

## 2. 用户操作流程

### 2.1 列表（`/sds_docs`）
按产品、文档版本筛选 → 查看/编辑/复制/导出/删除 → 文件编号内联编辑 → 顶部 Word 导入、新增。

### 2.2 新增/编辑/只读
- 新增 `/sds_docs/add`：选产品、SRS 版本、SDS 版本、文件编号 → 加载模板或手工编辑树 → `add_sds_doc`。
- 编辑 `/sds_docs/edit/:id`：改元数据/变更说明/树 → `update_sds_doc`。文档内表格列宽按内容自适应。点表格「编辑」弹出的表格编辑框可改单元格，也可在预览表右侧按行插入空行或删除行（至少保留一行）；改「行数」再点「生成表格预览」仍可用。软件概要设计共用同一套弹框。运行环境等只读表仍不可进弹框增删行。
- 只读 `/sds_docs/view/:id`：`isReadOnly=true`，禁用编辑与同步。
- 打开或导出时，「1.4 术语」表格从所绑定需求规格说明的「1.3 术语、定义、首字母缩写和缩写」整表带出（术语/缩写、定义）。需求规格说明该节有内容才覆盖；没有则保留详细设计原文。章节下原来的「导入表格」术语副本（含英文表头 Terms/Abbreviations）不再显示。

## 4. 后端接口

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| GET | `/sds_doc/list_sds_doc` | product_id, version, 分页 | Page[SdsDocObj] |
| GET | `/sds_doc/get_sds_doc` | id | SdsDocObj（含 content） |
| POST | `/sds_doc/add_sds_doc` | SdsDocForm（含 content 树） | {id} |
| POST | `/sds_doc/update_sds_doc` | SdsDocForm | 成功/失败 |
| DELETE | `/sds_doc/delete_sds_doc` | id | 级联删 reqd/trace/node |
| GET | `/sds_doc/duplicate_sds_doc` | id | SdsDocForm{id} |
| POST | `/sds_doc/update_sds_doc_file_no` | Form: id, file_no | 成功/失败 |

**SdsDocForm 字段**：id, srsdoc_id, version, file_no, change_log, content[], n_id
**权限**：查看 `sds_doc_view`；编辑/导入/同步 `sds_doc_edit`。

## 5. 数据库表

`sds_doc`（唯一 `(srsdoc_id, version)`）、`sds_node`、`sds_reqd`、`sds_trace`、`logic`。

## 6. 关键业务逻辑与规则

### 6.1 创建时自动初始化
- `SdsReqd`：`SrsReq.type_code != "2"` 的全部需求。
- `SdsTrace`：`SrsReq.type_code != "reqd"` 的全部需求，默认 `sds_code = SRS→SDS`，`chapter` 来自层级。

### 6.2 保存策略
- 删全部 `sds_node` 后整树重建（`_update_nodes`），`n_id` 递增分配。
- **非 Word 导入树**保存前：`_ensure_trace_nodes_from_saved_locations`、`_refresh_trace_table_nodes`、`__normalize_heading_hierarchy`、`_dedupe_requirement_nodes`。
- **Word 导入树**（`preserve_word_structure` / `_is_word_imported_doc`）：跳过上述重排，保留 Word 结构。

### 6.3 复制 / 删除
- 复制：`new_version()` 递增；复制节点树 + `sds_reqd` + `sds_trace`；`(srsdoc_id, version)` 不可冲突。
- 删除：级联删 `sds_reqd / sds_trace / sds_node / sds_doc`。

### 6.4 评审记录签字表
- 「附件一 评审结论」的参评人员签字表，编辑页表格右侧有「编辑」「删除」。点「编辑」弹出表格编辑，确认后只写回签字表；点「删除」去掉签字表，评审内容表保留。查看页不显示这两个按钮。

### 6.5 目录加下一章
- 左侧目录里，一级到四级章节都有「＋」，点了在该章下加下一章。软件概要设计用同一套目录，规则相同。需求区、追溯区、自动图片节点不加。
- 进入编辑页或查看页时，左侧目录默认展开到二级：一级展开，能看到二级；二级及更深的章节默认收起，三级及以下要点箭头再展开。软件概要设计相同。
- 详细设计点全局保存后，重新加载目录与打开页面、刷新相同，不再额外跑需求补章剪枝。避免把「5.7.1 数据上传接口」这类接口章节当成过期需求删掉，也不要因此改乱章节号和标题。

### 6.6 封面日期与章节图片
- 编制人、审核人、批准人日期、生效日期，以及文件修订记录的修改日期，取该产品时间线里部门为产品开发部、输出包含「软件详细设计」的最晚日期，格式 `yyyy.MM.dd`。不使用「算法方案详细设计」。已有错误日期会被覆盖；签名、修订人、批准人已有内容不改。软件概要设计同样：时间线输出含「软件概要设计」或「概要设计」的最晚一天写入编审批日期、生效日期与修订首行修改日期，模板/导入的错误旧日期打开与导出都会覆盖；签名、修订人、批准人仍只填空不覆盖。
- 父章节不重复显示子章节自己的图。例如「2 系统结构与功能模块」不显示「2.1 物理拓扑图」的图；「6.6 登录」不显示「6.6.1 用户登录」下导入的图。
- 章节正文末尾按回车可以换行继续写，末尾空行保留。
- 「1.2 范围」正文从当前产品基本信息和产品版本自动写入，不能手改。产品名称、产品型号、版本号（完整版本）、适用范围分别取产品上的对应字段。打开页面或更换产品后覆盖。
- 法规符合性需求的设计编号是 `SDS-RCN300-009`，外部连接是 `SDS-RCN300-010`，与 2.4 追溯表一致。编号只出现在章节标题旁的编号框，正文不再重复写同一行编号。打开页面时按这个编号改掉章节上错位的编号。
- 「图 N ……程序逻辑」显示在正文「程序逻辑」一节下面，并显示图题。按钮放在图的右侧：还没有图时写「上传图」，已有图时写「重新上传」。新图写回该图题节点，不改章节正文。新加入、正文还是「无」的需求同样使用这套结构，上传后补上「图 N 章节名程序逻辑」。内嵌表显示表名。编辑态表名、图题可直接修改并写回对应节点（含目录名）；运行环境等只读表仍不可改。软件概要设计共用同一套编辑组件，规则相同。
- 同一章节直接挂的多张「图 N」都显示，并带图题。例如「5.2 功能」同时显示「图 9」和「图 10」。子章节自己的图仍不出现在父章节。
- 「5.7 接口」的接口列表（接口设计编号 / 接口名称 / 接口URL）只在该章展示。打开 5.7.1 等单个接口章节时不重复这张表。软件概要设计同样：接口总表只在「3 接口设计」展示，打开「3.1 用户接口」「3.2 外部接口」「3.3 内部接口」时不重复这张表。「3.3 内部接口」按详细设计的方式，一个接口一章（3.3.1 数据上传接口、3.3.2 创建处理任务接口，以此类推），正文从该章原来挤在一起的说明里切开。已经按接口拆开的不再重拆。单个接口章（详细设计 5.7.x）编辑与查看顺序为「图 →（1）输入 →（2）输出 → 表」：图在输入上方可上传/重新上传；输入与输出分开展示；Name/Value 等表在输入输出下方，可新增/编辑/删除。概要设计接口内容从详细设计同步带出，不单独改布局。导出 Word 时「接口设计编号」单行显示。「接口名称」略收窄，八个字以内仍一行，更长的名称换行。「接口 URL」列加宽，链接按正常行宽换行，不再挤成十几个字一行。参数、备注列保持能读。
- 数据结构里「××表：」这类数据表，导出时表题写在表的前面，表紧跟表题。连续多张表时，表题不落到下一张表或下一章前面。详细设计与概要设计导出时，表题（如「表 4 网络要求」「××表：」）均居中，与原 Word 模版一致。
- 软件概要设计导出使用同一套版式：封面标题「软件概要设计」上方、标题与表格之间留出与详细设计相同的空行。编制人取参与人员 TPM，审核人、批准人取研发负责人，有签名图导出签名，没有则导出姓名。页眉文件编号右对齐（与详细设计相同）。章节标题用正文里已有的章号（如「1 引言」），去掉 Word Heading 自带列表编号，避免导出成「.1 引言」。章节图按正文区缩小，图题在图下；父章节不再把子图题已经有的图再导一遍，运行环境这类章节也不补体系结构图。数据表表题写在表前：正文里的「××表：」或「字段名: 说明」，以及表格自带的表名，都紧挨着对应的表。不把「导入表格」写成章节；接口表的设计编号、接口名称单行显示，URL 列加宽。下载文件名与详细设计对称：`{文件编号}软件概要设计.docx`（中间不加分隔符），不用 `hld_doc_时间戳`。
- 软件概要设计的「附件一 评审结论」只在目录末尾单独展示，不写进「5.3 系统维护设计」。打开时：5.3 正文末尾若粘有「附件一 评审结论」去掉；5.3 下误挂的评审内容表、参评人员签字表也不显示并从该章拿掉。导出时正文同样跳过这些误挂内容，文末单独分页写出居中标题「附件一 评审结论」及评审表；评审结论勾选用 Wingdings「☑ 通过    □ 存在问题」，与详细设计一致。
- 软件概要设计「2.2 产品功能」不按物理拓扑图或体系结构图去产品图示取图。图题节点上已有的图保留；章节没有图时才用对应产品图示补。导出 Word 带封面「软件概要设计」和「文件修订记录」两页，树上没有这两节时按文档版本补出。
- 软件概要设计「2.4 子模块结构」下图 3～图 6（DP / DLServer / RePACS / NeoViewer）用初始化模版内嵌图；模版章号为 2.4.1～2.4.4。打开已有文档时若这些图题节点无图，按同名图题从标准模版回填，打开后静默保存则导出也有图。
- 软件概要设计新增、编辑时手选关联的详细设计版本，不再按概要设计自己的文档版本去对同名版本。「从详细设计同步」、打开时的「1.4 术语」都读这份选中的详细设计。详细设计该节有内容才覆盖术语；没有则保留概要设计原文。章节下原来的「导入表格」术语副本不再显示。未选择详细设计时不同步接口、库表和术语。同步接口时按接口名把详细设计对应章节的正文写入 3.3.N，该章节下的参数表、Name/Value 表一并挂到同一章；再同步时用详细设计的表覆盖原导入表。详细设计没有该接口时保留概要设计原文，不把已经写好的接口章节清空重拆。编辑页已有文档时，点「从详细设计同步」成功后自动 `update_hld_doc` 落库，刷新不必再同步；新增尚未落库时仍只改本地树，需点全局保存。点「从详细设计同步」成功后，写入的「3.3.x 内部接口」正文与参数表、以及「4.1.x」下同步来的库表字段表，与「2.3 运行环境」相同：正文与表格只读（不可改表名、不可改单元格、不可增删行列或删表）；章节标题可改、章节可删。未同步前这些章节仍可手改。编辑页打开时若文档尚未从详细设计同步过接口/库表（含新增空文档初始化标准目录时尚未点同步），顶部提示「尚未从详细设计同步接口与库表，请点击「从详细设计同步」」；已点过同步并落库后不提示；查看页不提示。新增打开时只初始化标准目录、不自动静默同步。
- 软件概要设计「2.3 运行环境」：打开/导出时用产品运行环境覆盖；文档内自动获取的正文与表格只读（不可改单元格、不可增删行列或删表），章节标题可改、章节可删。
- 软件概要设计「2.2 产品功能」若正文仍是导入时挤在一起的「1.1.1. 功能模块定义、2.2.2. DataProcessing、3.3.3. DLServer」整段，打开或导出时拆成 2.2.1 功能模块定义、2.2.2 DataProcessing（DP）、2.2.3 DLServer、2.2.4 RePACS、2.2.5 NeoViewer、2.2.6 系统性能。图 2 系统结构图仍放在 2.2.1 和 2.2.2 之间。已经有 2.2.1 至 2.2.6 时不改。
- 软件概要设计「4.1 逻辑结构设计要点」下成批的字段表，按详细设计的方式挂到目录（原 Word 模版只有 4.1，没有单独的 4.2 物理结构）：库 1 的表放在「4.1.1 Postgresql库1数据库：」下，库 2 的表放在「4.1.2 库2数据库：」下，目录项就是表名。点开表名只显示这一张表。「4.1」正文只留结构说明，不再把表名和全部表格堆在这一章。已经按表名挂好的不再重挂。历史上误写成「4.2 物理结构设计要点」的库 2 打开时迁回 4.1.2。「4.1.2 标记信息」去掉，同一套字段表不要挂两遍。打开、新增初始化模版、导出使用同一套目录：接口按 3.3.1、3.3.2 分章写出，总表只在「3 接口设计」；字段表不写成章节标题，表名紧挨着对应的表。
- 导出 Word：封面与文件修订记录紧挨着分页，中间不留空白页。章节图按页面正文区等比缩小，宽不超过约七成页宽、高不超过约三分之一页高，整图都显示，不放大、不裁切。2.4 追溯表导出行序与编辑页相同，按需求编号 RCN300、RCN301、RCN306 往后排；需求编号、设计编号单行显示，不换行。

### 6.7 可见范围 & SRS 绑定
- 非 admin 按 `prod_user` 过滤。
- SRS 已删（版本前缀 `__deleted_srs__`）：列表仍显示 SDS，但 `srs_version` 置空。
- 导入 SRS 绑定优先级：指定 `srsdoc_id` → 同 `version` → 最新 SRS。

## 7. 边界与特殊处理

- 未绑定 SRS（`srsdoc_id=0`）：前端警告并限制操作。
- 加载后若静默同步导致树变化，会**静默** `update_sds_doc` 持久化。
- 图片 URL 保存时去掉 `?_v=` 缓存参数。

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **创建时自动初始化 sds_reqd/sds_trace** 的类型过滤（reqd 排除 trace、type_code=2 排除 reqd）不可改。
2. **Word 导入树与手工树的不同保存路径**（保留结构 vs 重排）不可混淆。
3. **整树重建 + 级联删除**为既定策略，不可改为增量。
4. SRS 软删时 SDS 仍显示、srs_version 置空的兼容逻辑不可移除。
5. 图片 URL 去 `?_v=` 防止参数无限叠加，不可去除。
