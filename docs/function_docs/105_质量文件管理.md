# 质量文件

独立导航模块，不放进产品文件、开发文件或测试文件。四个子菜单共用一张 `qa_doc`，用 `kind` 区分。

| 菜单 | kind | 来源模板 |
| --- | --- | --- |
| 设计开发输出评审 | output_review | 评审记录（设计开发输出） |
| 成品检验规程 | inspect_spec | 成品检验规程 |
| 成品检验记录 | inspect_record | 成品检验记录 |
| 变更评估及关闭表 | change_close | 变更评估及关闭表 |

1. 同一产品、同一 kind、同一文档版本只能有一份。编辑页可以切换产品和完整版本；切换后按新产品重新获取自动内容并保存。目标产品在同一文档版本下已经有这份文件时，不能切换过去。新增和编辑页不填写文件编号。文件编号在列表单击修改；没填时导出用产品 DHF 里同名文件的编号。设计开发输出评审在 DHF 里的名称是「评审记录（设计开发输出）」，按这个名称取编号。导出文件名是「文件编号 文件名称.docx」。成品检验记录、变更评估及关闭表的编辑页按产品验收记录的单页展示，标题居中，不用左侧章节目录。单元格样式与产品验收记录一致：边框 #9aa4b0，标签格灰底左对齐，表头灰底居中加粗，填写格白底；自动带出的格子显示为文字。成品检验记录四列宽度为检验项目 14%、检验标准 48%、检验结果 18%、判定 20%。表格按 Word 模版合并单元格：成品检验记录是信息区、检验项目、检验标准、检验结果、判定；变更评估及关闭表是基本信息、评审人、变更内容描述和后面的评估、行动、关闭。勾选可直接点，合格和不合格、是和否互斥，样例勾选和人员不预填。打开或导出时，还是旧两列表的换成这套表。产品名称、完整版本、发布版本、型号，以及成品检验记录的检验依据和安装包 MD5，按已有规则自动带出。变更评估及关闭表的评审人按参与人员带出，只填空格：申请人取产品经理，申请部门负责人取产品负责人，研发部负责人取研发负责人，质量部负责人和 QA 取角色含 QA 的姓名（DQA 不算），生产部负责人取角色含「生产」的姓名，两名研发工程师取开发人员或研发工程师的前两人，批准人取管理者代表或管代。评审时间和批准时间取时间线输出含「变更评估」的日期，格式 yyyy.MM.dd。变更关闭里变更负责人、质量部复核、产品部负责人、管理者代表的签字日期只取时间线输出含「变更评估关闭」的日期，取到就覆盖这四格。没有这条输出时不改已填内容。变更评估及关闭表的 ECR号按产品名称从 ECR 台账带出：去掉空格后名称相同，或产品名称与台账「变更后产品名称」互为开头，取名称最长的编号；同一名称有多条时按台账顺序用顿号连接。没匹配到不改已填内容，该格只读。当前版本没有该人员或时间线时，用同一产品名称下其它版本。来源为空不覆盖已填内容。变更评估及关闭表里仍是「文件号：」的格子，按该活动或 DMR 文件名称匹配本产品 DHF，写成「文件号：文件名称」，不写文件编号，多个用顿号隔开。当前版本没有 DHF 时，用同一产品名称下其它版本。没匹配到不改已填内容；已经手改过的保留。成品检验记录的生产日期取时间线输出含「设计转换」的日期，格式 yyyy.MM.dd。当前版本没有时间线时，用同一产品名称下其它版本的时间线。来源为空时不覆盖已填内容，该格只读。成品检验记录的备注取版本管理里的备注。检验人员取参与人员中角色含 QA 的姓名（DQA 不算），日期取时间线输出含「成品检验记录」的一天，没有则用含「成品检验规程」的日期，格式 yyyy.MM.dd，写在「检验人员/日期」后面。当前完整版本没有安装维护手册、备注、QA 或对应时间线时，用同一产品名称下其它版本。来源为空时不覆盖已填内容。这些格子只读。设计开发输出评审按《评审记录（设计开发输出）》生成，编辑页与评审记录相同：只读合并表，点右侧「编辑」改表格。第一张表头是「评审内容 / 评审结论」，评审结论横跨后两列；相同类别的首列纵向合并，每一项一行，评审结论用勾选框，通过和存在问题互斥，通过默认勾选，可直接改，末行是评审结论。第二张是参评人员签字，人员角色与评审记录相同，姓名从该产品参与人员获取，样例姓名和签字日期不预填。评审时间取时间线输出含「设计开发输出」的日期，优先含「评审」的一天，格式 yyyy.MM.dd。当前版本没有时间线时，用同一产品名称下其它版本的时间线。文档版本为 A0 时不使用带 A1、A2 的单元格；A1 及以后要在同一单元格里同时有文档名和该版本号。取到日期就写入评审时间，没取到不改已有日期。打开或导出时，还是旧两列表的换成这套表；已经按评审记录保存的保留手改，仍把默认空框改成勾选通过，并写入评审时间。导出只出标题和这两张表，合并方式与评审记录一致。成品检验规程仍用章节编辑。
2. 新建时带出对应模板。成品检验规程「依据文件」写在正文输入框，不放表格。默认一行，不编号、不换行，用顿号分隔：《医疗器械生产质量管理规范》、《医疗器械生产质量管理规范附录：独立软件》、产品技术要求、用户说明书、采购要求及产品BOM、安装维护手册。正文已有内容时不覆盖，并去掉「序号 / 文件名称」表。产品型号从版本管理读取，多个型号用顿号拆开。型号表按型号各一行，描述和 UDI 留空，由本页填写。
3. 成品检验规程封面编审批、生效日期，以及文件修订记录第一行的修改日期，取时间线输出含「成品检验规程」的日期，格式 yyyy.MM.dd。当前版本没有时间线时，用同一产品名称下其它版本的时间线。编制人和修订人取参与人员中角色含 QA 的姓名（DQA 不算 QA）；审核人、批准人，以及修订记录的批准人，取角色含「管理者代表」或「管代」的姓名。当前版本没有该职能时，用同一产品名称其它版本的参与人员。来源为空时不覆盖已填内容。上述姓名和日期只读。成品检验规程、成品检验记录在打开和导出时自动覆盖：产品名称、完整版本、发布版本（版本管理）。成品检验规程再覆盖检验条件里的前 4 张表（产品运行环境整表：服务器硬件、服务器软件、用户端、网络），这 4 张表只读。说明书「文件名称」取该产品 DHF 里名称含「用户说明书」的编号，写成「编号 用户说明书.pdf」；「说明书发布日期」取时间线输出含「用户说明书」的最晚一天，格式 YYYY-MM-DD。来源为空时不覆盖已填内容。上述自动格子只读。成品检验规程「软件技术要求」表格 2 取该产品最新产品技术要求的第 2 章（封面、附录不编号，第 2 个正文章）下的最末级小节，有下级的分组标题（如「2.1 功能」「2.1.1 模块名」）不进入表格：测试目的写「编号 标题」，是否检验默认「是」。判定标准按模板写「安装包MD5码：」加该产品安装维护手册中的 MD5（同文档版本优先，否则最新一份；先取 MD5 附件表，再取「确认安装包信息」表，最后取 content.md5_value）。当前完整版本的安装维护手册没有 MD5 时，用同一产品名称下其它版本里最新一份；都没有时只保留「安装包MD5码：」，不填模板样例码。检验方法按模板写 MD5 校验说明。这两列各行相同，页面和导出合并成一格。没有技术要求或第 2 章没有最末级小节时，表格 2 保持原样。条款、判定标准、检验方法只读，不能增删行；是否检验可改，再次打开按条款保留。
4. 模板里的检验条件以外的检查项、评审项、变更检查项保留，勾选格默认是 □。设计开发输出评审的「通过」默认勾选。样例产品的勾选结果、签字日期不预填。安装包 MD5 不使用模板样例码，按第 3 条从安装维护手册获取。
5. 其余正文和表格可以改。表格可以加行。自动获取的运行环境表、软件技术要求表格 2 的条款、判定标准和检验方法不能改；表格 2 不能增删行。封面编制人、审核人、批准人、生效日期，以及修订记录的修改日期、修订人、批准人不能改。
6. 导出 Word 按产品开发计划分页：封面（标题居中、签署表）、文件修订记录、目录、正文各自另起一页。封面不显示页码，之后从「第 1 页」起。页眉右对齐文件编号。正文用标题样式并编号，打开 Word 后目录可更新页码。表格通栏、有边框，表头加粗；封面生效日期横向合并；软件技术要求表格 2 的判定标准、检验方法纵向合并。文件名是「文件编号 文档名称.docx」。
