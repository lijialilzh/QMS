## 1. 功能概述

按**产品（版本）**维护《产品开发计划》文档（DHF 之一），提供「新增 / 编辑 / 导出 Word / 复制 / 删除」操作，基本范式与「网络安全风险管理报告」一致。

- 一个产品下可有多个版本文档，`(product_id, version)` 唯一。
- 采用**目录树模型**（对齐风险管理/网络安全）：`content.sections` 为可递归的章节树，**用户可自助任意增删/重命名章节、加子章节、编辑正文与表格**，不需改代码即可扩展章节。
- **章节编号自动生成**：标题只存名称（不含编号），编号按目录树层级与位置自动计算（正文顶级 1/2/3、子级 1.1、孙级 1.1.1），增删章节后自动重排；封面、文件修订记录为前置项不编号。导出 Word 时用自动编号并套 `Heading N` 样式（目录域可自动识别）。
- 新增时预填标准模板默认树（封面、文件修订记录、1~6 章；人员/设备/里程碑作为预置「通用表格章节」，含模板行，可自由加行/列）。

## 2. 前置依赖 & 关联模块

- 【只读 / 禁止修改】：`/product/*` 产品模块。

## 3. 完整执行流程（分步细化）

1. 列表页按产品 / 文档版本筛选，分页展示；「文件编号」支持列内单击编辑、失焦保存。
2. 新增：弹窗选择产品 + 文档版本（默认 A0）+ 文件编号 + 变更说明 → `add_pdp_doc` 以模板默认值建档 → 跳转 `/pdp_docs/edit/:id`。
3. 编辑（`/pdp_docs/edit/:id`）：详情页左侧为**目录树**（点击切换当前章节、＋加子章节、🗑删除、底部＋顶级章节），右侧编辑当前章节的「标题 / 正文 / 通用表格」（表格可＋行 ＋列 / 删行 删列 / 删除此表 / 添加表格）；点「保存」整体 `update_pdp_doc`（仅提交 `content`，前端会剥离临时 `_key`）。
4. 查看（`/pdp_docs/view/:id`）：与编辑同页，所有输入禁用为只读，仅可导出。
5. 导出：`export_pdp_doc` **遍历 sections 树**渲染 Word——封面（`ref_type=cover` 居中大标题）与修订记录（`ref_type=revision`）作为前置不编号，随后插入目录域 + 分页，再按树层级用 `Heading N` 样式渲染正文章节（标题文本由用户维护、含编号）、正文多行、各表格。
6. 复制：`duplicate_pdp_doc` 在同产品/跨产品上自动递增版本号，深拷贝 `content`。
7. 删除：`delete_pdp_doc` 物理删除该文档记录。

---

## 4. 核心规则 & 判定条件

- `add_pdp_doc`：`(product_id, version)` 已存在则报 `msg_obj_exist`；`content` 经 `__normalize_content` 补齐模板默认结构。
- `update_pdp_doc`：仅按 `exclude_none` 更新传入字段；`content` 落库前规范化。
- `duplicate_pdp_doc`：同产品在原版本号递增；跨产品按目标产品现有最大版本递增；冲突则继续递增。
- 列表权限收敛：`product_manager` 角色（非超管）仅能看到自己创建产品下的文档。
- 权限：写操作 `pdp_doc_edit`，读操作 `pdp_doc_view`；默认授予 root/dqa/qa 及 `product_manager`。

## 5. 数据结构说明

表 `pdp_doc`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| product_id | Integer NOT NULL | 产品 ID |
| version | String(64) NOT NULL | 文档版本，`(product_id, version)` 唯一 |
| file_no | String(128) | 文件编号 |
| change_log | String(512) | 版本变更说明 |
| content | JSON | 整份文档内容（见下） |

`content` JSON 结构（目录树）：

```
content = { "sections": [ node, ... ] }
node = {
  "title":    str,            # 章节名称（不含编号，编号自动生成）
  "body":     str,            # 正文（多行，\n 分段）
  "tables":   [ table, ... ], # 通用表格列表，table 为二维字符串数组，首行视为表头
  "children": [ node, ... ],  # 子章节（可递归）
  "ref_type": str|omit        # 仅导出/编号用：cover=封面(居中不编号)，revision=修订记录(不编号)
}
```

- 后端 `__normalize_content` 递归规范化：非法 `content` 回落 `DEFAULT_PDP_CONTENT`；每个节点补齐 title/body/tables/children，表格单元转字符串。
- 前端加载时给每个节点附加临时 `_key`（用于定位编辑），保存前 `stripKeys` 剥离。
- 模板默认树见后端常量 `DEFAULT_PDP_CONTENT`（封面表、修订表头、1~6 章；设备资源 10 行、里程碑标准阶段行、相关计划写入正文）。

## 6. 异常场景 & 兜底逻辑

- 新增版本重复：返回 `msg_obj_exist`。
- 详情不存在：`get_pdp_doc` 返回 `msg_obj_null`；导出空 id 返回空白 docx。
- `content` 非字典：`__normalize_content` 回落为模板默认结构，列表键非数组时回落空数组。
- 保存 / 导出失败：前端 `message.error` 提示；数据库异常后端 `rollback` 返回 `msg_err_db`。

---

## 7. 功能约束 & 修改红线

1. 章节为数据驱动的目录树，用户可自助增删；导出仅依赖 `ref_type`（cover/revision）做前置不编号处理，其余一律按树层级渲染。
2. `update` 不接受修改 `id`；不允许跨产品迁移 `product_id`（复制走 `duplicate`）。
3. 默认值仅用于新增预填，不强制覆盖已保存数据。
4. 与「产品参与人员」「设备资源」模块相互独立：本文档内人员/设备为文档自带副本，便于按版本归档（不实时联动那两个模块）。
