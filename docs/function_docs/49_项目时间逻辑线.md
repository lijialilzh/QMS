## 1. 功能概述

按**产品（版本）**维护「时间 × 部门」的体系时间逻辑线矩阵：行=日期（年/月/日），列=固定部门，单元格=该部门当天「输出结果」（多行文本）。另支持「年份分组行」「阶段里程碑行」。支持按模板 Excel 导入、导出。数据维度为产品版本级（`prod_id`，与产品 RCM/HAZ/CST 一致）。

固定部门列（常量 `TIMELINE_DEPTS`）：产品部 / 模型部 / 数据部 / 产品开发部-开发 / 产品开发部-测试 / 质量部 / 三级通用技术文件。

## 3. 完整执行流程（分步细化）

1. 进入列表页 → 拉取产品下拉（`list_product`），默认「全部」。列表按「已有时间线的产品」一行一条展示（产品名称 / 完整版本 / 发布版本 / 型号 / 行数 / 查看·编辑·删除），交互对齐产品 DHF。
2. 顶部「新增」弹窗选产品后进入 `/project_timeline/edit/:prodId`；「查看」进入 `/project_timeline/view/:prodId`（只读，隐藏导入与批量删除）。详情页 `list_timeline(prod_id)` 返回 `{ depts: 固定部门, rows: [行(含 cells: {部门:输出结果})] }`，行按 `sort_order, id` 升序。列表「删除」二次确认后 `list_timeline(prod_id)` 再 `delete_timeline_row` 逗号拼接全部行 id。
3. 编辑（点击单元格 → 失焦实时保存）：
   - 日期行的 年/月/日：`Input`，保存调 `update_timeline_row`；
   - 部门单元格（输出结果）：`Input.TextArea` 多行，保存调 `update_timeline_cell`（按 `(row_id, dept)` upsert）；保存后仅本地更新该行 `cells`；
   - 里程碑/年份行：整行合并的单元格内编辑 `milestone_text`，保存调 `update_timeline_row`。
4. 新增行（仅操作列「+」，无顶部「新增行」按钮）：
   - 表格为空：操作列「+」→ `add_timeline_row(prod_id, row_type='date')`，`sort_order` 未传时后端取当前产品最大值 +1（追加首行）。
   - 行尾「+」→ `add_timeline_row(prod_id, row_type='date', sort_order=当前行+1)`，把该行之后的 `sort_order` 整体 +1，在中间插入空日期行（年/月继承当前行）。
5. 删除行：行尾「删除」→ 二次确认 → `delete_timeline_row(id)`，级联删除该行所有单元格，成功提示「已删除」。
6. 导入模板（`import_timeline`，multipart：prod_id + replace + file）：
   - 解析首个 sheet；第 1 行第 4 列起为部门名，仅映射到固定部门列；
   - 从第 3 行起逐行解析：A/B/C = 年/月/日；
     - 分支①（有月/日或任一部门有内容）→ **日期行**，并对年/月做**向下填充**（继承上一非空年/月），各部门非空内容写入 `project_timeline_cell`；
     - 分支②（仅 A 列有值）→ A 含「年」且长度≤8 视为**年份行**，否则视为**阶段里程碑行**，文本存 `milestone_text`；
   - `replace=true`（默认）先清空该产品原有行与单元格再导入。
7. 导出（`export_timeline`）：openpyxl 从零构建工作簿，表头「时间(合并 A1:C1)+各部门」「年/月/日 + 输出结果×部门」，日期行写 年/月/日 + 各部门输出，里程碑/年份行整行合并写文本。

---

## 4. 核心规则 & 判定条件

- `row_type`：`date`（日期行）/ `year`（年份分组行）/ `milestone`（阶段里程碑行）。
- `update_timeline_cell`：`row_id` 与 `dept` 必填，且 `dept` 必须属于固定部门列，否则参数错误；存在则更新、不存在则插入（upsert）。
- `update_timeline_row`：按 `id` 定位，不更新 `id`/`prod_id`；只写传入的非空字段（改年/月/日时不得清空 `row_type` / `sort_order`）。
- `delete_timeline_row`：先删 `project_timeline_cell` 再删 `project_timeline_row`。
- 导入年/月向下填充仅作用于日期行；里程碑/年份行不参与填充。
- 权限：写 `project_timeline_edit`，读 `project_timeline_view`；默认角色「产品经理」读写。

---

## 5. 数据结构说明

表 `project_timeline_row`：`id, prod_id(NOT NULL,index), year(16), month(16), day(16), row_type(16 默认 date), milestone_text(256), sort_order(默认0)`。

表 `project_timeline_cell`：`id, row_id(NOT NULL,index), dept(64,NOT NULL), output_result(TEXT)`，唯一约束 `(row_id, dept)`，随行级联删除。

`list_timeline` 返回行对象附加 `cells`（`{部门: 输出结果}` 透视映射）。详见 [01_数据库表结构.md](./01_数据库表结构.md)。

## 6. 异常场景 & 兜底逻辑

- 列表默认「全部」：只列出已有时间线行的产品；导入/导出在详情页且必须有具体 `prodId`。查看页隐藏导入与批量删除。详情页表格空时点「+」新增该产品首行。部门输出结果纵向合并仅限同一产品（详情页单产品）。
- 导入文件行数 < 3 或解析异常：返回参数错误 / `msg_err_db`，并 `rollback`。
- 导入会覆盖原数据：前端二次确认弹窗后才执行。
- 单元格/行保存成功：`message.success`（「保存成功」/「已新增一行」/「已插入一行」）。失败：`message.error` 并保持编辑态可重试。
- 删除行：二次确认「确认要删除吗？」；确认后删除成功提示「已删除」。

---

## 7. 功能约束 & 修改红线

1. 部门列为固定 7 列（`TIMELINE_DEPTS`），单元格只存「输出结果」单值；如需调整列须前后端常量同步，不可仅改一端。
2. `update_timeline_cell` 的 `dept` 白名单校验不可移除（防止脏列）。
3. 导入 `replace` 语义为「整项目覆盖」，删除顺序「先单元格后行」不可颠倒。
4. 行/单元格不可跨产品迁移（不更新 `prod_id`）。
5. 导出表头结构（时间合并 + 部门 + 输出结果）须与模板一致，便于复用。
