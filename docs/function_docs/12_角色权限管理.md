# 角色权限管理

## 1. 功能概述

维护角色及其权限范围。系统内置固定角色及基线权限；自定义角色可增量授权。权限按模块 view/edit 粒度划分。

---

## 2. 用户操作流程

按角色名查询 → 列表（含关联用户数）→「权限范围」编辑模块级权限 → 批量删除自定义角色（`root` 不可勾选）。

> 前端 `Roles.tsx` **无「新增角色」按钮**（仅刷新与删除）；`add_role` 接口存在但 UI 未暴露。

---

## 3. 前端实现

- 页面：`pages/syscfg/Roles.tsx`
- 组件：`RoleDlg`。权限卡片由 `pages/navMenu.tsx` 的一级菜单自动生成，名称和顺序跟随左侧导航；在导航里新增、删除或调整一级菜单后，角色权限对话框和用户权限预览一起变，不用再维护第二份名单。

---

## 4. 后端接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/role/add_role` | role_edit | name 唯一；code=uuid |
| POST | `/role/update_role` | role_edit | 固定角色不可改名；权限 = 基线 ∪ 提交 |
| DELETE | `/role/delete_role` | role_edit | code；固定角色不可删；有用户不可删 |
| GET | `/role/list_role` | role_view \| user_view | 含 user_count |
| GET | `/role/get_role` | role_view | perm_tree, role_perms, all_perms, fixed_base_perms |

---

## 5. 数据库表

- `role`：id, code(唯一), name(唯一)
- `role_perm`：role_code, perm_code（联合唯一）
- `perm`：code, p_code, priority, name

---

## 6. 权限模型（`obj/tobj_role.py`）

- **固定角色**：root, dqa, qa, ra, product_manager, developer, tester, model_staff（模型人员）, data_staff（数据人员）（`get_fixed_role_codes()`）。
- **基线权限**：`get_default_role_perm_codes()`；更新固定角色时 `role_perms = base ∪ 提交`，**不可剥离基线**。
- **接口校验**：`@try_log(perm=...)`，列表为 OR。
- **菜单**：前端依据 `*_view`；按钮级 `*_edit` 多数仅后端校验（前端不一定隐藏按钮）。产品版本列表、需求规格说明列表按 `product_edit` / `srs_doc_edit` 隐藏写操作。

预置角色权限范围（代码定义，可增量）：
- product_manager：产品管理（可编辑）、产品文件管理、产品图示、风险追溯管理（产品HAZ/RCM/THREAT）。不查看基础数据总表。
- 角色权限卡片自动跟随左侧一级导航（当前含产品图示、数据质控）。用户管理的权限预览用同一套判断：某个一级菜单下只要有一项属于该菜单的权限，卡片就勾选，预览里也列出这个模块。`project_member` 不算系统配置。勾选「通用配置」后，非 root/dqa/qa 的导航仍只显示「版本命名规则」。「基础数据」中 HAZ管理、RCM管理、THREAT管理仅超级管理员 root、DQA、QA 的导航可见。合规医院列表对 root、DQA、QA 以及模型人员、数据人员可见；模型人员、数据人员只读，不能新增、编辑、删除、导入。其它角色即使有合规医院权限，预览和权限卡片也不算作拥有基础数据。数据质控与数据文件共用 `data_doc` 权限，两个勾选同时生效。
- developer：产品管理（仅查看）、产品文件管理、开发测试文件管理、产品图示、网络安全管理、风险追溯管理
- tester：同 developer
- ra：同 developer
- model_staff / data_staff：同一基线。产品管理-基本信息仅查看（含 DHF）；需求规格说明仅查看；模型文件、数据文件、数据统计、数据自查可读写；一键导出/一键打印仅模型和数据文件。合规医院列表只读。其它未授权模块不可见。
- root/dqa/qa：全部 perm

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. **固定角色不可改名 / 不可删 / 基线权限不可剥**——这是权限安全底线。
2. **有用户关联的角色不可删**。
3. 权限 perm code 命名（`{module}_view` / `{module}_edit`）是前端菜单与后端校验共用，**新增模块须同时补 perm 定义与菜单映射**。
4. `role_perms = 基线 ∪ 提交` 的合并规则不可改为「全量覆盖」，否则会丢失基线权限。
