## 1. 功能概述

按**产品（版本）**维护《4. 设备资源》标准模板：一张固定行结构的表（设备及用途 / 设备名称 / 数量），作为交付文档「设备资源」章节来源。每个产品一条记录，行的「设备及用途」标签固定，预填模板默认值。软件/工具类行可改「设备名称」，「数量」按名称中顿号/逗号分隔的项数自动计算；开发/测试/生产/检验设备可改「设备名称」，「数量」按该产品参与人员中对应职能的人数计算（只读）。

- 数据维度：产品版本级（`prod_id`，与运行环境/产品参与人员/时间线一致），一个产品唯一一条记录（`prod_id` 唯一）。
- 表格条目以 JSON 数组存于单一 `items` 字段：`[{"use":设备及用途, "name":设备名称, "qty":数量}]`。

## 2. 前置依赖 & 关联模块

- 依赖：产品主数据（`/product/list_product`）提供「产品名称 + 完整版本」级联下拉（`ProductVersionSelect`）；开发/测试/生产/检验设备数量只读自 [48_项目人员管理.md](./48_项目人员管理.md) `list_project_member`。
- 页面：`pages/syscfg/ProdDeviceRes.tsx`（自绘 HTML 表格还原模板版式，样式复用 `ProdRuntimeEnv.less`）；API `api/ApiProdDeviceRes.ts`。
- 菜单：「产品管理 → 设备资源」`/prod_device_res`，权限 `prod_device_view`。
- 【只读 / 禁止修改】：`/product/*` 产品模块。

## 3. 完整执行流程（分步细化）

1. 进入页面 → 拉取产品下拉（`list_product`），用产品名称 + 完整版本级联选择，默认「全部」。未选具体产品时按产品并行 `get_prod_device_res`，以汇总表展示产品名称、完整版本、设备及用途、设备名称、数量（只读）。
2. 选择具体产品（版本）→ `get_prod_device_res(prod_id)`：
   - 已有记录：返回该产品已保存的设备资源（解析 `items` JSON）；
   - 未建记录：返回**模板默认值**条目（带 `prod_id`，不落库），供前端预填。
3. 编辑（点击「设备名称」单元格直接编辑、失焦实时保存）：
   - 「设备及用途」为固定标签列，不可编辑；
   - 操作系统 / 开发语言 / 数据库 / 开发工具 / 测试工具 / 配置管理工具：「数量」= 设备名称按 `、` / `，` / `,` 拆分后的非空项数，打开与改名称时重算，该列只读；
   - 开发设备 / 测试设备 / 生产设备 / 检验设备：「数量」= 该产品参与人员中职能分别含「开发」「测试」「生产」「检验或 QA」且姓名非空的行数（一人一行），打开时重算，该列只读；无匹配人则为 0；不按「计算机」项数计；
   - 失焦时若整体条目较上次保存快照有变化 → 调 `save_prod_device_res`（按 `prod_id` upsert，首次保存才创建记录）；无变化不发请求；打开时若自动数量与已存不一致则重算并保存；
   - 保存成功后更新本地快照并 `message` 提示成功。

---

## 4. 核心规则 & 判定条件

- `get_prod_device_res`：`prod_id` 必填；无记录时回落模板默认值。
- `save_prod_device_res`：`prod_id` 必填，按 `prod_id` upsert（存在则更新、不存在则新建）；整表条目以 JSON 覆盖写入 `items`。
- 一个产品唯一一条记录（`prod_id` 列 `UNIQUE`）。
- 权限：写操作 `prod_device_edit`，读操作 `prod_device_view`；默认与「产品版本管理」权限同步（有 `product_view` 者可查看、有 `product_edit` 者可编辑）。

## 5. 数据结构说明

表 `prod_device_res`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| prod_id | Integer NOT NULL, UNIQUE, index | 产品 ID（产品版本），一对一 |
| items | TEXT | 设备资源条目 JSON 数组，元素 `{use, name, qty}` |

模板默认值（后端常量 `DEFAULT_DEVICE_ITEMS`，与标准模板一致）：

| 设备及用途 | 设备名称 | 数量 |
|------------|----------|------|
| 操作系统 | Ubuntu24.04、Windows 10 | 2 |
| 开发语言 | Python、JavaScript、less、html | 4 |
| 数据库 | PostgreSQL | 1 |
| 开发工具 | VS Code | 1 |
| 测试工具 | Chrome、JMeter、Nmap | 3 |
| 配置管理工具 | Jira、GitLab、NextCloud、Nas | 4 |
| 开发设备 | 计算机 | 7 |
| 测试设备 | 计算机 | 2 |
| 生产设备 | 计算机 | 1 |
| 检验设备 | 计算机 | 1 |

## 6. 异常场景 & 兜底逻辑

- 未选具体产品（默认「全部」）：展示全部产品设备资源汇总表，不进入可编辑表单。
- 失焦无改动：不触发保存。
- 保存失败：`message.error` 提示后端 msg，本地快照不更新。
- `items` JSON 解析失败：后端按空数组兜底；数据库异常 `rollback` 并返回 `msg_err_db`。

---

## 7. 功能约束 & 修改红线

1. 模板行结构固定（设备及用途标签固定），不在此模块做动态增删行。软件/工具类只改名称、数量由名称项数算出；开发/测试/生产/检验设备只改名称、数量由参与人员对应职能人数算出。
2. `save` 不接受修改 `id`、不允许跨产品迁移（按 `prod_id` upsert）。
3. 默认值仅用于「未建记录」预填，不强制覆盖已保存数据。
4. 一个产品仅一条记录（`prod_id` 唯一）。
