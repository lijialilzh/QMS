# 数据库表结构

> 共 33 张表。除 `session` 外均继承基类 `Model`。所有关联均为**逻辑外键**（Integer 字段引用），代码中**未声明 SQLAlchemy ForeignKey**。

---

## 0. 公共基类字段（除 session 外所有表）

所有继承 `Model`（`__abstract__=True`）的表均含以下 3 列：

| 字段 | 类型 | 约束 | 含义 |
|------|------|------|------|
| id | Integer | PK，自增，index | 主键 |
| create_time | DateTime | nullable，默认 `datetime.now` | 创建时间 |
| update_time | DateTime | nullable，默认 `datetime.now` | 更新时间 |

**通用规则：**
- 未显式声明 `nullable=False` 的列，SQLAlchemy 默认 **nullable=True**（主键除外）。
- 全库**未发现独立 `Index(...)`**；索引仅来自：主键 `id`（index=True）、列级 `unique=True`、`UniqueConstraint`，以及 `session.uid`（index=True）。
- 复合唯一均由 `UniqueConstraint` 实现（下文各表标注）。
- `String` 无长度的仅 `prod_cst.prev_accept / cur_accept / rcm_codes`（DB 方言默认长度）。

## 9. ER 关系总图

```
project 1──N product 1──N srs_doc 1──N srs_node
                              ├──N srs_req 1──1 srs_reqd
                              │         └──N req_rcm ──N rcm
                              └──N srs_type

product 1──N sds_doc (via srsdoc_id → srs_doc)
sds_doc 1──N sds_node
sds_doc + srs_req → sds_reqd 1──N logic
sds_doc + srs_req → sds_trace

product 1──N test_set 1──N test_case
product 1──N doc_file
product 1──N prod_dhf
product N──N usr  (prod_user)
product N──N haz  (prod_haz) ── haz(主数据)
product N──N rcm  (prod_rcm) ── rcm
product N──N cst  (prod_cst) ── cst

usr N──1 role N──N perm (role_perm)

product 1──N risk_mgmt_doc 1──N risk_analysis
                              └──N risk_control
risk_participant (全局字典，无 doc 外键)

session.uid → usr.id
```

**追溯链**：`srs_req` ↔ `sds_trace`/`sds_reqd` ↔ `sds_doc` ↔ `srs_doc` ↔ `product`；测试用例通过 `srs_code` 字符串关联需求。

## 10. 关键编码语义

### 10.1 `srs_req.type_code`
| 值 | 含义 |
|----|------|
| `"1"` | 标准/产品需求 |
| `"2"` | 其他需求（无功能/子功能列） |
| `"reqd"` | 独立新增功能描述的占位行 |
| 其它（UUID / `change_xxx`） | 变更需求表，1:1 对应 `srs_type` |

### 10.2 节点 `label`
- `__auto_req_detail`：自动生成的功能描述节点
- `__auto_req_group`：自动生成的分组容器节点

### 10.3 `n_id`
- 文档主表 `n_id` = 当前已分配最大节点 ID。
- 保存时先删全部节点再整树重建，新节点 `n_id=0` 由后端重新分配。

## 11. 修改注意事项 / 不可破坏的核心逻辑

1. **唯一约束是业务护栏**，不可随意删除：
   - `srs_req (doc_id, type_code, code)`、`srs_reqd.req_id`、`srs_type (doc_id, type_code)`、`sds_trace/sds_reqd (doc_id, req_id)`、`product (name, full_version)`、`srs_doc (product_id, version)`、`sds_doc (srsdoc_id, version)` 等。
2. **逻辑外键**：表间无 DB 级 FK，删除主数据时**必须在 serv 层手动级联**（如删 rcm 要删 prod_rcm，删 srs_doc 要删其 node/req/reqd/type）。改删除逻辑时勿遗漏级联。
3. **`req_id` 是 `srs_req.id`（整数），不是 SRS 编号字符串**：sds_reqd / sds_trace / req_rcm 关联均基于此。
4. **`srs_reqd.intput` 字段名为历史拼写**，全栈一致保留，**不要"修正"为 input**，否则会破坏读写。
5. **`type_code` 语义**贯穿 SRS/SDS 全链路，改动需同步前后端所有判断。
