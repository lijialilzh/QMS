## 1. 功能概述

按**产品（版本）**维护项目成员清单：每条记录是「职能 → 姓名」的一行（如 管理者代表=王少康、RA=杨冰、开发人员=胡晓光 / 徐帅各占一行）。一个职能可对应多人（多行）。用于产品研发人员分配登记。

- 数据维度：产品版本级（`prod_id`，与产品 RCM/HAZ/CST 一致），与项目无直接绑定。
- 与「风险管理报告参与人」(`risk_participant`) 是不同的两套数据：后者是全局 role/name 列表，本模块按产品维护。

---

## 2. 前置依赖 & 关联模块

- 依赖：产品主数据（`/product/list_product`）提供「产品名称 + 完整版本」级联下拉（`ProductVersionSelect`）。
- 页面：`pages/syscfg/ProjectMembers.tsx`；API 客户端 `api/ApiProjectMember.ts`。
- 菜单：「系统配置 → 项目人员管理」`/project_members`，权限 `project_member_view`。
- 【只读 / 禁止修改】：`/product/*` 产品模块、`risk_participant` 风险参与人模块。

## 3. 完整执行流程（分步细化）

1. 进入页面 → 拉取产品下拉（`list_product`，page_size=1000），用产品名称 + 完整版本级联选择。
2. 选择产品（版本）→ 调用 `list_project_member(prod_id)` 加载该产品成员，按 `sort_order, id` 升序展示。
3. 点击「新增」→ `add_project_member(prod_id, role=默认首个职能, name="", sort_order=当前最大+1)`，新增一空行后重新加载，用户再点单元格补全。
4. **点击单元格即可编辑、失焦实时保存**（与产品 HAZ/CST 一致）：
   - 职能：`AutoComplete`（内置固定职能下拉 + 允许自定义输入），失焦保存；
   - 姓名 / 备注：`Input`，失焦或回车保存；
   - 保存调用 `update_project_member`，成功后仅本地更新该行，避免整表刷新闪烁。
   - 分支：未选中编辑态时单元格只读展示，空值显示淡灰 `—`。
5. 删除：行尾「删除」→ 确认 → `delete_project_members(id)`（支持逗号多 id）→ 重新加载。
6. 导入清单（`import_project_members`，multipart：prod_id + replace + file）：按模板「人员分配」表原样导入：
   - 优先选表头含「职能/人员」的 sheet，其次标题含「人员」，再退化首个 sheet；定位「职能」「人员」列；
   - 逐行解析：**职能为空时向上继承**上一非空职能；姓名单格含多人（、,/ 空白 换行）自动拆成**一人一行**；
   - `replace=true`（默认）先清空该产品原有人员再导入，前端二次确认。

固定职能下拉（前端常量 `ROLES`，可自定义）：管理者代表 / 研发负责人 / 产品负责人 / RA / QA / TPM / 产品经理 / 开发人员 / 测试人员 / 生产 / 临床 / **模型部负责人** / **高级算法工程师** / **算法工程师** / **项目专员** / **标注人员**。

默认标注人员名单（产品下还没有「标注人员」时自动写入一人一行，之后可在本页手动新增/删除）：刘冰、周鑫仪、蒙明、余露、王丽、任小军、赵钰淇、龙菲、李良梦、徐飘飘、史江坤、马星宇、王莹莹。

默认模型人员（产品下还没有该职能时按职能补齐，之后可在本页手动新增/删除）：模型部负责人=王瑜、高级算法工程师=张欢、算法工程师=刘恩佑 / 郝增号、项目专员=肖薇。旧职能「模型负责人」且姓名为肖微/肖薇时改为「模型部负责人」王瑜。某职能已有人则不重复写入。

## 4. 核心规则 & 判定条件

- `add_project_member`：`prod_id` 必填，否则返回参数错误。
- `update_project_member`：按 `id` 定位；不更新 `id` 与 `prod_id`（人员不可跨产品迁移）。
- `delete_project_members`：入参为逗号分隔 id，过滤非数字后批量删除。
- 列表后端按 `sort_order` 升序、再按 `id` 升序；前端不分页（一次取全部，footer 显示总数）。
- 权限：写操作 `project_member_edit`，读操作 `project_member_view`；默认角色「产品经理」拥有读写。

## 5. 数据结构说明

表 `project_member`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| prod_id | Integer NOT NULL, index | 产品 ID（产品版本） |
| role | String(64) NOT NULL | 职能 |
| name | String(64) NOT NULL | 姓名（允许空字符串，新增时占位） |
| sort_order | Integer 默认 0 | 排序 |
| note | String(256) | 备注 |

接口端点见 [03_接口明细_用户角色项目产品.md](./03_接口明细_用户角色项目产品.md)（项目相关）。

## 6. 异常场景 & 兜底逻辑

- 未选产品点「新增」：前端提示「请先选择产品」，不发请求。
- 未选产品：列表清空。
- 保存/删除失败：`message.error` 提示后端 msg；保存失败回滚编辑态 `updating`。
- 数据库异常：后端 `rollback` 并返回 `msg_err_db`。

---

## 7. 功能约束 & 修改红线

1. 人员一人一行，不在单格塞多人（便于增删与统计）。
2. `update` 不可修改 `prod_id`，避免人员跨产品错位。
3. 不可与 `risk_participant`（全局风险参与人）合并或互相引用，两者数据维度不同。
4. 删除为物理删除，按 id 批量；不做软删除。

- [ ] 新增后出现新行，点击单元格可编辑职能/姓名/备注并实时保存。
- [ ] 职能下拉含固定职能（含模型部负责人 / 高级算法工程师 / 算法工程师 / 项目专员 / 标注人员）且支持自定义输入。
- [ ] 产品下尚无标注人员时自动写入默认 13 人，可再手动新增。
- [ ] 产品下尚无对应模型职能时自动写入王瑜 / 张欢 / 刘恩佑 / 郝增号 / 肖薇，已有该职能则不重复写。
- [ ] 删除后该行消失，其它产品数据不受影响。
- [ ] 导入「项目人员清单」模板：职能/姓名按模板原样还原，职能空格向上继承，单格多人拆成一人一行。
- [ ] 无 `project_member_view` 权限者看不到菜单。
