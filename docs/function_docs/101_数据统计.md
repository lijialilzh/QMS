# 1. 功能概述

- **用途**：从本机病例文件夹或服务器目录读取 DICOM 头，在本页生成统计结果；需要时手动下载 Excel。
- **使用场景**：左侧菜单「数据质控 → 数据统计」；面向不跑服务器脚本的用户。
- **最终目标**：全产品通用，不写死路径；浏览器不上传 DICOM；服务端只读已有目录的文件头，不存图像、不新建统计库表。解析后的表按「产品 + 原始/基础/标注」写入该产品已有 `dd_015_*` 记录章节（`case_rows` / `case_meta`），本机缓存作加速；刷新或换浏览器后选同一产品即可从数据文件读回；不含图像。
- **归档**：原始、基础、标注三个库分开读取，每个库有自己的路径，只管自己的数据。本页选择产品后，在某个库下选完病例文件夹或从服务器读完，只在本页展示并写入本机缓存，不写数据文件、不建档，并提示点击写入。点「写入数据」后，才把「数据分布」和病例明细写入该产品最新的**这一个库**的统计表（原始→`dd_015_01`，基础→`dd_015_02`，标注→`dd_015_03`；封面/修订不改；编辑页仍只展示数据分布原表），其它两个库不动。下游记录按库分（见 R13）：原始库写「多中心数据回传记录」`dd_002`、「数据整理记录」`dd_003` 和「数据库上传记录」`dd_010` 的原始/基础段；标注库写试标注/标注记录（100 的 R18）、`dd_010` 标注段、「训练集测试集查重记录」`dd_012` 和「数据标注需求反馈」`dd_011`；基础库只写自己的统计表。写入时不补齐缺失文档。点「生成文件模版」才按 R14 补齐该产品尚未建档的数据文件、模型文件菜单类型（模板 A0；已有任意版本则跳过、不覆盖、不替换）。仍可下载 Excel，到编辑页「导入统计 Excel」备用。规则见 [100_数据文件管理.md](./100_数据文件管理.md)。
- **关联**：统计口径对齐原 `dd_015_*` 表（年龄 `(0, 17]` / `(17, 40]` / `(40, 60]` / `>60`；管电压；重建算法按系列归并）。封面/产品信息自动填不在本模块。亚组目标值与回传/基础库核对应见 [104_数据自查.md](./104_数据自查.md)。

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

菜单「数据质控 → 数据统计」进入 `/data_stats`。无 `data_doc_view` 不显示。

## 3.1 选择报表类型

单选：原始数据库 / 基础数据库 / 标注数据库。选中的库决定：服务器路径框显示哪个库的路径、读到的病例写进哪个库、本页展示哪个库、下载文件名。点「写入数据」时，只覆盖该产品最新的当前库统计表（原始 `dd_015_01` / 基础 `dd_015_02` / 标注 `dd_015_03`；无该文档则提示先点「生成文件模版」，本次不新建），其它两个库不变。读取进行中切换了库，结果仍只写回发起读取的那个库。页上选择产品（名称+完整版本，默认「全部」）；未选具体产品则算完只展示、不写入。

## 3.1.1 标注库按算法模块读取

已选产品且该产品在「算法模块管理」里有模块时，选中「标注数据库」后下方出现页签：最前面是「汇总」，其后按「算法模块管理」页列出的全部模块各一个（章节模块 + 只在导航模块里、名称对不上章节模块的模块，同名只算一个；顺序与该页一致，见 103）。默认选中第一个模块。各模块页签上显示该模块已读序列数，没读过显示「未读」；页面只展示当前模块的病例。「汇总」展示各已读模块去重后的病例，页签数字是去重后的序列数，一个模块都没读则显示「未读」。去重与写入标注统计表相同：同一序列（`SeriesInstanceUID`，无则 TXID+PatientID）只留一条，按模块页签从左到右，先出现的留下。各模块自己的例数不去重，所以各模块相加可能大于汇总。

- **模块页签**：有自己的服务器路径（按「产品 + 模块」记在本机）。路径为空时，从该产品最新 `dd_010` 标注表里「数据集」含该模块名（去掉末尾「模块」）的行取存储路径，多行取公共父目录；找不到则提示填写，不编造。选择病例文件夹、从服务器读取、导入 gt/pred/dice 都只改这个模块的病例。
- **汇总页签**：只展示各已读模块去重后的病例明细、数据分布、统计结果、设备分布。不能选病例文件夹、不能从服务器读取、不能导入 gt/pred/dice、不能改 TXID 和「自定义」。点「写入数据」只回填标注数据库统计表 `dd_015_03`（合并后的数据分布和病例明细），不写试标注/标注记录、`dd_010`、`dd_012`、`dd_011` 和模型文件。写入前核对各模块病例的医院编码，有对不上的则本次不写入。下载 Excel 为这份去重结果，文件名带「汇总」。来源为各模块来源拼接。
- **合并（写入）**：写入标注统计表时，各模块病例按模块顺序合并，同一序列（`SeriesInstanceUID`，无则 TXID+PatientID）只算一次。与汇总页签同一口径。
- **按模块分开写入**：读完某个模块（选文件夹 / 服务器读取 / 导入 gt/pred/dice）后只在本页展示并写入本机缓存，并提示点击写入。点按钮「写入『模块名』」才写入该模块；下载 Excel 时同样只下载当前模块，不写文件。合规医院只核对该模块自己的病例 TXID。有未对上的、该产品没有合规医院、或名单读失败：本次不写入任何文件，提示修改 TXID 后再写入。其它模块未对上的编号不出现在这次提示里。写入模块 X 时：
  - `dd_015_03` 只写一份（一张数据分布表，与原表一致）：只替换 X 的病例清单，再按**当前存在的**模块合并统计数据分布与 `case_rows`，`case_meta.source` 为各模块来源拼接；各模块病例存在同一章节的 `case_modules`（`{模块名: {rows, source}}`），编辑页不展示。未读模块不计入、不编造；算法模块管理里已删除或改名的旧模块病例在下次写入时去掉。Excel 下载的是当前页签的病例，文件名带模块名。本机缓存按模块各存一份，「标注」槽位存合并结果。
  - 试标注 / 标注记录：写 X 自己的那份「X试标注记录」「X标注记录」（100 的 R36，每个模块各一份，名称随模块），PID 为 X 的病例；其它模块的记录不动。对不上任何模块的旧写死文件（列表显示「未对应模块」）不写。
  - 评测记录 `dd_009_03` 仍为固定文件：名称含 X 时写 X 的 PID，对不上任何模块时写合并 PID。
  - `dd_010`：只改标注段里数据集名含 X 的行（上传数据量 = X 的序列数，上传日期/上传人员同 R29）；原始段、基础段、其它模块和对不上模块的数据集行不动。
  - `dd_012`、`dd_011` 为产品级，照常重算。
  - 该模块已有病例时，再覆盖该模块已有的模型训练集构建记录、模型调优集构建记录、模型测试集构建记录、模型训练记录、模型测试记录（99 的 R27、R28）。没有这些文件则跳过，不新建。代码审查、封装不写。其它模块的模型文件不动。
- **模块名匹配**：记录名或数据集名同时含多个模块名时，取模块名更长的（如「肺叶分割2」优先于「肺叶分割」）。同一序列在多个模块里出现时，各模块数量各算各的，合并表只算一次，所以各模块数量相加可能大于合并总量。
- 模块还没有自己的试标注/标注记录时（一般在算法模块管理加模块时已建好），写入该模块前先按 100 的 R36 补建（已有不覆盖），再写该模块的 PID；不建评测记录。R14 补齐建档时不再建旧的写死试标注/标注类型。`dd_010` 标注段没有含该模块名的数据集行时不写数量、不补行。
- 模块未读时该页签为空，不展示拆分前整库读取留下的旧病例（如拆分前一个地址同时写入三个库的病例）。旧病例仍留在标注统计表里，第一次按模块读取并写入后被各模块合并结果替换。
- 未选产品或该产品没有算法模块：没有模块页签，标注库仍按整个库一个路径读取。

## 3.2 选择病例来源

两种来源，口径相同。从服务器读取、选择病例文件夹、下载 Excel 三个按钮按这个顺序排在路径行右侧。每个病例一个子文件夹（其下为 DICOM）；根下直接是病例，或「中心/批次 → 病例」均可。病例夹下的序列子文件夹（`DICOM` / UID 名等）并入该病例，不另算一例。每病例只读 1 个可解析 DICOM 的文件头（跳过 SQ，最多读前 512KB），像素不读。

1. **本机文件夹**：文件夹选择器选出本机根目录。浏览器读文件头，文件不上传。请用 Chrome / Edge。
2. **服务器路径**：原始、基础、标注各有一个路径，切换库时路径框跟着换，框前标出当前库；用户名、密码三个库共用。输入框填 `主机:/abs`（如 `172.16.8.93:/data/dicom/ct-dr-hj`），并填用户名、密码，点「从服务器读取」，只读当前库的路径。本机已挂载该目录则直接扫、不用账号；否则用 SFTP（22 端口）登录后只读每个病例 DICOM 头。密码不落库、不写入统计表、不进本机缓存。路径为空且已选产品：从该产品最新 `dd_010` 对应库（原始/基础/标注）的存储路径取公共父目录再扫（远程同样要账号）。无匹配路径、登录失败或目录不存在则提示，不改已有统计。

## 3.3 展示

选完文件夹或从服务器读完后结果**直接显示在本页**，不自动下载、不写入数据文件，并提示点击「写入数据」。点「写入数据」时，原始、基础、标注三个库都用本次病例的 TXID（第一段 `-` 前，与 100 的 R20 同一口径）对应该产品合规医院编号。全部对上才提示写入成功，列出本次实际写入的每一份文件名，如「已统计 N 个序列；已写入 5 份数据文件：「原始数据库统计表」、「多中心数据回传记录」、「数据整理记录」、「数据库上传记录」…」（没写成的另有错误/警告提示，不列入）。有对不上的（一条都没有，或只对上一部分），或该产品没有合规医院、或合规医院名单读失败：改为警告，写明没对上的 TXID，不提示写入成功；统计表仍写入。原始库此时不把多中心数据回传记录、数据整理记录列入已写入（一条都没对上则这两份不按医院写入；只对上一部分时，未对上的病例不写入这两份）。点「生成文件模版」新建了缺失文档时，逐个列出新建的文件名；已有类型不替换。两种提示都按左侧导航位置分行显示，每行写「数据文件/模型文件 › 分组 › 菜单项：「文件名」」，如「数据文件 › 入库记录 › 试标注记录：「肺栓塞分诊试标注记录」」；菜单项就是该文件本身时（如统计表）只写位置。解析行只写入当前产品+当前库的本机缓存。刷新或再进本页：先读本机缓存，没有则从该产品对应统计表读回病例明细（不含 DICOM），**只展示、不写入数据文件**。切换产品或原始/基础/标注时换对应缓存/数据文件，都没有则空表，不把别的库的病例带过来。仅在点「写入数据」时，才只覆盖当前库的 `dd_015_*`，并按 R13 写入该库对应的下游记录；封面/修订不改。选择病例文件夹、从服务器读取、导入 gt/pred/dice、下载 Excel 不建档、不写文件。未选产品则只展示、不写入、不建档。页签：病例明细、数据分布、统计结果、设备分布。病例明细在 gt 前有「自定义」列，只许改 TXID 和「自定义」，其它列不能改；改完写入本机缓存，已选产品时写入该库统计表 `case_rows`（标注库再写入当前模块的 `case_modules`），不因此改下游回传/整理。重新从文件夹或服务器读取按新扫描覆盖这两列。导入 gt/pred/dice 不改「自定义」。「自定义」不参与分布统计和医院核对；手改后的 TXID 在下次点「写入数据」时按新值核对。统计人←参与人员「脱敏+清洗人员」（页上已填则用已填）；统计日期←时间线「数据部」该库统计表（无则该库上传记录）写成 `yyyy.M.d`，不写当天。数据类型空则「胸部CTPA」，疾病构成空则「肺栓塞层阳性+阴性」。数据分布表对齐原表：含重建算法、管电压、总计、记录人/审核人；空年龄段不写 0 行。服务器读取的识别结果带「数据来源」（服务器 IP+路径，取接口返回的 `path`/`root`）：随「产品+类型」写入本机缓存与 `dd_015_*` 的 `case_meta.source`，设备分布页签上方与下载 Excel 的「设备分布」工作表首行展示「数据来源」；切换产品/类型读回各自来源；本机选文件夹则来源为空。

## 3.4 下载

仅当用户点击「下载 Excel」时才生成 xlsx，不自动下载。工作表与离线脚本对齐：

| 工作表 | 对齐脚本 | 内容 |
|--------|----------|------|
| 病例明细 | `data_statistics_multi.py` | 每病例一行，只保留指定列：TXID（病例文件夹）/ PatientID / SeriesInstanceUID / SEX / DEVICE / ConvolutionKernel / PhotometricInterpretation / AGE / KVP / THICKNESS / PixelSpacing / 自定义 / gt / pred / dice。自定义在 gt 前，手填，可空。只许改 TXID 和自定义。其余 DICOM 列不展示、不缓存、不落库（服务器扫描与本地解析在内部读全量头做合并统计，输出行裁剪） |

# 4. 核心规则 & 判定条件

| 编号 | 规则 / 判定条件 | 含义 | 不满足 / 命中时的后果 |
|------|----------------|------|----------------------|
| R1 | 权限 `data_doc_view` | 与数据文件同权 | 菜单不可见 |
| R2 | 浏览器不上传 DICOM；服务端只读已有目录的文件头 | 像素不读、不落库、不存图像 | 无后端 DICOM 存储 |
| R11 | 可从服务器路径读取 | 原始、基础、标注各用自己的路径。点「从服务器读取」：当前库有路径则扫该目录；空则从最新 `dd_010` 该库存储路径取公共父目录。本机已有该目录则直接读。`主机:/abs` 且本机没有则 SFTP（用户名+密码，22 端口）。密码不落库、不缓存 | 无账号则提示填写；登录失败/目录不存在/0 例则提示、不改已有统计；本机选文件夹仍可用 |
| R3 | 一病例一文件夹，只读 1 个 DICOM 头 | 与离线脚本同一套头字段。TXID=选中根下的病例子夹名，不上卷成主目录。同一检查的更深层序列夹合并为一例；同一夹下多检查则 TXID=PatientID | 无子文件夹则整目录算 1 例；选中根的第一层子夹即使名为 Thorax/Abdomen 也当病例夹 |

# 6. 异常场景 & 兜底逻辑

- 未选到文件夹、服务器目录不存在或 0 个病例：提示「未找到病例文件夹」或「服务器上找不到该目录」。
- 远程路径未填用户名/密码：提示「请填写服务器用户名和密码」。
- SFTP 登录失败：提示「服务器登录失败，请检查用户名和密码」。
- 无法连上主机：提示「无法连接服务器 …」。
- DICOM 头解析失败：跳过该病例；全部失败则提示「无法读取 DICOM」。
- 非 Chrome/Edge 可能无法选本机文件夹：仍可用服务器路径；本机选择请用 Chrome / Edge。
- DICOM 含 SQ 时按数据集顺序跳过该序列，只取根级标签（与浏览软件 / pydicom 一致）；禁止在文件中搜索标签字节，以免读到错误 PatientID。
- 本机缓存写满：提示本机可能丢；已写入 `dd_015_*` 的分布表和 `case_rows` 仍保留，再选产品可从数据文件读回。
- 旧统计表尚无 `case_rows`：本页病例明细为空，需再选一次病例文件夹或从服务器再读后才会写入。
- 密码不写入数据文件、本机缓存和日志正文。
