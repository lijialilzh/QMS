# 1. 功能概述

- **用途**：从本机病例文件夹或服务器目录读取 DICOM 头，在本页生成统计结果；需要时手动下载 Excel。
- **使用场景**：左侧菜单「数据质控 → 数据统计」；面向不跑服务器脚本的用户。
- **最终目标**：全产品通用，不写死路径；浏览器不上传 DICOM；服务端只读已有目录的文件头，不存图像、不新建统计库表。解析后的表按「产品 + 原始/基础/标注」写入该产品已有 `dd_015_*` 记录章节（`case_rows` / `case_meta`），本机缓存作加速；刷新或换浏览器后选同一产品即可从数据文件读回；不含图像。
- **归档**：本页选择产品后，选完病例文件夹或从服务器读完即把「数据分布」和病例明细写入该产品最新对应 `dd_015_01` / `dd_015_02` / `dd_015_03`（封面/修订不改；编辑页仍只展示数据分布原表）；并把试标注/标注记录按 100 的 R18 写入（含分诊表的评测日期、项目、测试医生等）；同时按 100 的 R20 / R21 / R29 / R30 把当前识别结果写入该产品最新「多中心数据回传记录」`dd_002`、「数据整理记录」`dd_003`、「数据库上传记录」`dd_010` 和「训练集测试集查重记录」`dd_012`（回传医院与数据量按 TXID 命中合规医院，整理表跟回传，上传表原始/基础跟回传、标注跟统计表，查重跟标注上传）。无该文档则提示先在数据文件新增。页上可再点「写入数据文件」。仍可下载 Excel，到编辑页「导入统计 Excel」备用。规则见 [100_数据文件管理.md](./100_数据文件管理.md)。
- **关联**：统计口径对齐原 `dd_015_*` 表（年龄 `(0, 17]` / `(17, 40]` / `(40, 60]` / `>60`；管电压；重建算法按系列归并）。封面/产品信息自动填不在本模块。亚组目标值与回传/基础库核对应见 [104_数据自查.md](./104_数据自查.md)。

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

菜单「数据质控 → 数据统计」进入 `/data_stats`。无 `data_doc_view` 不显示。

## 3.1 选择报表类型

单选：原始数据库 / 基础数据库 / 标注数据库。只影响本页表头标题和下载文件名。写入数据文件时，用当前识别结果同时覆盖该产品最新 `dd_015_01` / `dd_015_02` / `dd_015_03`（无该文档则跳过并提示先新增）。页上选择产品（名称+完整版本）；未选则算完只展示、不写入数据文件。

## 3.2 选择病例来源

两种来源，口径相同：每个病例一个子文件夹（其下为 DICOM）；根下直接是病例，或「中心/批次 → 病例」均可。病例夹下的序列子文件夹（`DICOM` / UID 名等）并入该病例，不另算一例。每病例只读 1 个可解析 DICOM 的文件头（跳过 SQ，最多读前 512KB），像素不读。

1. **本机文件夹**：文件夹选择器选出本机根目录。浏览器读文件头，文件不上传。请用 Chrome / Edge。
2. **服务器路径**：输入框填 `主机:/abs`（如 `172.16.8.93:/data/dicom/ct-dr-hj`），并填用户名、密码，点「从服务器读取」。本机已挂载该目录则直接扫、不用账号；否则用 SFTP（22 端口）登录后只读每个病例 DICOM 头。密码不落库、不写入统计表、不进本机缓存。路径为空且已选产品：从该产品最新 `dd_010` 对应库（原始/基础/标注）的存储路径取公共父目录再扫（远程同样要账号）。无匹配路径、登录失败或目录不存在则提示，不改已有统计。

## 3.3 展示

选完文件夹或从服务器读完后结果**直接显示在本页**，不自动下载。读取成功只提示一句「已统计 N 个序列，并已写入数据文件」，不再分别提示统计表/标注记录/采集记录。解析行按产品+类型写入本机缓存。刷新或再进本页：先读本机缓存，没有则从该产品对应统计表读回病例明细（不含 DICOM），**只展示、不写入数据文件**。切换产品或原始/基础/标注时换对应缓存/数据文件，都没有则空表。仅在选完病例文件夹、从服务器读取、导入 gt/pred/dice、下载 Excel，或点「写入数据文件」时，才把当前结果同时覆盖原始/基础/标注三份 `dd_015_*`，并把试标注/标注记录按 R10 写入；再按 100 的 R20 / R21 / R29 / R30 写入最新 `dd_002` / `dd_003` / `dd_010` / `dd_012`；封面/修订不改。无该文档则提示先新增，不自动建档。未选产品则只展示、不写入。页签：病例明细、数据分布、统计结果、设备分布。统计人←参与人员「脱敏+清洗人员」（页上已填则用已填）；统计日期←时间线「数据部」该库统计表（无则该库上传记录）写成 `yyyy.M.d`，不写当天。数据类型空则「胸部CTPA」，疾病构成空则「肺栓塞层阳性+阴性」。数据分布表对齐原表：含重建算法、管电压、总计、记录人/审核人；空年龄段不写 0 行。服务器读取的识别结果带「数据来源」（服务器 IP+路径，取接口返回的 `path`/`root`）：随「产品+类型」写入本机缓存与 `dd_015_*` 的 `case_meta.source`，设备分布页签上方与下载 Excel 的「设备分布」工作表首行展示「数据来源」；切换产品/类型读回各自来源；本机选文件夹则来源为空。

## 3.4 下载

仅当用户点击「下载 Excel」时才生成 xlsx，不自动下载。工作表与离线脚本对齐：

| 工作表 | 对齐脚本 | 内容 |
|--------|----------|------|
| 病例明细 | `data_statistics_multi.py` | 每病例一行，只保留指定列：TXID（病例文件夹）/ PatientID / SeriesInstanceUID / SEX / DEVICE / ConvolutionKernel / PhotometricInterpretation / AGE / KVP / THICKNESS / PixelSpacing，其余列不展示、不缓存、不落库（服务器扫描与本地解析在内部读全量头做合并统计，输出行裁剪） |
| 数据分布 | `summarize_db_stats.py` | 因素/类别/序列数/占比，供 `dd_015_*` 导入 |
| 统计结果 | `triage_subgroup.py`（无 gt/pred 分支） | SEX/DEVICE/KVP/THICKNESS/ConvolutionKernel 计数 |
| 设备分布 | 同上 | 统计结果的 Item/Catgory/pos_cases/neg_cases；服务器读取时首行加「数据来源」（IP+路径） |

无标注列时 Sen/Spe 留空；Dice 需表中有 gt/pred/dice，本页从 DICOM 读不到则不出该表。不写到病例目录。不新建表。浏览器不上传 DICOM；服务端扫描不存图像。

# 4. 核心规则 & 判定条件

| 编号 | 规则 / 判定条件 | 含义 | 不满足 / 命中时的后果 |
|------|----------------|------|----------------------|
| R1 | 权限 `data_doc_view` | 与数据文件同权 | 菜单不可见 |
| R2 | 浏览器不上传 DICOM；服务端只读已有目录的文件头 | 像素不读、不落库、不存图像 | 无后端 DICOM 存储 |
| R11 | 可从服务器路径读取 | 点「从服务器读取」：有路径则扫该目录；空则从最新 `dd_010` 对应库存储路径取公共父目录。本机已有该目录则直接读。`主机:/abs` 且本机没有则 SFTP（用户名+密码，22 端口）。密码不落库、不缓存 | 无账号则提示填写；登录失败/目录不存在/0 例则提示、不改已有统计；本机选文件夹仍可用 |
| R3 | 一病例一文件夹，只读 1 个 DICOM 头 | 与离线脚本同一套头字段。TXID=选中根下的病例子夹名，不上卷成主目录。同一检查的更深层序列夹合并为一例；同一夹下多检查则 TXID=PatientID | 无子文件夹则整目录算 1 例；选中根的第一层子夹即使名为 Thorax/Abdomen 也当病例夹 |
| R4 | 年龄分段对齐原表 | `(0, 17]` / `(17, 40]` / `(40, 60]` / `>60`；有例才写该段，不写数量 0 的空段 | 无年龄则该因素无行 |
| R5 | 性别 / 设备 / 管电压 / 层厚 / 重建算法按实际值分组 | 重建算法按系列归并（空则「未知」），该因素必出；表末必有「总计」及记录人/审核人 | 卷积核全空仍写「未知」，不删该块 |
| R6 | 导入或导出时同时覆盖三份 `dd_015_*` | 选文件夹 / 服务器读取 / 导入 gt/pred/dice / 下载 Excel / 点「写入数据文件」时，用当前识别结果同时替换该产品最新 `dd_015_01` / `dd_015_02` / `dd_015_03` 的数据分布与 `case_rows` / `case_meta`，本机缓存三份一并更新。进页、换产品、切换页签只读回展示，不写。不改封面/修订；无文档不建档 | 未选产品则只展示；缺哪份统计表提示先新增、其余照写；仅打开本页不写 |
| R12 | 统计人与统计日期自动带出 | 统计人←参与人员「脱敏+清洗人员」（页上已填则用已填）；统计日期←时间线「数据部」该库统计表关键字（无则该库上传记录），`yyyy.M.d`。打开/换产品 `dd_015_*` 若有 `case_rows` 则按同一口径重填分布表 | 无该职能则统计人空；无匹配日则日期空、不写当天 |
| R9 | 解析结果本机缓存 + 数据文件 | 缓存按产品+类型加速；缓存空则从该产品 `dd_015_*` 读回病例明细；不存 DICOM | 缓存满则提示；无 `case_rows` 的旧文档本页明细仍空，需再选一次文件夹 |
| R7 | 不改封面自动填 | 与 99/100 分离 | 本页无封面 |
| R8 | 下载含病例明细+数据分布+统计结果+设备分布 | 对齐离线脚本 | 不得只导出数据分布一张表 |
| R10 | 导入或导出时写入试标注/标注记录 | 与 R6 同一触发时机。PID←DICOM PatientID（空则病例文件夹名）。`dd_008_*` / `dd_009_01` / `dd_009_02` 同时带时间线日期、参与人员标注人（轮流）、项目/类型/已标注/通过；审核医生←职能「审核医生」轮流（无则空）。`dd_009_03` 带评测日期、项目、测试集、前两名标注人员、二合一=一致；仲裁医生←职能「仲裁医生」轮流，仲裁时间←分诊最晚一天，仲裁状态=无需仲裁。打开记录页不一致则写入 | 无时间线/无标注人员则对应格空；无仲裁医生则仲裁三列空；仅打开本页不写 |
| R13 | 导入或导出时同步回传/整理/上传/查重 | 与 R6 同一触发时机。用当前识别结果按 100 的 R20 覆盖最新 `dd_002`，再 R21 覆盖 `dd_003`，再 R29 覆盖 `dd_010`，再 R30 覆盖 `dd_012`。顺序：回传→整理→上传→查重。无文档不建档 | 缺哪份提示先新增、其余照写；TXID 未命中合规医院的例数不写入回传表；仅打开本页不写 |

# 5. 数据结构说明

无新表。每病例 DICOM 头一行。本机 localStorage（`qms_data_stats_v1`）按产品+类型缓存（含 `source` 来源）；已选产品时写入该产品 `data_doc` 对应 `dd_015_*`：记录表仍是数据分布，病例明细挂同一记录章节的 `case_rows` / `case_meta`（含 `source` 来源，编辑页不展示、导出仍只出数据分布原表）。PID 写入已有 `dd_008_*` / `dd_009_*`。下载四张工作表。

# 6. 异常场景 & 兜底逻辑

- 未选到文件夹、服务器目录不存在或 0 个病例：提示「未找到病例文件夹」或「服务器上找不到该目录」。
- 远程路径未填用户名/密码：提示「请填写服务器用户名和密码」。
- SFTP 登录失败：提示「服务器登录失败，请检查用户名和密码」。
- 无法连上主机：提示「无法连接服务器 …」。
- DICOM 头解析失败：跳过该病例；全部失败则提示「无法读取 DICOM」。
- 非 Chrome/Edge 可能无法选本机文件夹：仍可用服务器路径；本机选择请用 Chrome / Edge。
- DICOM 含 SQ 时按数据集顺序跳过该序列，只取根级标签（与浏览软件 / pydicom 一致）；禁止在文件中搜索标签字节，以免读到错误 PatientID。
- 本机缓存写满：提示本机可能丢；已写入 `dd_015_*` 的分布表和 `case_rows` 仍保留，再选产品可从数据文件读回。
- 旧统计表尚无 `case_rows`：本页病例明细为空，需再选一次病例文件夹或从服务器再读后才会写入。
- 密码不写入数据文件、本机缓存和日志正文。

# 7. 功能约束 & 修改红线

## 7.1 允许修改范围
