# 1. 功能概述

- **用途**：在浏览器内从本机病例 DICOM 文件夹生成统计结果并在本页展示；需要时手动下载 Excel。
- **使用场景**：左侧菜单「数据统计」；面向不跑服务器脚本的用户。
- **最终目标**：全产品通用，不写死路径；DICOM 不上传服务器；不新建统计库表。解析后的表按「产品 + 原始/基础/标注」写入该产品已有 `dd_015_*` 记录章节（`case_rows` / `case_meta`），本机缓存作加速；刷新或换浏览器后选同一产品即可从数据文件读回；不含图像。
- **归档**：本页选择产品后，选完病例文件夹即把「数据分布」和病例明细写入该产品最新对应 `dd_015_01` / `dd_015_02` / `dd_015_03`（封面/修订不改；编辑页仍只展示数据分布原表）；并把试标注/标注记录按 100 的 R18 写入（含分诊表的评测日期、项目、测试医生等）。无该文档则提示先在数据文件新增。页上可再点「写入数据文件」。仍可下载 Excel，到编辑页「导入统计 Excel」备用。规则见 [100_数据文件管理.md](./100_数据文件管理.md)。
- **关联**：统计口径对齐备用脚本 `summarize_db_stats.py`（年龄分段 `0,18,40,60,110`；每病例文件夹读 1 个 DICOM 头）。封面/产品信息自动填不在本模块。

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

菜单「数据统计」进入 `/data_stats`。无 `data_doc_view` 不显示。

## 3.1 选择报表类型

单选：原始数据库 / 基础数据库 / 标注数据库。影响表头标题、下载文件名，以及写入哪份 `dd_015_*`。页上选择产品（名称+完整版本）；未选则算完只展示、不写入数据文件。

## 3.2 选择病例文件夹

用户用文件夹选择器选出本机根目录。约定：每个病例一个子文件夹（其下为 DICOM）；根下直接是病例，或「中心/批次 → 病例」均可。病例夹下的序列子文件夹（`DICOM` / UID 名等）并入该病例，不另算一例。浏览器按数据集顺序读每个病例夹内第一个可解析 DICOM 的文件头（跳过 SQ，不在文件中搜索标签字节；最多读前 512KB），文件不上传。

请用 Chrome / Edge。

## 3.3 展示

选完文件夹后结果**直接显示在本页**，不自动下载。解析行按产品+类型写入本机缓存，并写入该产品最新 `dd_015_*` 记录章节。刷新或再进本页：先读本机缓存，没有则从该产品对应统计表读回病例明细（不含 DICOM）。切换产品或原始/基础/标注时换对应缓存/数据文件，都没有则空表。若已选产品，同时把「数据分布」写入记录表，并把试标注/标注记录按 R10 写入；封面/修订不改。无该文档则提示先新增，不自动建档。未选产品则只展示、不写入。页上「写入数据文件」用当前识别结果再写一次。页签：病例明细、数据分布、统计结果、设备分布。统计人、数据类型、疾病构成可在页上填写后反映到「数据分布」表头并随写入带出。

## 3.4 下载

仅当用户点击「下载 Excel」时才生成 xlsx，不自动下载。工作表与离线脚本对齐：

| 工作表 | 对齐脚本 | 内容 |
|--------|----------|------|
| 病例明细 | `data_statistics_multi.py` | 每病例一行，DICOM 头字段（PatientID/SEX/AGE/DEVICE/KVP/层厚/卷积核等） |
| 数据分布 | `summarize_db_stats.py` | 因素/类别/序列数/占比，供 `dd_015_*` 导入 |
| 统计结果 | `triage_subgroup.py`（无 gt/pred 分支） | SEX/DEVICE/KVP/THICKNESS/ConvolutionKernel 计数 |
| 设备分布 | 同上 | 统计结果的 Item/Catgory/pos_cases/neg_cases |

无标注列时 Sen/Spe 留空；Dice 需表中有 gt/pred/dice，本页从 DICOM 读不到则不出该表。不写到病例目录。不新建表、不传 DICOM。

# 4. 核心规则 & 判定条件

| 编号 | 规则 / 判定条件 | 含义 | 不满足 / 命中时的后果 |
|------|----------------|------|----------------------|
| R1 | 权限 `data_doc_view` | 与数据文件同权 | 菜单不可见 |
| R2 | 文件留在本机 | 不上传 DICOM | 无后端存储 |
| R3 | 一病例一文件夹，只读 1 个 DICOM 头 | 与离线脚本同一套头字段。TXID=选中根下的病例子夹名，不上卷成主目录。同一检查的更深层序列夹合并为一例；同一夹下多检查则 TXID=PatientID | 无子文件夹则整目录算 1 例；选中根的第一层子夹即使名为 Thorax/Abdomen 也当病例夹 |
| R4 | 年龄分段 0–18–40–60–110 | 与 `summarize_db_stats.py` 一致 | 无年龄则该因素无行 |
| R5 | 性别 / 设备 / KVP / 层厚 / 卷积核按实际值分组 | 缺列不编造 | 全空则该因素不出现 |
| R6 | 已选产品则写入最新对应 `dd_015_*` 记录表 | 换数据分布原表，并在同一记录章节写入 `case_rows` / `case_meta`；不改封面/修订；无文档不建档 | 未选产品或无该文档则只展示/提示 |
| R9 | 解析结果本机缓存 + 数据文件 | 缓存按产品+类型加速；缓存空则从该产品 `dd_015_*` 读回病例明细；不存 DICOM | 缓存满则提示；无 `case_rows` 的旧文档本页明细仍空，需再选一次文件夹 |
| R7 | 不改封面自动填 | 与 99/100 分离 | 本页无封面 |
| R8 | 下载含病例明细+数据分布+统计结果+设备分布 | 对齐离线脚本 | 不得只导出数据分布一张表 |
| R10 | 已选产品则写入试标注/标注记录 | PID←DICOM PatientID（空则病例文件夹名）。`dd_008_*` / `dd_009_01` / `dd_009_02` 同时带时间线日期、参与人员标注人（轮流）、项目/类型/已标注/通过；审核医生←职能「审核医生」轮流（无则空）。`dd_009_03` 带评测日期、项目、测试集、前两名标注人员、二合一=一致；仲裁医生←职能「仲裁医生」轮流，仲裁时间←分诊最晚一天，仲裁状态=无需仲裁。打开记录页不一致则写入 | 无时间线/无标注人员则对应格空；无仲裁医生则仲裁三列空 |

# 5. 数据结构说明

无新表。每病例 DICOM 头一行。本机 localStorage（`qms_data_stats_v1`）按产品+类型缓存；已选产品时写入该产品 `data_doc` 对应 `dd_015_*`：记录表仍是数据分布，病例明细挂同一记录章节的 `case_rows` / `case_meta`（编辑页不展示、导出仍只出数据分布原表）。PID 写入已有 `dd_008_*` / `dd_009_*`。下载四张工作表。

# 6. 异常场景 & 兜底逻辑

- 未选到文件夹或 0 个病例：提示「未找到病例文件夹」。
- DICOM 头解析失败：跳过该病例；全部失败则提示「无法读取 DICOM」。
- 非 Chrome/Edge 可能无法选文件夹：页面注明浏览器要求。
- DICOM 含 SQ 时按数据集顺序跳过该序列，只取根级标签（与浏览软件 / pydicom 一致）；禁止在文件中搜索标签字节，以免读到错误 PatientID。
- 本机缓存写满：提示本机可能丢；已写入 `dd_015_*` 的分布表和 `case_rows` 仍保留，再选产品可从数据文件读回。
- 旧统计表尚无 `case_rows`：本页病例明细为空，需再选一次病例文件夹后才会写入。

# 7. 功能约束 & 修改红线

## 7.1 允许修改范围

- 本文；前端 `pages/data_stats/`；`Home.tsx` 本菜单项；`index.tsx` 本路由；i18n `menu.data_stats`。备用脚本只读对齐口径。

## 7.2 绝对禁止改动（红线）

- 禁止改产品文件 / 模型文件 Word、禁止回写产品主数据。
- 禁止改 `src/store/`、`src/common/`、`src/utils/base/`。
- 禁止把 DICOM 传到服务器；禁止为本功能新建数据库表。
- 禁止改 `dd_015_*` 封面编制部门规则。

## 7.3 禁止新增逻辑

- 不得在无 gt/pred 时编造灵敏度、特异度、Dice（与 `triage_subgroup.py` 无标注分支一致，只出计数）。
- 不得把 DICOM 传到服务器；写入 `dd_015_*` / `dd_008_*` / `dd_009_*` 仅限记录章节（含 `dd_015_*` 的 `case_rows`），不得改封面/修订，不得无文档时自动新建；不得编造标注人、日期、审核结果。

## 7.4 禁止重构结构

- 不得把本页合并进数据文件编辑页。
