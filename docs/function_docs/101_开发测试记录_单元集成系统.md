# 开发测试记录（单元 / 集成 / 系统）

> 文档编号：101（与用户手册 92 区分）。

## 1. 功能概述

在测试用例合集导入 **单元测试 / 集成测试 / 系统测试** 用例时，自动生成或刷新对应阶段的测试记录；列表「导出数据集」导出 **测试记录 xlsx**（非纯用例表），多型号时 sheet 与查看 Tab（`sheet_name`）一致。模版对齐体系文件 VV-001-QR-05/06/07。

> 用户测试记录见 [91_用户测试记录管理.md](./91_用户测试记录管理.md)，不纳入本表。

---

## 2. 用户操作流程

测试集导入用例（单元/集成/系统）→ 自动生成/刷新记录 → 合集列表点「导出数据集」下载测试记录 Excel（按型号分 sheet）。

---

## 3. 前端实现

- 暂不新增独立菜单页；生成与导出挂在 `pages/test_set/TestSets.tsx`「导出数据集」。
- 查看用例仍用 `TestCases` Tabs（按 `sheet_name`）。

---

## 4. 后端

| 能力 | 说明 |
|------|------|
| 表 `dev_test_record_doc` | product_id, stage, version, file_no, content(JSON)；唯一 `(product_id, stage, version)` |
| 导入后 | stage∈{单元测试,集成测试,系统测试} 成功导入 Excel → 无则建 A0，有则刷新；结果按 Case 编号保留 |
| 导出数据集 | 上述 stage：按模版导出测试记录；多 `sheet_name` → 多 sheet；用例正文取自 `test_case`，结果取自 content |

content：表头信息 + `results: { code: { actual, result, remark } }`；用例行打开/导出时从 test_case 现取。

---

## 5. 关键规则

1. 模版列：Case编号、需求编号/设计编号、测试类型、测试阶段、功能点、简短描述、前置条件、测试步骤、预期结果、实际结果、测试结果、备注。
2. 表头自动获取可复用：产品/版本、运行环境网络与工具、STR 设备、时间线日期等（与用户测试记录同源策略）。
3. 用户测试阶段「导出数据集」仍导出用例（或提示走用户测试记录导出），不走本模版。

---

## 6. 修改注意事项

1. 用例正文以 `test_case` 为准，勿在 content 中存死全量用例导致与重导不一致。
2. 导出 sheet 划分必须与查看 Tab 的 `sheet_name` 一致。
