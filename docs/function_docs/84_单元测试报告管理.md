# 单元测试报告管理（UTR）

## 1. 功能概述

管理单元测试报告（测试文件），PDP 风格章节树结构。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 导出 docx。

---

## 3. 前端实现

- 页面：`pages/utr/UtrDocs.tsx`（列表）、`UtrDocDetail.tsx`（详情/编辑）
- API：`api/ApiUtrDoc.ts`

`utr_doc`：product_id, version, file_no, change_log, content(JSON)

## 6. 关键业务逻辑与规则

1. PDP 风格章节树结构（菜单名「用户测试报告」）。
2. 与 UTP（用户测试计划）不同，UTR 是测试报告阶段文档。
3. **文件修订记录**：修订人 ← 测试人员日期规则（2025.09 前「宋月」、之后「孙家旭」，打开即覆盖）；批准人 ← 研发负责人。
4. 评审记录页面与需求规格说明一致：只读合并表，点右侧「编辑」弹出表格编辑，确认后写回；点「删除」去掉该表。编辑弹框里，参评人员签字、评审时间、评审结论、批准人员签字这些只在第一格有内容的行合并成一格。查看页不显示编辑和删除。参评人员模板含：产品经理、产品部经理、QA、**测试负责人**（置于 QA 行右侧）；打开已有文档若缺「测试负责人」则自动补到 QA 行右侧空位。参评人员从该产品参与人员覆盖。测试负责人多人时有宋月用宋月，没有宋月用孙家旭。
5. **「描述」章**：打开/换产品时自动写入产品名称←`name`、完整版本←`full_version`；有产品型号（`type_code`）则写入「产品型号：…」，无型号则不显示该行；其后说明正文保留。编辑页产品信息行只读，说明正文仍可改。
6. **「测试分布图」**：仅使用章节 `charts`（页内生成的分布图）；**不**再从图表文件 `img_flow` 注入 `images`。打开/换产品时清空该章误挂的 `images`，避免多出流程图。
7. **「人力资源」表**：打开/换产品时按「具体职责」与用户测试计划负责人同一规则覆盖「角色」与「资源数量/具体人员」——职责含「用户培训」→ 产品经理；职责含「执行测试」或角色含「用户测试」→ 用户测试人员；其余（生成测试计划/用例/评估等）→ 测试人员（日期规则宋月/孙家旭）。
8. **产品版本号**：打开/换产品时，只把「测试版本」「完整版本」格子里的四段版本号换成当前产品 `full_version`。单元格或表头含「浏览器」/Chrome 的内容不换成产品版本。
9. **「测试工作量」**：开始/结束时间按任务从时间线取最早到最晚一天。用户测试报告：测试计划←「用户测试计划」，测试用例设计←「用户测试用例」，测试执行←「用户测试记录」，测试总结←「用户测试报告」，用户培训←「用户培训」。天数按时间线命中的天数。对不上时开始/结束才用该文档封面日期。
10. **「测试设备详情」**：格子里已经保存了设备信息时，打开、换产品都不覆盖，手改留在这里。这一格还空着时，才从该产品最新《用户测试记录》封面的用户端设备、服务端设备整段补上（含显示器分辨率、浏览器、显存、硬盘、网卡等全部行），浏览器版本一并写入设备信息（记录里浏览器在单独一列时，补进「浏览器版本：…」）。编辑页这一格行高按全文撑开，用户端从操作系统到浏览器、服务端从操作系统到网卡都要露出来。没有对应用户测试记录或对应行没有设备信息时不覆盖。「是否满足要求」不改。用户测试记录反过来读取这里已保存的整段配置。
