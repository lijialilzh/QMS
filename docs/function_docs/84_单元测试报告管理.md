# 单元测试报告管理（UTR）

## 1. 功能概述

管理单元测试报告（测试文件），PDP 风格章节树结构。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 导出 docx。

---

## 3. 前端实现

- 页面：`pages/utr/UtrDocs.tsx`（列表）、`UtrDocDetail.tsx`（详情/编辑）
- API：`api/ApiUtrDoc.ts`

## 5. 数据库表

`utr_doc`：product_id, version, file_no, change_log, content(JSON)

---

## 6. 关键业务逻辑与规则

1. PDP 风格章节树结构（菜单名「用户测试报告」）。
2. 与 UTP（用户测试计划）不同，UTR 是测试报告阶段文档。
3. **文件修订记录**：修订人 ← 测试人员日期规则（2025.09 前「宋月」、之后「孙家旭」，打开即覆盖）；批准人 ← 研发负责人。
4. 评审记录页面与需求规格说明一致：只读合并表，点右侧「编辑」弹出表格编辑，确认后写回；点「删除」去掉该表。编辑弹框里，参评人员签字、评审时间、评审结论、批准人员签字这些只在第一格有内容的行合并成一格。查看页不显示编辑和删除。参评中含「测试」且不含「用户」的角色按测试人员日期规则覆盖。
5. **「描述」章**：打开/换产品时自动写入产品名称←`name`、完整版本←`full_version`；有产品型号（`type_code`）则写入「产品型号：…」，无型号则不显示该行；其后说明正文保留。编辑页产品信息行只读，说明正文仍可改。
6. **「测试分布图」**：仅使用章节 `charts`（页内生成的分布图）；**不**再从图表文件 `img_flow` 注入 `images`。打开/换产品时清空该章误挂的 `images`，避免多出流程图。
7. **「人力资源」表**：打开/换产品时按「具体职责」与用户测试计划负责人同一规则覆盖「角色」与「资源数量/具体人员」——职责含「用户培训」→ 产品经理；职责含「执行测试」或角色含「用户测试」→ 用户测试人员；其余（生成测试计划/用例/评估等）→ 测试人员（日期规则宋月/孙家旭）。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. content(JSON) 结构需与章节树编辑器兼容。
