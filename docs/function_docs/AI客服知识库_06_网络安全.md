# AI 客服知识库（六）网络安全管理

> 本文件是给"AI 客服"使用的功能知识库，内容来自系统真实功能（功能逻辑文档 47、用户手册 94 拓展）。
> 每个功能按统一结构描述：界面位置 / 用户常见问法 / 是做什么的 / 解决什么问题 / 怎么用 / 相关功能。

## 模块总览：网络安全管理

网络安全管理模块面向 IEC 62304 / IEC 81001-5-1 / FDA 网络安全要求，按产品/版本维护**网络安全风险管理报告**——独立于通用「风险管理报告」（45），不共用模型与数据表。

它分布在一级菜单：
- **网络安全管理**（菜单「网络安全管理」）按产品/版本维护网络安全报告文档，包含**网络安全风险管理报告**一个二级菜单。
- 评分标准内置 5×5 likelihood × severity 矩阵（独立常量 `CYBERSEC_SCORE_TABLE`，与风险管理报告评分独立）。
- 残余风险作为 5.3 章节内联，不另设菜单。
- 7. 威胁缓解措施追溯**运行时计算**，从威胁与控制措施的 (threat_code ↔ rcm_codes / threat_codes) 关联实时反映。

它解决的核心问题是：把产品的网络安全威胁与控制措施结构化记录下来，**与产品 CST（网络安全威胁库）实时联动**，并产出符合监管要求的网络安全风险管理报告，与现有的 RCM/HAZ 风险管理体系并行不重叠。

---

## 1. 网络安全风险管理报告（列表 / 新建 / 编辑 / 复制 / 导入 / 导出 / 删除）

- **界面位置**：菜单「网络安全管理 → 网络安全风险管理报告」，列表页路径 `/cybersec_docs`；详情页 `/cybersec_docs/add`（新建）、`/cybersec_docs/edit/{id}`（编辑）、`/cybersec_docs/view/{id}`（只读查看）。
- **用户常见问法**：怎么写网络安全报告、网络安全风险管理报告怎么导入 Word、怎么新建网络安全报告、网络安全报告怎么复制、怎么导出网络安全 Word、网络安全报告版本怎么改、网络安全文件编号在哪改、STRIDE 威胁怎么填、SBOM 风险评估怎么写、网络安全扫描结果怎么录入。
- **是做什么的**：按「产品 + 版本」管理网络安全风险管理报告文档，支持 Word 导入、空白新建、复制版本（支持跨产品）、按章节编辑、导出 Word。报告内容由章节树（content JSON）+ 网络安全威胁矩阵（cybersec_threat）+ 三类风险控制措施（**三张独立表** cybersec_control_internal / _sbom / _scan）+ 评分标准等构成。
- **解决什么问题**：把产品的网络安全风险输出整理成符合监管要求的标准报告文档，与产品 CST 实时联动，保证报告里 STRIDE 威胁矩阵和控制措施跟当前产品网络安全数据一致；与通用「风险管理报告」并行管理，互不混淆。
- **怎么用**：
  1. 列表页按产品 + 文档版本筛选，列含产品名称、产品版本、报告版本、文件编号（单击编辑）、变更说明、创建时间、操作（查看/编辑/复制/导出/删除）。
  2. **新建（空白）**：点「新建」→ 选产品（必填，**选完会自动联动该产品的 CST/RCM 数据**，并把适用范围/产品描述等文本章节按产品信息预填，仅当章节为空时填，不覆盖手填）→ 填写报告版本（必填）、变更说明 → 点「初始化模版」加载目录结构 → 选中章节后编辑内容 → 点顶栏「保存」。
  3. **导入 Word**：点列表「导入 Word」→ 弹窗中填写产品（必填）、版本（必填）、变更说明、上传 `.docx`（必填）→ 确定上传，系统按标题归一化匹配模板章节、图片转 base64 写入。
  4. **复制版本**：点行内「复制」→ 弹窗选目标产品（默认当前产品，可选其它产品实现跨产品复制）→ 确定，系统自动生成新版本号（同时复制威胁/控制行，并把子表 product_id 同步为目标产品）。
  5. **编辑**：列表行点「编辑」进入详情页 → 在目录结构区编辑章节（增删一级目录、节点改标题/加同级或下级）→ 各章节按类型编辑：
     - 「2. 阶段活动」是表格类章节，行编辑（阶段/开始/结束/结果）；
     - 「4. 视图分析与威胁建模」分 5 个子视图（系统全局/多患者/安全用例/可更新性/STRIDE），每个子视图含若干表格；
     - 「4.5 STRIDE 威胁建模」展示威胁矩阵（数据主要来自**产品 CST 实时数据**，并补充文档内 `cybersec_threat where view_type='STRIDE'`）；
     - 「5.1 评分标准」展示固定 5×5 likelihood × severity 色块表（红/橙/绿图例），编辑态可维护矩阵格；
     - 「5.2 风险评估及控制措施 RCM」分三个子节——内部 / SBOM / 网络安全扫描，**对应三张独立 DB 表** `cybersec_control_internal` / `_sbom` / `_scan`，每节独立 CRUD 行；
     - 「5.3 残余风险评估」是结论性文本 + 残余威胁汇总；
     - 「6. 维护更新」普通文本章节（设计保证、异常情况响应、安全更新策略、用户指导）；
     - 「7. 威胁缓解措施追溯」自动渲染（**只读**），跟着威胁/控制实时更新；
     - 含图章节：上传/更换/清除图片（非图片提示「请选择图片文件」）；
     编辑完成点顶栏「保存」。
  6. **导出 Word**：详情页顶栏点「导出 Word」（**非新建态可见**，新建状态需先保存才能导出）。
  7. **文件编号**：在列表里单击「文件编号」单元格直接编辑。
  8. **删除**：行内点「删除」并按确认提示完成（删除会级联删除其威胁/控制行）。
- **相关功能**：产品 CST（4.5 STRIDE 威胁矩阵的数据源）、产品 RCM（5.2 内部 RCM 的可参考来源）、产品管理（报告挂在产品下）。**注意：网络安全报告与「风险管理报告」（45）是两个独立模块，互不共用模型与数据表。**

## 2. 网络安全 RCM 三类（内部 / SBOM / 网络安全扫描）

- **界面位置**：详情页 5.2 章节内三个子节，路径 `/cybersec_docs/edit/{id}` 进入后定位到 5.2。
- **用户常见问法**：内部 RCM 是什么、SBOM 风险怎么填、网络安全扫描结果怎么录入、SBOM 和扫描有什么区别、三类 RCM 在哪。
- **是做什么的**：把网络安全控制措施按来源分三类，**对应三张独立 DB 表**（结构同构、独立持久化、独立 CRUD，未来可独立扩展字段）：
  - **内部 RCM**（`cybersec_control_internal`）：由产品自身设计/实现引入的网络安全控制（认证、加密、签名等）。
  - **SBOM RCM**（`cybersec_control_sbom`）：来自 SBOM（Software Bill of Materials）依赖组件分析，标注每个第三方组件的已知漏洞与缓解措施。
  - **网络安全扫描 RCM**（`cybersec_control_scan`）：来自绿盟等扫描工具的扫描结果及其控制响应。
- **解决什么问题**：网络安全风险来源差异大（自研代码、第三方依赖、扫描工具），未来三类各自字段可能独立演化（SBOM 加 component_name/cve_id，扫描加 scanner_name/scan_date 等），先拆表保留独立扩展能力；三表暂时同构，按需独立加列。
- **怎么用**：
  1. 进入 5.2 章节后切换到目标子节（内部 / SBOM / 网络安全扫描），调用对应表的端点 `add/update/delete/list_cybersec_control_{internal|sbom|scan}`。
  2. 行内「新增」→ 填编号（doc 内唯一，跨三张表不互斥但不建议同名）、描述、关联威胁编号、验证证据、是否引入新风险、备注 → 保存。
  3. 行内编辑：可改 description / verification_evidence / threat_codes / new_risk_flag / note；分类由所在表决定，**不可跨表迁移**（要换分类需删后重加到目标表）。
  4. 删除：行内删除按钮。
- **相关功能**：4.5 STRIDE 威胁（threat_code 与 RCM 的 threat_codes 串关联，形成 7. 威胁缓解措施追溯的两端，三张 control 表合并查询并标注 source 列）、产品 RCM（内部 RCM 可与产品 RCM 库对照填写）。

## 3. 网络安全威胁（cybersec_threat）

- **界面位置**：详情页 4. 视图分析与威胁建模 → 4.x 各子视图，及 4.5 STRIDE 威胁建模。
- **用户常见问法**：网络安全威胁怎么加、STRIDE 是什么、威胁评估怎么填、产品 CST 和这里的威胁是什么关系。
- **是做什么的**：把每条网络安全威胁结构化记录在 `cybersec_threat` 表，含 view_type（归属哪个子视图：全局/多患者/用例/可更新性/STRIDE）、stride_category（STRIDE 类别：欺骗/篡改/否认/信息泄露/拒绝服务/特权提升）、资产、攻击路径、影响、likelihood/severity/risk_level、控制措施、关联 RCM 编号、剩余风险评估。
- **解决什么问题**：网络安全威胁需要按多个视角描述（不只是 STRIDE 一种），引入 view_type 字段后一张表覆盖 4.x 的全部视图，避免重复建表。
- **怎么用**：
  1. 进入 4.x 对应子视图后，行内「新增」→ 选 view_type（默认当前子视图）、填编号（doc 内唯一）、资产、描述、攻击路径、影响、likelihood（1-5）、severity（A-E 或 1-5）、风险水平、控制措施、关联 RCM 编号串、剩余三项 → 保存。
  2. 4.5 STRIDE 子视图额外要填 stride_category。
  3. 4.5 STRIDE 矩阵会**自动并入产品 CST 实时数据**显示，不需要再次手填产品 CST 已有的内容。
- **相关功能**：产品 CST 库（4.5 STRIDE 的首选数据源）、网络安全 RCM 三类（threat_code 与 RCM.threat_codes 互相引用）、7. 威胁缓解措施追溯（自动追溯链条的起点）。

## 4. 评分标准（5×5）

- **界面位置**：详情页 5.1 章节，固定矩阵展示。
- **用户常见问法**：评分标准在哪改、likelihood 和 severity 怎么对应风险水平、网络安全评分跟风险管理报告评分一样吗。
- **是做什么的**：内置常量 `CYBERSEC_SCORE_TABLE`（5×5 likelihood × severity → 风险水平），红/橙/绿三色图例展示。
- **解决什么问题**：固化评分依据，所有威胁评估遵循同一套标准；与「风险管理报告」的 `RISK_ACCEPTANCE_TABLE` **独立**（虽结构同），方便按 IEC 62443 等标准独立调整网络安全评分而不影响通用风险评估。
- **怎么用**：5.1 章节展开即看到色块矩阵；编辑态下可维护矩阵格（仅文档内有效，不影响全局常量）。
- **相关功能**：4.x 威胁评估（likelihood + severity 算 risk_level）、5.3 残余风险（按残余三项二次定级）。

## 5. 残余风险评估与威胁缓解措施追溯

- **界面位置**：5.3 残余风险评估、7. 威胁缓解措施追溯。
- **用户常见问法**：残余风险怎么填、残留风险结论在哪写、追溯链怎么自动生成、追溯能不能手动改。
- **是做什么的**：
  - 5.3 是结论性文本+残余威胁汇总（来自每条 cybersec_threat 的 residual_* 字段）。
  - 7. 是**只读运行时计算**——以 cybersec_threat.threat_code 为键，反向查**三张** cybersec_control_* 表（internal/sbom/scan）的 threat_codes 串中包含该编号的 RCM 行，合并后渲染成「威胁 → 控制措施」追溯表，每行带 source 列标识来源（内部/SBOM/扫描）。
- **解决什么问题**：审查时需要看到每条威胁有哪些控制措施去缓解，手维护极易遗漏；以"威胁⇄控制"双向编号串自动反查，威胁/控制改了追溯立刻更新。
- **怎么用**：
  1. 5.3：写残留风险结论文本，残余威胁列表自动从 4.x 各 cybersec_threat 行汇总。
  2. 7：不可手动编辑，只读展示；追溯不准时去 4.x 对应威胁行修 rcm_codes 或在 5.2 RCM 行修 threat_codes。
- **相关功能**：4.x 威胁评估（提供 threat_code 与 residual_*）、5.2 RCM 三类（提供 rcm_code 与 threat_codes 反向链）。
