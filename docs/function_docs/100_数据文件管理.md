# 1. 功能概述

- **用途**：按「产品 + 文档类型 + 文档版本」维护数据侧 Word/Excel，交互与模型文件相同。记录 / 反馈 / 统计表编辑页对齐模型文件训练/测试记录：无左侧章节，单页原表，导出一张 xlsx（不导出封面/修订）。`dd_016` / `dd_017` 编辑页对齐模型文件 `md_019`：无左侧章节，单页资产表 + 只读说明 + 周检表，导出 Word。
- **使用场景**：用户从左侧菜单「数据文件」进入二级分组后再进某一子菜单，对该类型文档建档、改章节、导出。分组按归档：规范、采集记录、人员记录、入库记录、数据资产、设备与环境维护。名称与 `doc_type` 不改。
- **最终目标**：`(product_id, doc_type, version)` 唯一；封面空的编制部门为「数据部」；无独立「产品信息」章，不回写产品主数据。
- **导出格式**：`docx` 走封面→修订→目录→正文；`dd_016` / `dd_017` 按 DEM 式周检表导出；记录 / 统计表 `xlsx` 一张原表（多工作表按原表名，不含封面/修订）；其余 `xlsx` 每章节一张工作表。
- **关联**：引擎与规则对齐 [99_模型文件管理.md](./99_模型文件管理.md)；权限 `data_doc_view` / `data_doc_edit`。`dd_016_qr` / `dd_017_qr` 仍保留类型供旧数据，不出现在菜单（周检表并入对应说明 Word）。

菜单分组（类型名不变；路由仍为 `/data_docs/:type`）：

| 二级导航 | 文档 | doc_type | 格式 |
|----------|------|----------|------|
| 规范 | 数据采集需求、数据标注需求、数据标注规则、标记规则、标注质量评估方法、人员考核评价方法 | `dd_001` / `md_003` / `md_002_01` / `md_002_02` / `dd_006` / `dd_007` | docx |
| 采集记录 | 多中心数据回传记录、数据整理记录、数据采集需求反馈 | `dd_002` / `dd_003` / `dd_004` | xlsx |
| 人员记录 | 人员培训记录 ×2、考核记录 ×7 | `dd_005_01` / `dd_005_02` / `dd_013_01`～`dd_013_07` | xlsx |
| 入库记录 | 试标注 ×2、标注记录 ×3、标注需求反馈、数据库上传记录、查重记录 | `dd_008_01` / `dd_008_02` / `dd_009_01`～`dd_009_03` / `dd_011` / `dd_010` / `dd_012` | xlsx |
| 数据资产 | 数据库维护记录、原始/基础/标注数据库统计表 | `dd_014` / `dd_015_01` / `dd_015_02` / `dd_015_03` | xlsx |
| 设备与环境维护 | 数据设备清单、开发环境维护记录说明、标注环境维护记录说明 | `dd_eq` / `dd_016` / `dd_017` | xlsx / docx（016、017） |

`数据/` 中与 QR 表结构相同的 `DD-016-A0` / `DD-017-A0` 记录 xlsx 不另开类型。旧类型 `dd_016_qr` / `dd_017_qr` 不进菜单。`md_002_01` / `md_002_02` / `md_003` 类型码仍用 MD 编号（与样例 Word 文件编号一致），菜单挂在数据文件；`dd_002` / `dd_003` 仍是 Excel。

大表（标注明细等）只预填表头与少量空行。数据库统计表数字由独立模块「数据统计」生成，见 [101_数据统计.md](./101_数据统计.md)；下载的 Excel 可在 `dd_015_*` 编辑页导入展示。封面/修订仍按第 4 节填空，不从统计模块取。离线脚本 `trace-api/scripts/data_stats/` 仅作备用。

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

菜单「数据文件 → {二级分组} → {类型名}」进入 `/data_docs/{doc_type}`。分组：规范、采集记录、人员记录、入库记录、数据资产、设备与环境维护。规范顺序：采集需求、标注需求、标注规则、标记规则、评估方法、考核评价方法。入库记录顺序：试标、标注、标注需求反馈、上传、查重。设备与环境维护顺序：数据设备清单、开发环境维护记录说明、标注环境维护记录说明。`dd_016_qr` / `dd_017_qr` 不进菜单。类型名称、路由、权限不改。

## 3.1～3.6

与 99 相同：列表 / 新增 / 编辑查看 / 导出 / 复制 / 删除。接口与表名为 `data_doc`。导出按类型 format 输出 docx 或 xlsx。Word 评审表与 99 相同：相邻相同非空格先横向合并，纵向合并首列（该列已横向合并时仍合并）。`dd_015_*` 可导入统计脚本 Excel 替换记录章节。

成功终态：`data_doc` 落库一行；导出不落库。

# 4. 核心规则 & 判定条件

| 编号 | 规则 / 判定条件 | 含义 | 不满足 / 命中时的后果 |
|------|----------------|------|----------------------|
| R1 | `(product_id, doc_type, version)` 唯一 | 同产品同类型不重复版本 | `msg_obj_exist` |
| R2 | 写 `data_doc_edit`，读 `data_doc_view` | 权限 | 无权限拦截，菜单不可见 |
| R3 | `product_manager` 非超管 | 只看自己创建的产品 | 其它产品不出现 |
| R4 | 自动获取仅填空 | 保护手改 | 已填保留；打开或换产品时精确全文替换产品名称 / 型号 / 产品代码（规则同 99）；**切换产品时覆盖封面签署人与日期、修订首行日期/修订人/批准人** |
| R5 | 不回写产品主数据 | 只读来源 | 不影响 `product` |
| R6 | 封面编制部门空则「数据部」 | 与模型文件「模型部」区分 | 用户已填则保留 |
| R7 | 更新忽略 `doc_type` | 类型由菜单锁定 | 不能改类型 |
| R9 | 导入统计 Excel 只替换记录章节 | 保护封面/修订 | 封面、修订保留，其余按工作表重建；不生成「产品信息」章 |
| R10 | 左侧菜单按归档二级分组，组内按依赖/流水；标注规则/标记规则/标注需求挂数据文件 | 规范（DD-001、MD-003、MD-002、DD-006、DD-007）、采集记录（DD-002～004）、人员记录（DD-005、DD-013）、入库记录（DD-008～009、DD-011、DD-010、DD-012）、数据资产（DD-014、DD-015）、设备与环境维护（清单、DD-016、DD-017） | 不改类型名；`md_002_*`/`md_003` 不出现在模型文件菜单 |
| R11 | `dd_016` / `dd_017` 周检与模型文件说明一致 | 菜单只留说明。编辑页无左侧章节，单页：资产表 + 只读说明 + 各资产检查表（样式对齐 `md_019`）。定期检查后有维护记录章。资产编码 ← 该产品最新 `dd_eq` 组装机/Apple（跳过显示器；`dd_016` 用途含「开发」，`dd_017` 用途含「标注」）。用途含「共用」=服务器，否则开发机/标注机。周日期 ← 时间线「产品开发」（不含计划）到「测试」的周一～周五。检查人 ← 「数据部负责人」否则「数据负责人」否则角色含「数据」（签字图否则姓名）。默认勾选：更新升级/日志是否错误=否，其余=是 | 打开详情/换产品/导出覆盖资产编码（同编码保留设备信息）及周次与检查人；无清单不改资产表；无该时间线则提示暂无周记录 |
| R12 | 记录 / 反馈 / 统计表 / 设备清单单页原表 | `dd_002`～`dd_004`、`dd_005_*`、`dd_008_*`、`dd_009_*`、`dd_010`～`dd_012`、`dd_013_*`、`dd_014`、`dd_015_*`、`dd_eq`。编辑页无左侧章节，只展示原表（跳过封面/修订/产品信息）；标题/文件编号通栏合并居中，数据格居中。旧章节树打开时抽出记录表。导出一张 xlsx 对齐原表（标题通栏合并居中），不导出封面/修订。`dd_015_*` 仍可导入统计 Excel 只替换记录表 | 打开即见原表；导出不含封面/修订 |
| R13 | `dd_001` 封面编制人/审核人 | 编制人←模型负责人否则模型部负责人否则角色含「模型」；审核人←固定沈宏（签名图否则姓名）；批准人仍←研发负责人 | 新增/打开空格/换产品/导出按此带出；其它数据文件仍按第 4 节默认 |
| R14 | 需求/规则/方法 Word 封面编制人/审核/批准 | `md_002_01` / `md_002_02` / `md_003` / `dd_006` / `dd_007`：编制人←模型负责人否则模型部负责人否则角色含「模型」；审核人、批准人←固定沈宏 | 新增/打开空格/换产品/导出按此带出 |
| R16 | `dd_006`「评估流程」2.1～2.5 是正文 | 源 Word 为 Normal，不是 Heading。模板写入「评估流程」正文；打开已存文档时若子章正文/表都空则折回正文（已手写不改） | 目录不再出现 2.1～2.5 子节 |

修订首行、文件编号规则同 99（关键字取该类型名称）。无独立「产品信息」章（打开/新增/导出去掉）。原 Word 有「附件 1 评审记录」表的类型（`dd_001`、`md_003`），附件为空则按原表补上；误挂在其它章节的评审表挪回附件。打开或换产品时，章节标题 / 正文 / 表格对产品名称、型号、产品代码做精确全文替换（模板基准名「肺栓塞CT图像辅助评估软件」、型号「IR-CT-PE」换成当前产品；换产品时再把原产品字段整段换成新产品）。签名图不替换。不按疾病词或模块名做模糊匹配。**切换产品时覆盖封面编制人/审核人/批准人及日期、生效日期，以及文件修订记录首行修改日期/修订人/批准人**（编制人←数据部负责人否则数据负责人否则角色含「数据」；审核人←角色含「模型」；批准人/修订批准人←研发负责人；封面日期为 `yyyy.MM.dd`；修订日期为 `YYYY年M月D日`）。**`dd_001` 数据采集需求例外**：编制人←模型负责人否则模型部负责人否则角色含「模型」；审核人←固定沈宏（有签名图用图，无图用姓名）；批准人/修订批准人仍←研发负责人；修订人跟编制人。**`md_002_01` / `md_002_02` / `md_003` / `dd_006` / `dd_007` 例外**：编制人←模型负责人否则模型部负责人否则角色含「模型」；审核人、批准人、修订批准人←固定沈宏；修订人跟编制人。编制部门、文件版本、修订说明不因换产品改写。
