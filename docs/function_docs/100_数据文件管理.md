# 1. 功能概述

- **用途**：按「产品 + 文档类型 + 文档版本」维护数据侧 Word/Excel，交互与模型文件相同。记录 / 反馈 / 统计表编辑页对齐模型文件训练/测试记录：无左侧章节，单页原表，导出一张 xlsx（不导出封面/修订）。`dd_016` / `dd_017` 编辑页对齐模型文件 `md_019`：无左侧章节，单页资产表 + 只读说明 + 周检表，导出 Word。
- **使用场景**：用户从左侧菜单「数据文件」进入二级分组后再进某一子菜单，对该类型文档建档、改章节、导出。分组按归档：规范、采集记录、人员记录、入库记录、数据资产、设备与环境维护。名称与 `doc_type` 不改。
- **最终目标**：`(product_id, doc_type, version)` 唯一；封面空的编制部门为「数据部」；无独立「产品信息」章，不回写产品主数据。
- **导出格式**：`docx` 走封面→修订→目录→正文；`dd_016` / `dd_017` 按 DEM 式周检表导出；记录 / 统计表 `xlsx` 一张原表（多工作表按原表名，不含封面/修订）；其余 `xlsx` 每章节一张工作表。
- **关联**：引擎与规则对齐 [99_模型文件管理.md](./99_模型文件管理.md)；权限 `data_doc_view` / `data_doc_edit`。`dd_016_qr` / `dd_017_qr` 仍保留类型供旧数据，不出现在菜单（周检表并入对应说明 Word）。

菜单分组（类型名不变；路由仍为 `/data_docs/:type`）：

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

菜单「数据文件 → {二级分组} → {类型名}」进入 `/data_docs/{doc_type}`。分组：规范、采集记录、人员记录、入库记录、数据资产、设备与环境维护。规范顺序：采集需求、标注需求、标注规则、标记规则、评估方法、考核评价方法。入库记录顺序：试标、标注、标注需求反馈、上传、查重。设备与环境维护顺序：数据设备清单、开发环境维护记录说明、标注环境维护记录说明。`dd_016_qr` / `dd_017_qr` 不进菜单。类型名称、路由、权限不改。

## 3.1～3.6

与 99 相同：列表 / 新增 / 编辑查看 / 导出 / 复制 / 删除。接口与表名为 `data_doc`。导出按类型 format 输出 docx 或 xlsx。Word 评审表与 99 相同：相邻相同非空格先横向合并，纵向合并首列（该列已横向合并时仍合并）。`dd_015_*` 可导入统计脚本 Excel 替换记录章节。

成功终态：`data_doc` 落库一行；导出不落库。
