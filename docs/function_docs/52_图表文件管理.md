# 产品图示（拓扑图 / 结构图 / 界面关系图 / 流程图）

## 1. 功能概述

按产品维护四类图表文件，并与 SRS/SDS 文档节点双向联动。四类共用 `serv_doc_file`，路由前缀不同。

| 类型 | category | 路由前缀 | 查看权限 | 编辑权限 |
|------|----------|----------|----------|----------|
| 物理拓扑图 | img_topo | `/doc_file/img_topo` | doc_file_topo_view | doc_file_topo_edit |
| 体系结构图 | img_struct | `/doc_file/img_struct` | doc_file_struct_view | doc_file_struct_edit |
| 用户界面关系图 | img_ui | `/doc_file/img_ui` | doc_file_ui_view | doc_file_ui_edit |
| 网络安全流程图 | img_flow | `/doc_file/img_flow` | doc_file_flow_view | doc_file_flow_edit |
| 主页面图示 | img_home | `/doc_file/img_home` | doc_file_home_view | doc_file_home_edit |

---

## 2. 用户操作流程

选产品 → 列表（可自动回填）→ 上传 png/jpg → 编辑/删除/下载 → 批量删除。

> **文档版本固定 A0**：新增弹窗不显示「文档版本」输入项，提交时固定写 `A0`；编辑弹窗同样不显示该输入项，仅允许换图。接口传入非 A0 的文档版本会被拒绝。

> **唯一性**：同产品 + 同图表类型只允许一条记录（文档版本固定 A0），重复新增返回「该产品此图表类型已有图示（文档版本固定 A0），请编辑或删除后再添加」。

> **主页面图示（img_home）** 不在左侧菜单单独展示，主要供产品技术要求·附录2 上传/取图使用，操作流程与其他四类相同。

---

## 3. 前端实现

- 页面：`pages/doc_file/DocFiles.tsx`（prop `fileType`）
- API：`api/ApiDocFile.ts`，动态路径 `/trace-api/doc_file/${fileType}/...`
- 新增/编辑弹窗只有「产品 + 文件」两项，不渲染文档版本输入框，提交时 `doc_version` 固定为 `A0`。

---

## 4. 后端接口（每类相同形态）

| 方法 | 路径 | 入参 |
|------|------|------|
| POST | `.../add_doc_file` | Form: product_id, file（doc_version 固定 A0，传其它值报错） |
| POST | `.../update_doc_file` | Form: id, product_id?, file?（不可改文档版本，换图后仍按 A0 命名） |
| DELETE | `.../delete_doc_file` | id |
| GET | `.../list_doc_file` | product_id, file_name, doc_version, product_name, product_version, 分页 |
| GET | `.../get_doc_file` | id |

另：`POST /doc_file/read_excel`（**无 perm**，UploadFile）→ List[Table]，供 SRS 等导入使用。

---

## 5. 数据库表

`doc_file`：product_id, category, file_name, file_size, file_url。文档版本不单独建列，写入 `file_name`：`{product_version}_{doc_version}_{category}.ext`。文件落盘 `data.trace/{category}/{id}{ext}`，静态挂载 `/data.trace`。

---

## 6. 关键业务逻辑与规则

### 6.1 列表自动回填（list_doc_file）
- **img_flow**：只从详细设计 **A0** 按关键词/同级结构匹配流程图。A1、A2 及以后的详细设计不回填、不新建图示。
- **img_topo / img_struct**：只从需求规格说明 **A0** 的章节 2.2/2.3 或 ref_type 回填。A1、A2 及以后的需求文档不回填、不新建图示。无图节点不覆盖；已有同版本手工上传不覆盖（其它版本有图不挡本版本回填）。节点 `img_url` 带缓存参数时按去参后的落盘路径取图。

### 6.2 上传/更新后反向同步
- `__sync_doc_nodes_from_doc_file`：反向写该产品**所有版本**的 SRS/SDS 节点 `img_url`（img_topo→SRS 2.2，img_struct→SRS 2.3，img_flow→SDS）。产品图示每类只有一张，换图后 A0、A1、A2、A3 等版本一起换，不再只改同版本。
- 文档版本为 A1 及以后时，img_topo / img_struct / img_flow 的新增、更新和反向写入对应文档都拒绝。Word 导入非 A0 的需求文档不把拓扑图、结构图写入产品图示；非 A0 的详细设计也不把网络安全流程图写入产品图示。详细设计、概要设计里不能更换物理拓扑图和系统结构图。

### 6.3 命名与唯一性
- `{product_version}_{doc_version}_{category}.ext`；列表可按 doc_version 模糊匹配 file_name。
- `pick_doc_image_file_row` 优先按 `doc_version` 匹配文件名；匹配不到时**回退到本产品该类型的当前图**（每类只有一条，版本固定 A0），保证 A1/A2/A3 等版本文档也能取到产品图示。
- 新增/编辑均不填文档版本：前端固定提交 `A0`，后端也强制为 `A0`，传入其它版本直接报错。
- 唯一性：同产品 + 同类型只允许一条（版本固定 A0）。历史行即使文件名里没有 A0 或解析不出文档版本，也视为已占用名额，不允许再叠加。
- 新增必须带文件，无文件直接报「请选择文件」。
- 编辑可换图、可改所属产品；若改到另一个产品且该产品下同类型已有图示则拒绝。
- 列表/详情解析出的文档版本若等于产品完整版本（从技术要求等入口上传、未带 SRS 版本时会出现），视为未填写，显示为空。
- img_topo / img_struct / img_ui / img_home 文档版本取该产品 **SRS** 版本；img_flow 取 **SDS** 版本；实际存库统一为 `A0`。

### 6.4 权限范围
- 五类图表列表**未选产品时显示全部产品**（不按 prod_user 过滤）；非图表 category 才按用户产品过滤。

---

## 7. 边界与特殊处理

- 下载：`window.open('/'+file_url)`。
- 前端展示文件名重格式化为「产品名_图类型.扩展名」。
- `read_excel` 无权限校验（通用导入工具）。
- 历史同产品同类型的重复图（如 2.0.0.3 下有两条拓扑图）不自动清理，仅阻止继续新增；需要清理请单独删行并同步删除磁盘文件。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **五类共用 serv_doc_file，仅 category/路由前缀不同**，改一类逻辑会影响五类。
2. **图片与文档节点双向联动**（列表回填 + 上传反写 img_url）不可破坏。
3. **img_flow 取 SDS、img_topo/struct/ui/home 取 SRS** 的来源区分不可混。
4. 「无图节点不覆盖手工上传」的保护逻辑不可移除。
5. `read_excel` 无 perm 是有意为之，改动需评估调用方。
6. 唯一性校验走 `__find_same_version_doc_file(product_id, category, exclude_id)`，不要改成按 file_name 前缀匹配，否则历史行会漏判。
