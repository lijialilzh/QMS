# 现场测试规程管理（FTR）

## 1. 功能概述

管理现场测试规程（测试文件 VV-006），PDP 风格章节树结构，与软件测试计划（STP）结构一致。用于记录产品在现场环境下的测试规程文档，属于质量管理体系中的测试文件。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 自动获取章节（产品信息/时间线/参与人员）→ 导出 docx。

---

## 3. 前端实现

- 页面：`pages/ftr/FtrDocs.tsx`（列表）、`FtrDocDetail.tsx`（详情/编辑）
- API：`api/ApiFtrDoc.ts`

## 6. 关键业务逻辑与规则

1. content 为 JSON 格式 `{"sections": [...]}`，每个 section 是树形节点（title/body/tables/children）。
2. 自动填充：产品名称替换、文件修订记录（日期/版本/修订人/批准人）、运行环境（从 ProdRuntimeEnv `tables_json` **整表覆盖** 4 张表，含增删行列后的结构）、封面日期/签署人。封面按测试文件：编制人 ← 测试人员（2025.09 前「宋月」，其后取参与人员中角色含「测试人员」的第一人），审核人、批准人 ← 研发负责人；有签名图用图，没有则用姓名。打开即覆盖，不沿用产品经理/产品负责人。文档内运行环境表只读；章节标题可改、章节可删。章节树通用表格列宽按内容自适应，编号等短列收窄。
3. **1.2 范围**：打开/换产品时按当前产品自动写入正文——产品名称←`name`、完整版本←`full_version`、末行「该测试覆盖了{产品名称}全部功能测试。」；有产品型号（`type_code`）则写入「产品型号：…」，无型号则不显示该行。自动获取后正文只读（不可改、不显示添加正文/上传图片/添加表格）；章节标题仍可改、章节可删。
4. **文件修订记录**：修订人 ← 测试人员日期规则（2025.09 前「宋月」、之后「孙家旭」，打开即覆盖）；批准人 ← 研发负责人。
5. **运行环境表名**：自动获取时写入 `table_captions`（如「表1 服务器硬件配置要求」），编辑页「表格上方说明/表名」展示。
6. **功能测试用例表**：统一为两列 Word 布局——序号/用例标题/功能描述/系统设置为「标签|值」；下一行「执行步骤|预期结果」（标签加粗、**无表头底色**）；再下一行步骤与预期内容。编辑页与导出一致：首行不加 `.head` 背景；标签列与「执行步骤|预期结果」行文字加粗。旧三列重复格式打开时归一。
7. 复制逻辑：同产品版本递增（A0→A1），跨产品取目标产品最大版本递增。
8. 切换产品（rebind_product）：删除旧记录，重置 content 为默认模板，强制重新自动填充。
9. 导出使用 python-docx 生成 Word，含封面/修订记录/目录/正文章节；正文与表格交错、表名（`table_captions`）、功能测试用例表样式与编辑页一致（静默占位不写入 Word；用例表标签加粗、无表头底色）。
10. 评审记录页面与需求规格说明一致：只读合并表，点右侧「编辑」弹出表格编辑，确认后写回；点「删除」去掉该表。编辑弹框里，参评人员签字、评审时间、评审结论、批准人员签字这些只在第一格有内容的行合并成一格。查看页不显示编辑和删除。参评人员从该产品参与人员覆盖。测试负责人多人时有宋月用宋月，没有宋月用孙家旭。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. content(JSON) 的 sections 树结构不可改变。
2. 自动填充逻辑（__autofill）不可破坏。
