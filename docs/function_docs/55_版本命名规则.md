## 1. 功能概述

「基础数据 → 版本命名规则」展示软件版本号（`VX.Y.Z.B`）命名规范，**全局单条、所有人共享**。

- 居中卡片布局（灰底 + 白卡），与「运行环境」页风格一致。
- **文字内容可编辑、失焦自动保存**：版本格式（发布版本 / 完整版本）、顶部说明、X/Y/Z/B 各项标题与说明、底部说明。
- **示意图（X.Y.Z.B 拆解箭头图）固定**，由前端 SVG 渲染，不可编辑。
- 全局唯一一条配置记录（`version_rule` 表固定 `id=1`），任意有编辑权限者修改后对所有人生效。

---

## 2. 前置依赖 & 关联模块

- 菜单：「基础数据 → 版本命名规则」`/version_rule`（菜单不限权限，登录即可查看）。
- 接口：`GET /version_rule/get_version_rule`（无权限校验，登录可读）、`POST /version_rule/save_version_rule`（需 `version_rule_edit`）。
- 权限：编辑权限 `version_rule_edit`，默认授予 root/dqa/qa（`all_perms`）。无该权限者页面为只读（输入禁用、顶部提示「只读」）。
- 前端权限判断：读取 `store.user.role_perms` 是否含 `version_rule_edit`。

---

## 3. 完整执行流程

1. 进入页面 `load()` → `get_version_rule`：有记录返回库内内容，无记录返回后端默认值 `DEFAULT_VERSION_RULE`。
2. 有编辑权限时，直接在各文字框修改；**失焦（onBlur）时若内容有变更即整体 `save_version_rule`**（提交完整 `content`），保存中显示「保存中…」。
3. 无编辑权限：所有输入禁用，仅可查看。

---

## 4. 核心规则 & 判定条件

- `get_version_rule`：`content` 非字典或无记录时回落默认值；正常时经 `__normalize` 规范化字段。
- `save_version_rule`：先 `__normalize`，再 upsert 固定单行（`id=1`，存在则更新、不存在则插入）；缺 `version_rule_edit` 由 `try_log` 拦截返回 `msg_no_perm`。
- 前端 `save` 仅在 `JSON.stringify(form) !== snapshot` 时发起，避免无变更请求；保存成功后刷新 `snapshot`。

---

## 5. 数据结构说明

表 `version_rule`（全局单行）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 固定为 1 |
| content | JSON | 版本命名规则文字内容 |

`content` JSON 结构：

```
content = {
  "release_format": str,        # 发布版本格式，如 VX
  "full_format":    str,        # 完整版本格式，如 VX.Y.Z.B
  "note_top":       str,        # 示意图下方说明
  "items": [                    # X/Y/Z/B 各项
    { "code": str, "title": str, "desc": str }, ...
  ],
  "note_bottom":    str         # 底部说明
}
```

---

## 6. 异常场景 & 兜底逻辑

- 无记录 / `content` 非法：返回 / 回落 `DEFAULT_VERSION_RULE`，页面正常展示默认规范。
- 无编辑权限点击保存：后端返回 `msg_no_perm`（前端输入已禁用，正常不会触发）。
- 数据库异常：后端 `rollback` 返回 `msg_err_db`，前端 `message.error` 提示。

---

## 7. 功能约束 & 修改红线

1. 全局单条配置，不区分产品 / 用户；固定 `id=1`。
2. 仅文字内容可编辑，示意图（SVG）固定不参与存储。
3. 编辑写操作受 `version_rule_edit` 约束；读取不限权限。
