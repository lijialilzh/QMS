# 功能描述管理（第 7 章 / srs_reqd）

## 1. 功能概述

第 7 章「功能描述」为每条需求维护一份 KV 详情（需求编号/名称/概述/主参加者/前置条件/触发器/工作流/后置条件/异常情况/约束），存于 `srs_reqd` 表（与 `srs_req` 1:1）。章节结构按 module→function→sub_function 自动生成。

---

## 2. 用户操作流程

- **主入口**：树内功能描述 KV 表（两列：字段名|值）编辑保存 → `handleSaveReqDetailTable`。
- **弹窗列表**：编辑页「需求列表」Modal（`list_srs_reqd` 展示）。
- 遗留页 `SrsReq.tsx` 未注册路由。

---

## 3. 前端实现

| 项 | 说明 |
|----|------|
| `isFunctionalKvTable` | 识别 KV 表（≥3 个标准字段标签） |
| `handleSaveReqDetailTable` | 保存：`add_srs_reqd` 或 `update_srs_reqd`（重复时 fallback update） |
| `syncSrsReqDetailsByKey` | 第 7 章按需求明细重建 module/function 层级与功能描述节点 |
| 字段标签 | 需求编号/名称/概述/主参加者/前置条件/触发器/工作流/后置条件/异常情况/约束 |

---

## 4. 后端接口

| 方法 | 路径 | 入参 |
|------|------|------|
| GET | `/srs_reqd/list_srs_reqd` | product_id, doc_id, 分页 |
| GET | `/srs_reqd/get_srs_reqd` | req_id |
| POST | `/srs_reqd/add_srs_reqd` | SrsReqdForm{doc_id, code, name, ..., rcm_ids} |
| POST | `/srs_reqd/update_srs_reqd` | SrsReqdForm{req_id, ...} |
| DELETE | `/srs_reqd/delete_srs_reqd` | req_id |

---

## 5. 数据库表

`srs_reqd`（`req_id` 唯一，1:1 srs_req）。详见 [01_数据库表结构.md](./01_数据库表结构.md)。

---

## 6. 关键业务逻辑与规则

1. `add_srs_reqd`：先建 `SrsReq(type_code="reqd")`，再建 `SrsReqd`；若已绑定 SDS 则插 `sds_reqd`。
2. `list_srs_reqd`：
   - **排除 `type_code=2`**（其他需求不进功能描述）。
   - `name` 优先取 `srs_req.sub_function / function / module`。
   - 空字段从 `srs_node` KV 表补齐（`__query_reqd_from_nodes`）。
3. 第 7 章自动生成：`syncSrsReqDetailsByKey` 按标准+变更需求明细重建层级与功能描述节点。
4. 删除变更需求/code 时联动清理第 7 章（详见 [25_变更需求表管理.md](./25_变更需求表管理.md)）。

---

## 7. 边界与特殊处理

- 功能描述 `name` 以 `srs_req` 主表 module/function/sub_function 为准，**非** `srs_reqd.name`。
- 第 7 章节点用 `__auto_req_detail` / `__auto_req_group` 标记。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **`add_srs_reqd` 先建占位 `srs_req(type_code="reqd")`** 的两步流程不可拆开。
2. **`list_srs_reqd` 排除 type_code=2** 不可改。
3. **name 来源优先级**（sub_function → function → module）不可改为取 srs_reqd.name。
4. 第 7 章 `__auto_*` 标记与自动生成逻辑是删除联动的基础，不可破坏。
5. `intput` 等历史字段名（在 SDS 侧）不要在此处误改。
