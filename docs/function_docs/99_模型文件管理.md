# 1. 功能概述

- **用途**：按「产品 + 文档类型 + 文档版本」维护模型侧文档（DHF 之一类），提供新增 / 编辑 / 导出 / 复制 / 删除。一般类型交互与产品文件（产品立项报告）一致：列表筛选、章节树编辑、封面 4 列、修订记录。`md_deq` / `md_teq` / `md_eq` 为单表设备清单，交互对齐开发文件 DEQ。`md_019` / `md_020` 编辑页对齐开发文件 DEM：无左侧章节，单页资产表 + 只读说明 + 周检表。`md_008_01` / `md_008_02` 编辑页对齐开发文件 CRR：无左侧章节，导出 Word。`md_009_*` / `md_010_*` / `md_011_*` 构建记录、`md_012_*` 训练记录编辑页对齐审查记录：无左侧章节，单页原 Word 表，导出 Word。`md_013_*` 测试记录、`md_015_*` 封装需求、`md_016` 封装记录、`md_018` 提交记录编辑页同样无左侧章节、单页原表，导出 Excel。
- **使用场景**：用户从左侧菜单「模型文件」进入二级分组后再进某一子菜单，对该类型文档建档、改章节、导出。分组：计划与需求、方案设计、审查、构建与训练、测试、封装与提交、配置与追溯、设备与环境维护。
- **最终目标**：同一产品下每种 `doc_type` 可有多个版本；`(product_id, doc_type, version)` 唯一；封面空的编制部门为「模型部」；无独立「产品信息」章，不回写产品主数据。
- **导出格式**：`DOC_META.format` 为 `docx`（默认）时导出 Word；`md_008_*` 按代码审查 Word 模版（抬头+检查表+结论+签字）；`md_009_*` / `md_010_*` / `md_011_*` 按构建记录原表；`md_012_*` 按训练记录原表（信息格+评估曲线+过程曲线+结论+签字）；`md_013_*` 按测试记录原表导出 Excel（信息格+测试环境+测试结果+结论+签字）；`md_015_*` / `md_016` / `md_018` 按封装需求/封装记录/提交记录原表导出 Excel；一般 Word 为封面→修订→目录→正文。为 `xlsx` 时导出 Excel（设备清单一类一张表；测试记录/封装需求/封装记录/提交记录一张原表；其余每章节一张工作表，含表格）。
- **范围**：22 份 Word + 9 份 Excel 菜单共用单表 `model_doc`。`md_019_qr` / `md_020_qr` 仍保留类型供旧数据，不出现在菜单（周检表并入对应说明 Word）。`md_002_01` / `md_002_02` / `md_003` 已归入数据文件，见 [100_数据文件管理.md](./100_数据文件管理.md)。
- **关联上下游**：上游读取产品主数据、产品 DHF 文件编号、时间逻辑线、参与人员、人员签名；下游无写回。不改动产品文件封面（产品部）及其它已有文档模块。

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

1. 菜单「模型文件 → {类型名}」进入 `/model_docs/{doc_type}`。
2. 数据文件入口见 [100_数据文件管理.md](./100_数据文件管理.md)。

## 3.1 步骤 1：列表查询

- **动作**：进入列表或点搜索。
- **入参**：`product_id`（可选）、`version`（可选模糊）、`doc_type`（路由类型，必填）、分页。
- **内部逻辑**：`list_model_doc` 按 `doc_type` 过滤；`product_manager` 且非超管仅能看到自己创建产品下的文档。
- **数据变化**：无写库。
- **调用链路**：`ModelDocs.doSearch` → `/list_model_doc` → `serv_model_doc.list_model_doc`。
- **页面表现**：表格展示产品名称、完整版本、文档版本、文件编号、变更说明、创建时间。

## 3.2 步骤 2：新增

- **动作**：点「新增」，选产品、填文档版本（默认 A0）、文件编号、变更说明。
- **入参**：`product_id`、`version`、`file_no`、`change_log`、`doc_type`。
- **内部逻辑**：`(product_id, doc_type, version)` 已存在则失败；`content` 取该类型模板树；空 `file_no` 按 DHF 名称关键字匹配。
- **数据变化**：插入 `model_doc` 一行。
- **调用链路**：`add_model_doc` → 跳转 `/model_docs/{type}/edit/{id}`。
- **页面表现**：进入编辑页；一般类型左侧为该类型默认章节；训练记录等单页类型无左侧章节。

### 分支 2A：版本已存在
- 走向：返回 `msg_obj_exist`，不跳转。
### 分支 2B：`doc_type` 非法
- 走向：返回参数错误，不建档。

## 3.3 步骤 3：编辑 / 查看

- **动作**：编辑页改章节树、正文、表格；工具栏可改产品与文档版本；查看页只读。
- **入参**：`id`；保存时 `content`、`product_id`、`version`（剥离 `_key`）。
- **内部逻辑**：进入或刷新时自动填充（见第 4 节规则，仅填空）；保存 `update_model_doc`，忽略入参 `doc_type`。
- **数据变化**：更新该行 `content` / `product_id` / `version` 等传入字段。
- **调用链路**：`get_model_doc` → 前端 `autofill`；保存 `update_model_doc`。
- **页面表现**：左侧目录、右侧标题/正文/表格；查看页禁用输入，仅可导出。全部模型 Word/Excel 无独立「产品信息」章（打开/新增/导出时去掉）。原 Word 有「附件 1 评审记录」表的类型，附件为空则按原表补上；误挂在其它章节的评审表挪回附件。`md_001`：「范围」正文首行「产品名称：」（空则带出产品名称，不做表）；「配置管理工具」仅正文、无表；「标识配置」两张 SCI 清单；「版本更新原则」工具类型表；评审记录表在「附件 1 评审记录」。打开已存 `md_001` 时把误挂表挪回对应章节，「范围」产品名称表并入正文。`md_006`：「参考文件 / 文档目的 / 文档范围 / 项目简介」无表；人员表在「人员资源」，设备表在「开发平台」，里程碑表在「项目开发计划及里程碑」；打开已存文档时把误挂表挪回。「项目开发时间」按模型开发阶段到封装/提交的日历天数写成「共用时约N天。」。`md_007`：三个模块下「算法基本信息」为原文两列表（末行算法流程图含图）；一级「算法基本信息」补图 1；「模块设计描述」补图 2～6 及立方体示意图。空表/空图才填。编辑页算法流程图与独立插图可更换本地图片。`md_014`：术语及缩略语、肺栓塞分诊测试数据/影响因素、肺叶分割测试数据/测试结果按原 Word 表回填，空表才补。其余模型 Word：原文有表的章节（性能测试环境/人员/结果、配置管理 SCI 清单、可追溯性表、开发/测试环境资产表等）同样空表才补。`md_022`「模型可追溯性分析表」打开/换产品/导出时按当前产品文件编号覆盖 ID 列（见 R20）。`md_001` / `md_004`「附件 1」不编号。首格含「评审记录」的表格按 Word 合并格展示与编辑。

### 分支 3A：切换产品
- 走向：前端 `rebindProduct` 按新产品覆盖：封面「编制人/审核人/批准人」及对应日期、生效日期；「文件修订记录」首行修改日期/修订人/批准人；`md_001`「范围」正文「产品名称：」；`md_017`「测试人员」资源数量/具体人员；`md_022` 可追溯性表 ID；`md_008_*` 检查日期/被审核人/审核人。章节标题 / 正文 / 表格对产品名称、型号、产品代码做**精确全文替换**（原产品字段 → 新产品字段；模板基准名「肺栓塞CT图像辅助评估软件」、型号「IR-CT-PE」同步换成当前产品）。不做模糊匹配（如不把「肺栓塞分割模块」里的疾病词单独替换）。编制部门、文件版本、修订说明不因换产品改写。点保存后 `product_id` 落库。若目标产品已有同类型同版本则保存失败 `msg_obj_exist`。

## 3.4 步骤 4：导出 Word

- **动作**：列表或详情点「导出」。
- **入参**：`id`。
- **内部逻辑**：先 `__autofill_for_export`（仅填空；`md_001` / `md_006` 同步纠偏误挂表格，`md_007` 补算法基本信息表与图，各 Word 类型按模板补空章节表；`md_006` 人员、`md_017` 测试人员、`md_022` 可追溯性 ID 覆盖），再渲染。一般 Word：封面（4 列，生效日期行合并）→ 分页 → 修订记录 → 分页 → 目录域 → 分页 → 正文（Heading + 加粗）。`md_012_*` 按训练记录原表（信息格 + 评估曲线图 + 过程曲线图 + 结论 + 签字），封面/修订不进编辑页。首格含「评审记录」的表格按 Word 合并：相邻相同非空格先横向合并，纵向合并首列（该列已横向合并时仍合并）。页眉为 `file_no`。算法流程图与独立插图按图幅导出，签名格仍为小图。
- **数据变化**：不落库。
- **调用链路**：`export_model_doc`。
- **页面表现**：下载 `{文档中文名}-{时间戳}.docx`。

## 3.5 步骤 5：复制

- **动作**：选目标产品（默认当前产品）。
- **内部逻辑**：保留 `doc_type`；同产品在原版本号递增；跨产品按目标产品该类型最大版本递增；冲突继续递增；深拷贝 `content`。
- **成功终态**：新记录出现在对应类型列表。

## 3.6 步骤 6：删除

- **动作**：单条或批量删除，物理删除该行。

# 5. 数据结构说明

表 `model_doc`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）：

| 字段 | 所属（表/对象/状态） | 含义 | 默认值 | 取值范围 | 流转规则（谁写、谁读、何时变化） |
|------|---------------------|------|--------|----------|-------------------------------|
| id | model_doc | 主键 | 自增 | 正整数 | 新增写入 |
| product_id | model_doc | 产品 | 必填 | 已有产品 | 新增/编辑可改 |
| doc_type | model_doc | 文档类型 | 必填 | 上表 22 个 Word key + 9 个菜单 Excel key（另可有旧 `md_019_qr` / `md_020_qr`） | 仅新增写入 |
| version | model_doc | 文档版本 | 必填，默认 A0 | 字符串 | 新增/编辑可改 |
| file_no | model_doc | 文件编号 | 可空，可 DHF 带出 | 字符串 | 列表单击保存或新增填写 |
| change_log | model_doc | 变更说明 | 可空 | 字符串 | 新增填写 |
| content | model_doc | 章节树 JSON | 类型模板 | 见下 | 编辑保存 |

一般类型 `content = { "sections": [ node, ... ] }`，`node` 含 `title` / `body` / `tables` / `children` / 可选 `ref_type`（`cover` / `revision`）。无独立「产品信息」章。封面 4 列：编制部门/文件版本、编制人/日期、审核人/日期、批准人/日期、生效日期。非法 `content` 回落该类型模板；旧封面「使用部门/版本号/编写部门」迁移为编制部门+模型部+文件版本。

`md_deq` / `md_teq` / `md_eq`：`content = { "rows": [ header, ...data ] }`，10 列：序号、名称、规格型号、品牌、资产编码/SN码、类别、用途、地点、使用人、状态。旧章节树打开时抽出含「序号+资产编码」的表。

`md_008_01` / `md_008_02`：`content = { code_url, check_date, auditee, auditor, basis, method, checklist, conclusion, sign_img, sign_date }`。旧 7 列 Excel 章节树打开时抽出。

`md_009_01` / `md_009_02` / `md_010_01` / `md_010_02` / `md_011_01` / `md_011_02`：`content = { author, write_date, data_use, data_type, method, case_count, annotator, dist_rows, author_sign, auditor_sign }`。`dist_rows` 为 4 列（因素/类别/数量/占比）。旧 Excel 章节树打开时抽出。

`md_012_01` / `md_012_02`：`content = { author, write_date, auditor, model_name, model_func, train_set, case_count, train_time, hw_env, sw_env, eval_points, process_points, conclusion, author_sign, auditor_sign, eval_img, process_img }`。`eval_points`：`md_012_01` 为 3 列（训练数据量/灵敏度/特异度），`md_012_02` 为 2 列（训练数据量/DICE）。`process_points` 为 2 列（step/loss）。`eval_img` / `process_img` 为 echarts 生成的 `data:image` PNG。旧 Excel 章节树打开时抽出。

`md_013_01` / `md_013_02`：`content = { author, write_date, auditor, model_name, test_set, method, test_time, hw_env, sw_env, result_rows, conclusion, author_sign, auditor_sign }`。`result_rows`：`md_013_01` 为 6 列（因素/类别/阳性数据量/阴性数据量/灵敏度(95%CI区间)/特异度(95%CI区间)），`md_013_02` 为 5 列（因素/类别/样本量/dice均值/dice方差）。旧 Excel 章节树打开时抽出。

`md_015_01` / `md_015_02`：`content = { model_func, param_url, consistency_url, code_url, submitter_sign, auditor_sign }`。旧 Excel 章节树打开时抽出。

`md_016`：`content = { model_func, pack_code_url, param_url, consistency_data_url, consistency_result_url, conclusion, packer_sign, auditor_sign }`。旧 Excel 章节树打开时抽出。

`md_018`：`content = { author, write_date, auditor, model_func, submit_model, test_conclusion, code_url, param_url, consistency_data_url, consistency_result_url, author_sign, auditor_sign, approver_sign }`。旧 Excel 章节树打开时抽出。

数据流向：模板 → 新增落库 → 编辑页读详情并填空 → 用户改树 → 保存 `content` → 导出再填空后渲染 Word。

# 6. 异常场景 & 兜底逻辑

| 场景 | 触发条件 | 系统处理 / 兜底 | 用户提示文案 |
|------|----------|----------------|--------------|
| 版本重复 | 同产品同类型同版本已存在 | 不写库 | `msg_obj_exist` |
| 详情不存在 | id 无效 | `msg_obj_null`；导出空白 docx | 前端 `message.error` |
| 类型非法 | `doc_type` 不在本文清单 | 拒绝新增 | 参数错误 |
| 自动获取源空 | 无时间线/人员/产品字段 | 对应格保持空 | 无报错 |
| 保存/导出失败 | 数据库或网络异常 | rollback / 前端错误提示 | `msg_err_db` 或「导出失败」 |
| 无权限 | 缺 view/edit | 拦截 | `msg_no_perm` |
| 数据文件 | 进入占位页 | 不调模型接口 | 文案：数据文件将在后续批次接入 |

# 7. 功能约束 & 修改红线

## 7.1 允许修改范围

- 本功能文档；`01_数据库表结构.md` 的 `model_doc` 表；`trace-api` 的 `model_doc` 模型/对象/服务/接口及 `serv_review_util` 中模型部门与关键字登记；`tobj_role` 权限与默认角色集合。
- 前端 `pages/model_doc/*`、`api/ApiModelDoc.ts`、`Home.tsx` 菜单、`index.tsx` 路由、i18n、`Roles.tsx` / `Users.tsx` 模块匹配。

## 7.2 绝对禁止改动（红线）

- 禁止改产品文件及其它已有模块的封面编制部门、自动获取规则、表结构。
- 禁止回写 `product` / 时间线 / 参与人员。
- 禁止改 `src/store/`、`src/common/`、`src/utils/base/`。
- 禁止把模型文件拆成多套独立表/服务；必须单表 `model_doc` + `doc_type`。
- 禁止自动获取覆盖已填单元格。

## 7.3 禁止新增逻辑

- 不得新增本文未列出的 `doc_type`、字段、接口。
- 不得把 Excel 拆成独立表；仍走 `model_doc`。
- 文档集成导出收录不在本文范围。

## 7.4 禁止重构结构

- 不得整文件重写立项报告等既有模块；不得合并/重命名既有 PIR/PDP 函数。
