# 1. 功能概述

- **用途**：按「产品 + 文档类型 + 文档版本」维护模型侧文档（DHF 之一类），提供新增 / 编辑 / 导出 / 复制 / 删除。交互与产品文件（产品立项报告）一致：列表筛选、章节树编辑、封面 4 列、修订记录。
- **使用场景**：用户从左侧菜单「模型文件」进入某一子菜单，对该类型文档建档、改章节、导出。
- **最终目标**：同一产品下每种 `doc_type` 可有多个版本；`(product_id, doc_type, version)` 唯一；封面空的编制部门为「模型部」；产品信息仅填空、不回写产品主数据。
- **导出格式**：`DOC_META.format` 为 `docx`（默认）时导出 Word（封面→修订→目录→正文）；为 `xlsx` 时导出 Excel（每章节一张工作表，含表格）。
- **范围**：15 份 Word + 21 份 Excel 共用单表 `model_doc`。数据文件见 [100_数据文件管理.md](./100_数据文件管理.md)。
- **关联上下游**：上游读取产品主数据、产品 DHF 文件编号、时间逻辑线、参与人员、人员签名；下游无写回。不改动产品文件封面（产品部）及其它已有文档模块。

# 3. 完整执行流程（分步细化）

## 3.0 触发入口

1. 菜单「模型文件 → {类型名}」进入 `/model_docs/{doc_type}`。
2. 数据文件入口见 [100_数据文件管理.md](./100_数据文件管理.md)。

## 3.1 步骤 1：列表查询

- **动作**：进入列表或点搜索。
- **入参**：`product_id`（可选）、`version`（可选模糊）、`doc_type`（路由类型，必填）、分页。
- **内部逻辑**：`list_model_doc` 按 `doc_type` 过滤；`product_manager` 且非超管仅能看到自己创建产品下的文档。
- **数据变化**：无写库。
- **调用链路**：`ModelDocs.doSearch` → `/list_model_doc` → `serv_model_doc.list_model_doc`。
- **页面表现**：表格展示产品名称、完整版本、文档版本、文件编号、变更说明、创建时间。

## 3.2 步骤 2：新增

- **动作**：点「新增」，选产品、填文档版本（默认 A0）、文件编号、变更说明。
- **入参**：`product_id`、`version`、`file_no`、`change_log`、`doc_type`。
- **内部逻辑**：`(product_id, doc_type, version)` 已存在则失败；`content` 取该类型模板树；空 `file_no` 按 DHF 名称关键字匹配。
- **数据变化**：插入 `model_doc` 一行。
- **调用链路**：`add_model_doc` → 跳转 `/model_docs/{type}/edit/{id}`。
- **页面表现**：进入编辑页，左侧为该类型默认章节。

### 分支 2A：版本已存在
- 走向：返回 `msg_obj_exist`，不跳转。
### 分支 2B：`doc_type` 非法
- 走向：返回参数错误，不建档。

## 3.3 步骤 3：编辑 / 查看

- **动作**：编辑页改章节树、正文、表格；工具栏可改产品与文档版本；查看页只读。
- **入参**：`id`；保存时 `content`、`product_id`、`version`（剥离 `_key`）。
- **内部逻辑**：进入或刷新时自动填充（见第 4 节规则，仅填空）；保存 `update_model_doc`，忽略入参 `doc_type`。
- **数据变化**：更新该行 `content` / `product_id` / `version` 等传入字段。
- **调用链路**：`get_model_doc` → 前端 `autofill`；保存 `update_model_doc`。
- **页面表现**：左侧目录、右侧标题/正文/表格；查看页禁用输入，仅可导出。

### 分支 3A：切换产品
- 走向：前端 `rebindProduct` 仅对空单元格再填新产品信息，已填内容保留；点保存后 `product_id` 落库。若目标产品已有同类型同版本则保存失败 `msg_obj_exist`。

## 3.4 步骤 4：导出 Word

- **动作**：列表或详情点「导出」。
- **入参**：`id`。
- **内部逻辑**：先 `__autofill_for_export`（仅填空），再渲染：封面（4 列，生效日期行合并）→ 分页 → 修订记录 → 分页 → 目录域 → 分页 → 正文（Heading + 加粗）。页眉为 `file_no`。
- **数据变化**：不落库。
- **调用链路**：`export_model_doc`。
- **页面表现**：下载 `{文档中文名}-{时间戳}.docx`。

## 3.5 步骤 5：复制

- **动作**：选目标产品（默认当前产品）。
- **内部逻辑**：保留 `doc_type`；同产品在原版本号递增；跨产品按目标产品该类型最大版本递增；冲突继续递增；深拷贝 `content`。
- **成功终态**：新记录出现在对应类型列表。

## 3.6 步骤 6：删除

- **动作**：单条或批量删除，物理删除该行。

# 4. 核心规则 & 判定条件

| 编号 | 规则 / 判定条件 | 含义 | 不满足 / 命中时的后果 |
|------|----------------|------|----------------------|
| R1 | `(product_id, doc_type, version)` 唯一 | 同产品同类型不能重复版本 | 新增/改产品或版本时返回 `msg_obj_exist` |
| R2 | 写操作 `model_doc_edit`，读操作 `model_doc_view` | 权限 | 无权限 `msg_no_perm`，菜单不可见 |
| R3 | `product_manager` 且非超管 | 列表只看自己创建的产品 | 其它产品文档不出现 |
| R4 | 自动获取仅填空、不覆盖已填 | 保护用户手改 | 已有文字/签名图保留 |
| R5 | 不回写产品主数据 | 文档内产品信息只读来源 | 改文档不影响 `product` 表 |
| R6 | 封面编制部门固定文案「模型部」（仅空则填） | 与产品文件「产品部」区分 | 用户已填其它部门则保留 |
| R7 | 更新忽略 `doc_type` | 类型由菜单锁定 | 不能把一份文档改成另一种类型 |
| R8 | 默认权限 | root/dqa/qa 全量；产品经理、开发、测试、RA 含模型文件与数据文件查看/编辑基线 | 新角色按角色管理勾选 |

自动获取明细（空才填）：

- **封面**：编制部门 ←「模型部」；文件版本 ← 文档版本；编制/审核/批准日期与生效日期 ← 时间线关键字（该类型文档名）；签署人按部门规则 `DOC_DEPT[doc_type]=model`：编制人角色含「模型」，审核人角色含「算法」，批准人角色含「研发负责人」；无匹配则空。
- **产品信息表**（`ref_type=basic_info` 或标题「产品信息」）：按行首标签匹配——产品名称←产品名称；软件版本/完整版本←完整版本；产品标识/产品代码←产品代码；适用范围/预期用途←适用范围；项目名称←产品名称。
- **文件修订记录首行**：修改日期 ← 时间线含该类型名称关键字的最早日期（`YYYY年M月D日`）；版本号 ← 文档版本；修订说明 ←「首次发布」；修订人 ← 角色含「模型」者（否则「算法」）；批准人 ← 角色含「负责人」者。
- **文件编号**：空则 `resolve_doc_file_no` 按该类型 `COVER_KEYWORDS` 匹配 DHF。

# 5. 数据结构说明

表 `model_doc`（详见 [01_数据库表结构.md](./01_数据库表结构.md)）：

| 字段 | 所属（表/对象/状态） | 含义 | 默认值 | 取值范围 | 流转规则（谁写、谁读、何时变化） |
|------|---------------------|------|--------|----------|-------------------------------|
| id | model_doc | 主键 | 自增 | 正整数 | 新增写入 |
| product_id | model_doc | 产品 | 必填 | 已有产品 | 新增/编辑可改 |
| doc_type | model_doc | 文档类型 | 必填 | 上表 15 个 key | 仅新增写入 |
| version | model_doc | 文档版本 | 必填，默认 A0 | 字符串 | 新增/编辑可改 |
| file_no | model_doc | 文件编号 | 可空，可 DHF 带出 | 字符串 | 列表单击保存或新增填写 |
| change_log | model_doc | 变更说明 | 可空 | 字符串 | 新增填写 |
| content | model_doc | 章节树 JSON | 类型模板 | 见下 | 编辑保存 |

`content = { "sections": [ node, ... ] }`，`node` 含 `title` / `body` / `tables` / `children` / 可选 `ref_type`（`cover` / `revision` / `basic_info`）。封面 4 列：编制部门/文件版本、编制人/日期、审核人/日期、批准人/日期、生效日期。非法 `content` 回落该类型模板；旧封面「使用部门/版本号/编写部门」迁移为编制部门+模型部+文件版本。

数据流向：模板 → 新增落库 → 编辑页读详情并填空 → 用户改树 → 保存 `content` → 导出再填空后渲染 Word。

# 6. 异常场景 & 兜底逻辑

| 场景 | 触发条件 | 系统处理 / 兜底 | 用户提示文案 |
|------|----------|----------------|--------------|
| 版本重复 | 同产品同类型同版本已存在 | 不写库 | `msg_obj_exist` |
| 详情不存在 | id 无效 | `msg_obj_null`；导出空白 docx | 前端 `message.error` |
| 类型非法 | `doc_type` 不在 15 个 key | 拒绝新增 | 参数错误 |
| 自动获取源空 | 无时间线/人员/产品字段 | 对应格保持空 | 无报错 |
| 保存/导出失败 | 数据库或网络异常 | rollback / 前端错误提示 | `msg_err_db` 或「导出失败」 |
| 无权限 | 缺 view/edit | 拦截 | `msg_no_perm` |
| 数据文件 | 进入占位页 | 不调模型接口 | 文案：数据文件将在后续批次接入 |

# 7. 功能约束 & 修改红线

## 7.1 允许修改范围

- 本功能文档；`01_数据库表结构.md` 的 `model_doc` 表；`trace-api` 的 `model_doc` 模型/对象/服务/接口及 `serv_review_util` 中模型部门与关键字登记；`tobj_role` 权限与默认角色集合。
- 前端 `pages/model_doc/*`、`api/ApiModelDoc.ts`、`Home.tsx` 菜单、`index.tsx` 路由、i18n、`Roles.tsx` / `Users.tsx` 模块匹配。

## 7.2 绝对禁止改动（红线）

- 禁止改产品文件及其它已有模块的封面编制部门、自动获取规则、表结构。
- 禁止回写 `product` / 时间线 / 参与人员。
- 禁止改 `src/store/`、`src/common/`、`src/utils/base/`。
- 禁止把模型文件拆成多套独立表/服务；必须单表 `model_doc` + `doc_type`。
- 禁止自动获取覆盖已填单元格。

## 7.3 禁止新增逻辑

- 不得新增本文未列出的 `doc_type`、字段、接口。
- 不得把 Excel 拆成独立表；仍走 `model_doc`。
- 文档集成导出收录不在本文范围。

## 7.4 禁止重构结构

- 不得整文件重写立项报告等既有模块；不得合并/重命名既有 PIR/PDP 函数。
