# 软件概要设计（HLD）文档管理

## 1. 功能概述

HLD 文档的列表、新增、编辑、查看、复制、删除、Word 导入/导出。文档仅绑定**产品 + 版本**（唯一约束 `(product_id, version)`），**不绑定 SRS**，无设计条目、无需求追溯、无 SRS 同步。采用「文档主表 + 节点树」存储，界面与 SDS 同风格，复用 `TreeStructure` 组件。

---

## 2. 用户操作流程

### 2.1 列表（`/hld_docs`）
按产品、文档版本筛选 → 查看/编辑/复制/导出/删除 → 文件编号内联编辑 → 顶部 Word 导入、新增。

### 2.2 新增/编辑/只读
- 新增 `/hld_docs/add`：选产品、HLD 版本、文件编号（选填）→「初始化模版」或「加载标准目录结构」→ 编辑树 → `add_hld_doc`。
- 编辑 `/hld_docs/edit/:id`：改元数据/变更说明/树 → `update_hld_doc`。
- 只读 `/hld_docs/view/:id`：`isReadOnly=true`，禁用编辑。

### 2.3 导入 Word
列表「导入」：选产品、版本、变更说明、上传 `.docx`；可选「导入前清空该产品历史概要设计」。**无需选择 SRS**。

## 4. 后端接口

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| GET | `/hld_doc/list_hld_doc` | product_id, version, 分页 | Page[HldDocObj] |
| GET | `/hld_doc/get_hld_doc` | id | HldDocObj（含 content 树；加载时按产品 DocFile 回填 img_topo/img_struct） |
| POST | `/hld_doc/add_hld_doc` | HldDocForm（含 content 树） | {id} |
| POST | `/hld_doc/update_hld_doc` | HldDocForm | 成功/失败 |
| DELETE | `/hld_doc/delete_hld_doc` | id | 级联删 hld_node |
| GET | `/hld_doc/duplicate_hld_doc` | id, product_id? | HldDocForm{id} |
| POST | `/hld_doc/update_hld_doc_file_no` | Form: id, file_no | 成功/失败 |
| POST | `/hld_doc/add_doc_file` | Form: doc_id, ref_type?, file | 图片路径 |
| POST | `/hld_doc/import_hld_doc_word` | Form: product_id, version, change_log, file | HldDocForm |
| GET | `/hld_doc/export_hld_doc` | id | .docx 流 |
| POST | `/hld_doc/export_hld_doc_snapshot` | HldDocForm（当前编辑快照） | .docx 流 |

**HldDocForm 字段**：id, product_id, version, file_no, change_log, content[], n_id  
**权限**：查看 `hld_doc_view`；编辑/导入 `hld_doc_edit`。

## 6. 关键业务逻辑与规则

### 6.1 与 SDS 的差异
- **无** `srsdoc_id`、**无** `sds_reqd` / `sds_trace`、**无**「获取 SRS 追溯」。
- 复制时仅复制节点树，不涉及 SRS 重绑定。
- 封面标题识别为「软件概要设计」/「软件概要设计说明书」（非「软件详细设计」）。

### 6.2 保存策略
- `update_hld_doc`：删全部 `hld_node` 后整树重建（`_update_nodes`），`n_id` 递增分配。
- 保存前校验 `content` 非空。
- `file_no` 随 `version` 通过 `sync_file_no_version` 同步。

### 6.3 产品级图片（DocFile）
- `ref_type` 支持 `img_topo`（物理拓扑/图1）、`img_struct`（系统结构/图2）、`img_flow`。
- 上传节点图片时若带 `ref_type`，写入/更新该产品下对应 `DocFile` 记录。
- `get_hld_doc` 加载树时，用产品最新 DocFile 回填对应 `ref_type` 节点的 `img_url`。

### 6.4 Word 导入
- 复用 SRS 服务的 `__parse_docx_content` **只读**解析 docx 树。
- 导入后：`__apply_hld_ref_types` 标注拓扑/结构图节点；`__persist_data_url_images` 落盘内嵌图；`__sync_imported_hld_doc_images_to_doc_file` 同步到 DocFile。
- 同产品同版本已存在则拒绝导入。

### 6.5 复制
- 同产品：`new_version(原版本)` 递增，撞号继续递增。
- 跨产品：取目标产品最大版本序号后 `new_version`；无文档则沿用原版本；`file_no` 随新版本同步。

### 6.6 封面与修订记录（前端）
- 封面表：「文件版本」随文档版本自动同步；「编制部门」空时默认「研发部」。
- 修订记录表：默认至少 5 行空行（`ensureChangeLogMinRows`）。

---

## 7. 边界与特殊处理

- 图片 URL 保存时去掉 `?_v=` 缓存参数（`_normalize_hld_img_url`）。
- 导出：已保存文档用 `export_hld_doc`；未保存编辑态可用 `export_hld_doc_snapshot`（后端已提供，前端详情页当前与 SDS 一致，仅导出已保存 id）。
- 非 admin 列表按 `prod_user` 过滤产品可见范围。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **不得引入 SRS 绑定或追溯逻辑**——HLD 与 SDS 独立，修改 HLD 不得影响 SDS/SRS 现有行为。
2. **整树重建 + 级联删除**为既定策略，不可改为增量。
3. **唯一约束 `(product_id, version)`** 不可改为绑定 SRS。
4. **TreeStructure 扩展须向后兼容**：`uploadDocFile` 可选，默认仍为 SDS 的 `add_doc_file`。
5. Word 导入复用 SRS 解析器时仅只读调用，不可改 SRS 解析语义。
6. 产品图片 `ref_type` 与 DocFile 联动逻辑不可移除，否则多版本 HLD 无法共享拓扑/结构图。
