# 软件变更规格管理（SCS）

## 1. 功能概述

管理软件配置状态报告（开发文件），PDP 风格章节树结构。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 导出 docx。

---

## 3. 前端实现

- 页面：`pages/scs/ScsDocs.tsx`（列表）、`ScsDocDetail.tsx`（详情/编辑）
- API：`api/ApiScsDoc.ts`

---

## 5. 数据库表

`scs_doc`：product_id, version, file_no, change_log, content(JSON)

---

## 6. 关键业务逻辑与规则

1. PDP 风格章节树结构。
2. 与 SCM（70）不同，SCS 是状态报告而非计划。
3. 「软件配置项状态(不包括现成软件)」取同产品《软件配置管理计划》「标识配置」中带「SCI类型」的软件配置项清单；「现成软件配置状态」取同一节里的现成软件配置项清单。打开、导出、切换产品时都按计划覆盖。优先用与本报告文档版本相同的计划，没有则用该产品最新一份。没有计划时保留原文。清单里的「软开源代码」不照抄那一行，改按同一计划「产品开发部软件构建配置项版本控制」中类别为「源代码」的各行展开：名字仍是软开源代码，类型为模块名（如 DP、RePACS），负责人为 infervision，版本号为 /，存储地点为该行路径。同一张版本控制表里的「验证Build」「最终构建工具」也追加在后面：验证Build 的类型为源代码，最终构建工具的类型为构建工具，负责人同为 infervision，版本号为 /，存储地点为对应路径。
4. 上述两张表：相邻同名配置项里内容相同的格子合并，版本号不同则分开。其它表不合并。页面和导出 Word 一致。
5. 评审记录页面与需求规格说明一致：只读合并表，点右侧「编辑」弹出表格编辑，确认后写回；点「删除」去掉该表。编辑弹框里，参评人员签字、评审时间、评审结论、批准人员签字这些只在第一格有内容的行合并成一格。查看页不显示编辑和删除。
