# 产品风险关联管理（产品 RCM / HAZ / CST）

## 1. 功能概述

将基础库（RCM/HAZ/CST）关联到具体产品，并在产品层补充风险评估、追溯、证据等信息。包含三个子模块：产品 RCM、产品 HAZ、产品 CST。

---

## 2. 产品 RCM（prod_rcm）

### 2.1 用户操作流程
`/prod_rcms` → 选产品 → 从主数据批量添加（EditDlg 勾选 `rcm_ids`）→ 列表展示 SRS 是否关联、SRS 编号、测试用例/证据 → 删除 → 导出 Excel。

### 2.2 前端
- `prod_risk/prod_rcm/index.tsx`、`EditDlg.tsx`
- `util.doSearchRcms` 用 `list_prod_rcm`（非全局 list_rcm）

### 2.3 后端接口
| 方法 | 路径 | 入参 |
|------|------|------|
| POST | `/prod_rcm/add_prod_rcms` | prod_id, rcm_ids[]（on_conflict_do_nothing） |
| DELETE | `/prod_rcm/delete_prod_rcms` | id（逗号分隔可多） |
| GET | `/prod_rcm/list_prod_rcm` | prod_id?, 分页 |
| GET | `/prod_rcm/export_prod_rcms` | 同上 |

`ProdRcmObj` 扩展：srs_codes[], srs_flag, test_codes[], product_name, product_version。

### 2.4 核心逻辑
- 列表时 `__repair_req_rcms_from_srs_nodes`：从 SRS 文档节点解析 SRS/RCM 对，回写 `req_rcm`。
- SRS 追溯：`req_rcm` + 测试集按 `srs_code` 匹配；按 `SRS-XX-YYY` 规则补单元/集成/系统/用户测试编号前缀。
- 测试过滤：按 RCM 描述与用例文本模糊/短语匹配；用户测试优先；特定 RCM 用 `NO_TEST_PROOF_MAP` 固定证据文案（如 RCM019→「模型文件」）。
- **无 update API**（只能删后重加）。

---

## 3. 产品 HAZ（prod_haz）

### 3.1 用户操作流程
`/prod_hazs` → 批量从主数据添加 → 行内编辑 situation/damage/deal/rcms/证据/初始与剩余风险 → 保存 `update_prod_haz`。选 RCM 时拼接 deal。

### 3.2 前端
- `prod_risk/prod_haz/index.tsx`、`EditDlg.tsx`、`TabColumns.tsx`
- 导出 `export_prod_hazs`（page_size 2000）

### 3.3 后端接口
| 方法 | 路径 | 入参 |
|------|------|------|
| POST | `/prod_haz/add_prod_hazs` | prod_id, haz_ids[] |
| POST | `/prod_haz/update_prod_haz` | ProdHazForm + id（可写字段集合固定） |
| DELETE | `/prod_haz/delete_prod_hazs` | id（可逗号多值） |
| GET | `/prod_haz/list_prod_haz` | prod_id? |
| GET | `/prod_haz/export_prod_hazs` | 模板 temp_haz.xlsx |

### 3.4 核心逻辑
- 列表合并：产品字段优先，否则主 `haz`。
- `rcms` 解析 RCM 编号后查**同产品** `list_prod_rcm` 得 `description`→deal、`test_codes`→evidence（自动推导）。

---

## 4. 产品 CST（prod_cst）

### 4.1 用户操作流程
`/prod_csts` → 批量添加 CST → 行内编辑**控制前/后**：score、severity、level、accept（可接受/不可接受/可忽略）、`rcm_codes` 多选。

### 4.2 前端
- `prod_risk/prod_cst/index.tsx`、`EditDlg.tsx`；`doSearchRcms(prod_id)`→list_prod_rcm

### 4.3 后端接口
| 方法 | 路径 | 入参 |
|------|------|------|
| POST | `/prod_cst/add_prod_csts` | prod_id, cst_ids[] |
| POST | `/prod_cst/update_prod_cst` | 仅评分与 rcm_codes 等 9 字段 |
| DELETE | `/prod_cst/delete_prod_csts` | 多 id |
| GET | `/prod_cst/list_prod_cst` / `export_prod_csts` | 合并 cst 主数据字段 |

### 4.4 核心逻辑
- CST 主数据描述「危害后果」(harm)；产品层为**独立评分体系**（Float），与 HAZ 的 rate/degree/level **不是同一套字段**。
- `rcm_codes` 为产品层建议关联的 RCM 编号串。

---

## 5. 数据库表

`prod_rcm`、`prod_haz`、`prod_cst`（均唯一 `(prod_id, *_id)`，详见 [01_数据库表结构.md](./01_数据库表结构.md)）。

---

## 6. 边界与特殊处理

- **产品级 RCM/HAZ/CST 列表后端未做真分页**（一次返回匹配全部，total 仍计算，前端分页仅 UI）。
- `prod_rcm` 无 update；`prod_cst` 无 get。
- prod_haz `cur_*` 模型注释写「初始」为历史笔误。
- EditDlg 提示文案误写「请选择HAZ」（实为 RCM）。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. **产品 HAZ 的 deal/evidence 自动推导**（来自同产品 prod_rcm 的 description/test_codes）不可破坏。
2. **prod_rcm 的 SRS/测试追溯匹配规则**（req_rcm 回写、SRS 编号→测试编号前缀、NO_TEST_PROOF_MAP）是追溯核心。
3. **CST 评分与 HAZ 评分是两套字段**，不可混用。
4. `add_prod_*s` 的去重（on_conflict / 唯一约束）不可移除。
5. 列表合并「产品字段优先、否则主数据」的优先级不可颠倒。
