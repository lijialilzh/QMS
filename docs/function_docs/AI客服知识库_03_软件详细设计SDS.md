# AI 客服知识库（三）软件详细设计 SDS

> 本文件是给“AI 客服”使用的功能知识库，内容全部来自系统真实功能（用户手册 93）。
> 每个功能按统一结构描述：界面位置 / 用户常见问法 / 是做什么的 / 解决什么问题 / 怎么用 / 相关功能。
> 目的：让 AI 既能“认识”每个功能（是什么、界面里叫什么），又能讲清楚“怎么用”。

---

## 模块总览：软件详细设计（SDS）

软件详细设计（SDS）模块用于为每个产品编写和维护“详细设计文档”，把 SRS 里的需求落实成具体的设计条目（概述、功能、逻辑图、输入、输出、接口）。文档挂在产品下、按版本管理，并且**必须绑定一份 SRS 需求文档版本**，主操作路径是「SDS 文档列表 → 文档详情页」：列表负责新建/导入/复制/导出/删除，详情页负责编辑章节树、维护设计条目、同步需求追溯。
它解决的是“把需求转化为可实现的设计、并保持需求与设计的追溯关系”的问题，前置依赖 SRS，向下连接测试与追溯。

---

## 1. SDS 文档管理（新建 / 编辑 / 查看 / 复制 / 删除）

- **界面位置**：菜单「创建管理 → SDS 文档」，列表页路径 `/sds_docs`；详情页 `/sds_docs/add`（新建）、`/sds_docs/edit/{id}`（编辑）、`/sds_docs/view/{id}`（只读查看）。
- **用户常见问法**：怎么新建详细设计、SDS 怎么建、怎么写软件详细设计、怎么编辑 SDS 文档、怎么复制一份 SDS、怎么删除 SDS 文档、SDS 文件编号怎么改。
- **是做什么的**：对产品的软件详细设计文档做整体管理——新建、编辑、查看、复制、删除，并可在列表里直接修改“文件编号”。
- **解决什么问题**：让每个产品都有一份按版本管理、并绑定到具体 SRS 版本的设计文档，作为设计条目与追溯的统一载体。
- **怎么用**：
  1. 进入列表页，选择产品 + 文档版本（选产品后加载该产品的 SDS 版本）后搜索。
  2. 新建：点「新建」进入新建页 → 选择产品、选择要关联的 SRS 需求文档版本、填写本次 SDS 版本号 → 点「初始化模版」加载标准目录结构 → 在目录树中编辑各章节标题、正文，维护设计条目与追溯 → 点顶栏「保存」；保存成功后进入该文档编辑页。
  3. 编辑：列表行点「编辑」进入编辑页修改后保存。
  4. 查看：列表行点「查看」进入只读详情页。
  5. 复制：列表行点「复制」并确认，生成新版本。
  6. 删除：列表行点「删除」按确认提示完成。
  7. 文件编号：在列表里单击“文件编号”单元格直接编辑，失焦或回车保存，提示「文件编号已保存」。
- **相关功能**：导入 Word 详细设计、设计条目（设计列表）、需求追溯、导出与对比；上游依赖 SRS（SDS 须绑定 SRS 版本，先有 SRS 才能建 SDS）。

## 2. 导入 Word 详细设计

- **界面位置**：SDS 文档列表页（`/sds_docs`）顶部「导入」按钮，打开「导入 Word 详细设计」弹窗。
- **用户常见问法**：详细设计怎么导入、SDS 怎么从 Word 导入、能不能直接上传设计 Word、导入 docx 详细设计。
- **是做什么的**：上传一个 `.docx` 文件，系统自动解析生成 SDS 文档树与设计内容并入库。
- **解决什么问题**：免去手工逐条录入，把已有的 Word 详细设计一键转成系统里的结构化 SDS 文档。
- **怎么用**：
  1. 列表页点「导入」。
  2. 在弹窗里填写：产品（必填，选产品后重载“关联需求文档”列表）、关联需求文档 SRS（必填，无 SRS 列表时禁用）、SDS 版本（必填）、变更说明（选填）、上传 Word 文件（必填，仅 `.docx`，单文件）；可选勾选“导入前清空该产品历史详细设计”。
  3. 点「确定」上传解析。
  4. 成功后关闭弹窗并刷新列表。
- **相关功能**：SDS 文档管理（导入后即生成一份可编辑文档）、SRS 文档（导入需关联 SRS 版本）。

## 3. SDS 文档章节树编辑（目录结构）

- **界面位置**：SDS 文档详情页（`/sds_docs/add` | `/edit/:id` | `/view/:id`）的「目录结构区」。
- **用户常见问法**：SDS 章节怎么编辑、怎么加目录、SDS 编码怎么填、怎么插表格、怎么上传图片、怎么获取 SRS 追溯、怎么删章节。
- **是做什么的**：编辑文档的树形目录结构——编辑各节点标题、SDS 编码与正文，增删子节点，插入表格、上传图片，并提供“获取 SRS 追溯”把绑定 SRS 的需求同步进来。
- **解决什么问题**：让设计文档按章节层级组织内容，并能与绑定的 SRS 保持需求—设计追溯一致。
- **怎么用**：
  1. 顶栏「初始化模版」加载标准目录（新建）或恢复进入页时的树（编辑）。
  2. 顶栏「获取SRS追溯」从绑定的 SRS 同步需求与追溯章节，成功提示「已从SRS获取追溯数据」；顶栏「添加根菜单」追加根节点。
  3. 节点上可编辑标题、SDS 编码（含 sds_code 的节点）、正文（多行）；1–2 级节点可上传图片。
  4. 增删节点：用 `+` 在前/后添加同级，level<2 可加下级菜单，节点「删除」按确认移除。
  5. 表格：非图片/设计/追溯节点可「表格 / 导入表格」（支持 `.xlsx/.xls/.csv`）。
  6. 编辑完成后点顶栏「保存」，整棵树随文档一起保存。
- **相关功能**：SDS 文档管理（保存即整树提交）、设计条目、需求追溯、图表文件管理（图片引用节点的图来自图表文件映射）。

## 4. 设计条目（设计列表）

- **界面位置**：SDS 文档详情页树内 `sds_reqds` 节点「设计列表」（只读弹窗）；独立编辑页「设计条目」`SdsReqds.tsx`（可编辑）。
- **用户常见问法**：设计条目怎么填、设计列表在哪、概述功能输入输出接口怎么填、逻辑图怎么上传、怎么编辑设计条目。
- **是做什么的**：为每条需求维护对应的设计明细——概述、功能详情、逻辑文本、输入、输出、接口，并可上传逻辑图（多图、可加说明）。
- **解决什么问题**：把每条需求的具体设计落到可实现的细节，作为开发与测试的依据。
- **怎么用**：
  1. 进入独立“设计条目”页，筛选产品 + SDS 文档版本（须同时选定且有数据）。
  2. 列表行点「编辑」打开弹窗，填写概述、功能详情、逻辑文本、输入、输出、接口（均选填）。
  3. 逻辑图：上传 `.png/.jpg/.jpeg` 多图，每张可填说明、可删除。
  4. 保存后回写到对应设计条目。
- **相关功能**：SDS 文档章节树编辑（树内只读查看）、需求追溯、SRS 需求条目。

---

## 5. 需求追溯（SDS）

- **界面位置**：SDS 详情页树内追溯节点（「获取SRS追溯」/「需求追溯表」）；独立编辑页「设计需求追溯」`SdsTraces.tsx`。
- **用户常见问法**：SDS 追溯怎么看、需求到设计的追溯在哪、怎么获取 SRS 追溯、SDS 编号怎么填、追溯表怎么编辑。
- **是做什么的**：建立并查看 SRS 需求与 SDS 设计之间的追溯关系（SRS 编号、SDS 编号、需求代码、章节号），支持从绑定的 SRS 同步。
- **解决什么问题**：保证每条需求都有对应设计、可被追溯，满足合规与追溯需要。
- **怎么用**：
  1. 详情页查看：未同步时点「获取SRS追溯」拉取（打开“需求追溯表”前若未同步会自动拉取），已同步点「需求追溯表」查看只读追溯。
  2. 独立页编辑：进入“设计需求追溯”页，筛选产品 + SDS 版本，行点「编辑」在弹窗里填写 SDS 编号（必填）、需求代码、章节号（SRS 编号不可改）。
- **相关功能**：SDS 文档章节树编辑、设计条目、SRS 文档追溯。

---

## 6. 导出与对比

- **界面位置**：SDS 列表页/详情页「导出」按钮；文档对比在「产品追溯总览 → 文档对比」。
- **用户常见问法**：SDS 怎么导出 Word、SDS 怎么下载、两个版本的设计怎么对比、文档对比在哪。
- **是做什么的**：把 SDS 文档导出为 Word；或在文档对比里对比两份软件详细设计文档的差异。
- **解决什么问题**：方便交付、评审、归档，以及在版本升级时核对设计的增删变化。
- **怎么用**：
  1. 导出 Word：在列表行或详情页点「导出」（详情页须先保存过文档，否则提示「请先保存文档」）。
  2. 文档对比：进入“产品追溯总览 → 文档对比”，文档类型选「软件详细设计」，左右各选产品/版本，点「开始对比」。
- **相关功能**：SDS 文档管理、产品追溯总览。
