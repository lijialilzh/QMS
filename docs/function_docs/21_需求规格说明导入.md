# 需求规格说明导入（Word）

## 1. 功能概述

从 `.docx` 文件解析生成 SRS 文档树，并抽取需求行（标准/其他/变更）、功能描述、图片，入库。

---

## 2. 用户操作流程

列表页「导入 Word 需求」弹窗 → 选产品、填版本、变更说明、上传 `.docx` → 确认。

---

## 3. 前端实现

- 页面：`SrsDocs.tsx` → `doImportWord` → `ApiSrsDoc.import_srs_doc_word`

---

## 4. 后端接口

| 方法 | 路径 | 入参 | 返回 |
|------|------|------|------|
| POST | `/srs_doc/import_srs_doc_word` | Form: product_id, version, change_log, file | SrsDocForm{id} |

权限：`srs_doc_edit`。依赖 `python-docx`。

---

## 5. 处理流程（serv_srs_doc.import_srs_doc_word）

1. `__parse_docx_content`：解析标题层级、段落、表格、图片 → 生成 `content` 树。
2. `__validate_heading_numbers`：校验标题编号连续性（从「介绍」起；**warning 级别，不阻断导入**）。
3. 双路径抽取需求：`__extract_srs_reqs_from_nodes` + `__extract_srs_reqs_from_tables`，合并去重（字段完整度优先）。
4. `__extract_srs_reqds_from_nodes`：抽取功能描述。
5. `add_srs_doc`：入库。
6. post-import 联动：`__upsert_imported_srs_reqs`、`__upsert_imported_change_req_tables_from_tree`、`__sync_saved_doc_srs_tables_from_req_rows`、`__sync_imported_req_rcms`、`__upsert_imported_srs_reqds`、`__auto_sync_product_doc_images`（2.2/2.3 图写入产品图表库）。

---

## 6. 编号与分类规则（重要）

| 规则 | 说明 |
|------|------|
| 标题编号 | 从 Word `numPr` / 样式推断 |
| 标准需求 | 表头含 `code + module + function` → `type_code=1` |
| 其他需求 | 表头含 `code + module + location`（无功能列）→ `type_code=2` |
| 变更需求 | 表名含「变更」→ `type_code=change_{md5}` 并创建 `srs_type` |
| 文件名解析 | `folder_name`（中文标题部分）、`file_no`（编码前缀） |
| 合并单元格 | 空值继承上行（`__fill_req_table_merged_values`） |

---

## 7. 边界与特殊处理

- 标题编号不连续仅 warning，不阻断导入。
- 缺少 `python-docx` 时报错。
- 导入失败 Modal 展示后端 `msg`。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **需求分类规则（type_code 1/2/变更）** 必须与编辑保存、SDS 同步保持一致，不可单独改导入侧判断。
2. **变更表名含「变更」→ 生成 change type** 是变更需求识别的源头，改动会影响后续整条链路。
3. **合并单元格继承上行**逻辑不可去除，否则需求行字段会丢失。
4. 标题编号校验为 warning，不可改为阻断（会导致大量历史 Word 无法导入）。
5. post-import 的多步联动顺序不可打乱。
