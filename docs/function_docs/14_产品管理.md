# 产品管理

## 1. 功能概述

产品是系统核心实体，SRS/SDS/测试集/图表/DHF/风险均挂在产品下。提供产品 CRUD、导出、数据可见范围控制与追溯查询。

---

## 2. 用户操作流程

模糊搜索 → 列表 → 新增/编辑（项目、类别、型号、版本、UDI、范围、组成等）→ **复制（弹窗选目标产品，支持跨产品复制）** → 删除/批量删除 → 导出列表 Excel。

---

## 3. 前端实现

- 页面：`pages/product/Products.tsx`
- API：`api/ApiProduct.ts`；编辑时 `ApiProject.list_project`

## 5. 数据库表

- `product`：project_id, name, category, type_code, full_version, release_version(必填), udi, product_code, scope, component, note, create_user_id；**唯一 (name, full_version)**
- `prod_user`：user_id, product_id（多对多，唯一对）

---

## 6. 关键业务逻辑与规则

### 6.1 数据可见范围（重要）
- `user.id == 1`：全部产品。
- `product_manager`：仅 `create_user_id == 自己`。
- 其他用户：`prod_user` 关联 或 `create_user_id`（兼容历史数据）。

### 6.2 新增
- `user_ids` 默认 `[op_user.id]`；产品经理强制仅自己。

### 6.3 复制（支持跨产品 + 可选 DHF 联动）
- **入口**：列表行「复制」弹窗，左侧选目标产品名称，右侧**手动输入完整版本**（默认预填递增值，可修改）；发布版本仍自动生成。
- **同产品复制**（目标名称 = 源产品名称）：完整版本默认 `new_version(原完整版本)`，用户可改；`(name, full_version)` 重复则拒绝。产品名称可相同、完整版本必须不同。
- **跨产品复制**（目标名称 ≠ 源产品名称）：完整版本默认按目标名称下最大版本递增预填，用户可改；`project_id` 取目标产品所属项目；`(name, full_version)` 重复则拒绝。
- **发布版本**：仍按同产品/跨产品规则自动递增，不由用户填写。
- **复制范围（默认）**：未勾选 DHF 时，仅复制产品主数据行（类别、型号、UDI、范围、组成等）及 `prod_user` 关联；**不复制**下游数据。
- **DHF 联动复制（可选）**：
  - 弹窗展示源产品 DHF 清单（文件编号 + 文件名称），支持**关键字搜索**后**手动勾选**（默认不全选）。
  - 入参 `dhf_ids[]`：勾选的 DHF 主键列表；选 N 条则新产品 DHF 清单写入 N 条（code + name）。
  - 对每个勾选的 DHF，在源产品各文档模块中查找并复制文档：
    - **文件名称**：DHF `name` 与模块 `COVER_KEYWORDS` 匹配（最长关键字优先），确定目标模块；
    - **文件编号**：若该模块下存在 `file_no` 与 DHF `code` 归一化一致的文档，则在该批文档中取**最新文档版本**一条；若不存在编号一致文档（例如模块内 file_no 仍为手工值、未与 DHF 同步），则在该模块全部文档中取**最新一条**。
    - **文档版本**：跨产品联动复制时，目标产品新建文档的**文档版本统一为 A0**，并按 A0 同步 `file_no` 末尾版本段。
    - **同产品小版本复制**（目标产品名称 = 源产品名称）：对 `TX-TF-{代号}-…` 格式编号，在代号段自动追加 **V+完整版本 compact**（如完整版本 `2.0.0.1` → `V2001`，`RUS` → `RUSV2001`；若已有 `RUSV1010` 则替换为 `RUSV2001`）；联动写入 DHF `code` 与各模块文档 `file_no`。
  - **联动范围**：匹配到的各 `*_doc` 模块文档；若命中测试类 DHF（软件/用户测试计划/报告、Bug 管理等），同步复制源产品**测试集**（含用例）；若命中 SRS/SDS 类 DHF，同步复制源产品**图表文件**（`doc_file` 各 category）。
  - **复制顺序**：先 SRS，再 SDS（跨产品时 SDS 自动绑定目标产品最新 SRS），再其余模块；各模块复用已有 `duplicate_*_doc(id, product_id)` 深拷贝内容后**强制落库为 A0**。
  - 未勾选 DHF 或 `dhf_ids` 为空：行为与旧版一致。

### 6.4 删除阻断
- 存在 SrsDoc / TestSet / ProdDhf / DocFile 时禁止删除。

### 6.5 追溯
- `with_trace=1`：join SdsDoc ↔ SrsDoc 得 `traces`、`srs_versions`、`sds_versions`。

### 6.6 产品-文档关系（核心）
- 产品 1:N **SRS 文档**（`srs_doc.product_id`）。
- SDS 经 `srsdoc_id` 挂 SRS：追溯链 **产品 → SRS 版本 ↔ SDS 版本**。
- 测试集、图表文件、DHF 均挂 `product_id`。

---

## 7. 边界与特殊处理

- `list_product` 允许 srs/sds view 访问，供需求/设计模块的产品下拉框使用。
- `(name, full_version)` 唯一，重复新增会失败。

---

## 8. 修改注意事项 / 不可破坏的核心逻辑

1. **数据可见范围三分支（id==1 / product_manager / prod_user）** 是安全边界，不可简化或绕过。
2. **删除阻断校验**（存在下游文档/测试集/DHF/图表）不可移除。
3. `(name, full_version)` 唯一约束是版本管理基础。
4. 产品-文档逻辑关系（product_id / srsdoc_id）贯穿全系统追溯，不可改动字段语义。
