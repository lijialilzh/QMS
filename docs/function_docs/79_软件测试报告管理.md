# 软件测试报告管理（STR）

## 1. 功能概述

管理软件测试报告（测试文件），PDP 风格章节树结构。支持导出 docx。

---

## 2. 用户操作流程

列表页按产品搜索 → 新增/编辑 → 章节树编辑器 → 导出 docx。

---

## 3. 前端实现

- 页面：`pages/str/StrDocs.tsx`（列表）、`StrDocDetail.tsx`（详情/编辑）
- API：`api/ApiStrDoc.ts`

## 6. 关键业务逻辑与规则

1. PDP 风格章节树结构。章节可删：全局保存后刷新不再自动补回已删章节。
   - **同级上下移**：编辑态目录节点可上移/下移，仅与同级交换位置；编号按层级与位置自动重算。不可跨父章节移动。首条无上移、末条无下移。↑↓ 仅在悬停或选中该行时显示，避免目录图标过挤。
2. 与 STP（软件测试计划）不同，STR 是测试报告阶段文档。
3. 评审记录页面与需求规格说明一致：只读合并表，点右侧「编辑」弹出表格编辑，确认后写回；点「删除」去掉该表。编辑弹框里，参评人员签字、评审时间、评审结论、批准人员签字这些只在第一格有内容的行合并成一格。查看页不显示编辑和删除。
   - 参评人员中含「测试」且不含「用户」的角色（如测试负责人）：按评审时间强制覆盖姓名与签字——2025.09 前「宋月」，之后「孙家旭」（避免日期后补时仍留着空日期时写入的孙家旭）。其它角色仍仅空值按参与人员补。
   - 用户删掉整章「评审记录」并保存后，普通打开不再自动再建；新建文档或换产品 `force` 时仍会生成。
4. 「测试项列表」按阶段自动填充用例：
   - **单元测试**表头：`需求编号 | 设计编号 | Case编号 | 功能点概述 | 用例个数 | 是否通过 | 备注`（与模版一致，含设计编号）。
   - **集成测试 / 系统测试**表头：`需求编号 | Case编号 | 功能点概述 | 用例个数 | 是否通过 | 备注`（不含设计编号）。
   - 单元测试用例 Excel 第二列为「设计编号」：功能行多为 `SRS-…`，接口行为 `SDS-IF…`。
   - 回填规则：`SRS-…` → 需求编号原样，设计编号优先取该产品 `sds_trace`，无追溯时 `SRS-` 改为 `SDS-`；`SDS-IF…` → 设计编号原样，需求编号按需求追溯同款接口编号→SRS 互转。接口号中间数字按 `主号×10+次号` 还原，且主号末两位等于 IF 号（`SDS-IF00-RCN3005-001`→`SRS-RCN300-005`，`SDS-IF00-RCN3010-001`→`SRS-RCN300-010`，`SDS-IF00-RCH2010-001`→`SRS-RCH200-010`）。本产品已有的候选里优先用这条还原结果；都没有时也取还原结果，不再只剥最后一位。其它 `SDS-…` 仅追溯反查，不做前缀回退。打开报告仍按用例重算需求编号和设计编号，手改这两列保存不住。
   - **单元测试表合并**：仅「需求编号」「设计编号」两列，上下相邻、去空白后内容相同且非空时纵向合并（空不合并）；Case编号、功能点概述、用例个数、是否通过、备注不合并。编辑页与导出 Word 一致。
   - 已有子章节（如单元/集成/系统）时只刷新各子章表格，并把 `stages` 同步为当前子章标题；不补回用户已删的阶段。仅当子章为空时才按 `stages` 初次生成。
   - **自动获取按钮**：手动新增且表格仍为空的「单元测试 / 集成测试 / 系统测试」子章显示「自动获取」；已有用例数据行的不显示。点击后按章节标题从该产品对应阶段测试集拉取并填表（`GET /refill_str_test_items?product_id=&stages=`，`stages` 逗号分隔）；无用例则提示。拉取后父章补 `ref_type=test_items` 并同步 `stages`。
5. **缺陷统计分析表**：「用例总数」行第 1 列起（数值格）横向合并至行末；首列「用例总数」标签单独一格。编辑页与导出 Word 一致。
6. 表题不体现代号：如「缺陷统计分析：」「参与此项目的测试人员：」前不加产品代号（模板/历史「XUS…」打开与导出时去掉代号前缀）。
7. **兼容性测试模块/测试点**：
   - 打开/换产品时，对「Win10测试项列表」「Win11测试项列表」「用户端测试」中带「测试模块」列的表：按该产品 SRS 标准需求叶子名重建数据行；表头（含浏览器/杀毒版本行）保留。
   - Win10/Win11 每模块测试点模板：`页面格式，字体，输入框，按钮字图片是否正常显示` / `排版是否统一` / `提示信息是否正常完整` / `功能是否正常使用`；结果列默认「通过」。
   - 用户端测试每模块测试点模板：`功能是否正常`；结果列默认「通过」。
   - 编辑页：上述章节表格尚无数据行（空）时显示「自动获取」；已有模块数据行则不显示。点击后 `GET /refill_str_compat_items?product_id=&kind=win|client` 按同样规则填表；无 SRS 叶子则提示。
8. **测试分布图**：在「测试分布图」章节点生成后，按各阶段测试项各出一张折线图（横轴功能点，用例个数、是否通过）。每张图的标题按该阶段写：「单元测试记录」「集成测试记录」「系统测试记录」。已保存的旧图要重新生成才换标题。
9. **兼容性测试的版本同步**（打开、换产品、导出时）：
   - 「测试概述」里的客户端/服务端杀毒软件名称和版本，写入「杀毒软件兼容测试」下用户端/服务端表。版本按顿号、逗号拆开，有几个版本就显示几列，版本号与测试概述一致。表头现在是「结果」、或还没有版本行时，也补上名称行和版本行；多出来的结果格写「通过」。
   - 浏览器版本以兼容性测试报告「设备需求」表的「设备信息及浏览器版本」为准。打开、换产品、导出都不改写这一列，手改保存后刷新仍保留。格子里写成 `x.y.z` 及以上的版本号（如 `浏览器版本：Chrome 137.0.1234.78、136.0.7103`）。含 Windows 10 / Win10 的行给 Win10 测试项列表，含 Windows 11 / Win11 的行给 Win11 测试项列表。有几个版本就显示几列，版本号与设备需求一致；名称行沿用原表头（缺省为「Google Chrome版本信息」）。同一版本写入软件测试报告「测试设备详情」对应用户端格子的「浏览器版本」一行。设备需求里还没有这类版本号时，不改 Win 表头和测试设备详情。
   - 「设备需求」「测试设备详情」的设备信息格在编辑页按全文撑开，不截成 8 行。
   - 杀毒软件版本和浏览器版本不再改成产品完整版本。产品完整版本只替换「测试版本」「产品名称/版本」和安装包路径里的版本号。
   - 导出「兼容性测试」时，封面大标题为「兼容性测试报告」。编审批、文件修订记录仍用软件测试报告封面的那一份。
