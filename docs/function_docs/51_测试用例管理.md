# 测试用例管理

## 1. 功能概述

测试用例归属测试集，记录用例编号、关联 SRS 需求编号、类型、步骤、预期等。维护主路径为测试集 Excel 导入；后端提供完整 CRUD 与导出。

---

## 2. 用户操作流程

- **只读列表**：测试集弹窗中 `TestCases.tsx` 展示，无单条增删改 UI。
- **维护主路径**：测试集 Excel 导入/更新覆盖。
- 导出：从 TestSets 行操作触发 `export_test_cases`。

---

## 3. 前端实现

- 页面：`pages/test_set/TestCases.tsx`（`list_test_case({ set_id })`）
- 导出：`api/ApiTestCase.ts` → export_test_cases

---

## 4. 后端接口

| 方法 | 路径 | 权限 | 入参 |
|------|------|------|------|
| POST | `/test_case/add_test_case` | test_case_edit | TestCaseForm 全字段 |
| POST | `/test_case/update_test_case` | test_case_edit | TestCaseForm |
| DELETE | `/test_case/delete_test_case` | test_case_edit | id |
| GET | `/test_case/list_test_case` | test_case_view \| srs_doc_view | set_id |
| GET | `/test_case/get_test_case` | test_case_view | id |
| GET | `/test_case/export_test_cases` | test_case_view | set_id → xlsx |

---

## 5. 数据库表

`test_case`：set_id, code, srs_code, test_type, function, description, precondition, test_step, expect, note。

---

## 6. 关键业务逻辑与规则

1. **新增**：`code` **全局唯一**（非 per set）。
2. 列表 join TestSet、Product，回填 stage、product_name、product_version。
3. 删除测试集时级联删除用例。

---

## 7. 修改注意事项 / 不可破坏的核心逻辑

1. **用例 code 全局唯一**，不可改为集合内唯一（追溯依赖全局编号）。
2. `srs_code` 是与需求追溯的关联字段（字符串），不可改语义。
3. 前端只读，维护入口为测试集 Excel；不要误加前端单条编辑而绕过校验。
